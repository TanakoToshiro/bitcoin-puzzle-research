# Локальный сайт Bitcoin Puzzle Research

HTML-оболочка для существующего архива `ru/` и `en/`. Публикация через GitHub Pages: https://tanakotoshiro.github.io/bitcoin-puzzle-research/. По умолчанию открывается английский язык; русский доступен через переключатель RU.

Статус на 25 ноября 2026: файлы загружены, но развёртывание Pages возвращает серверную ошибку GitHub HTTP 500. Проверки и шаг продолжения — в [QA.md](QA.md).

## Запуск

Из этой папки, с установленным Node.js 20 или новее:

```powershell
npm ci --ignore-scripts
npm run build
npm run preview
```

Открыть **http://127.0.0.1:4173/**. Сервер доступен только на локальном компьютере. Остановка — Ctrl+C в терминале сервера. Для другого порта задайте переменную `PORT`.

## Что работает

- Обзор исследований, восемь направлений, последние результаты и открытые вопросы.
- Полный каталог: по 886 Markdown-документов на языке текущего снимка.
- Поиск по названиям и полному тексту, фильтры по направлению и типу документа.
- Чтение документов внутри сайта: таблицы, формулы, содержание, внутренние ссылки.
- Переключение RU/EN с сохранением текущего документа.
- Отметки машинного и отредактированного перевода.
- Адреса для добровольной благодарности с кнопками копирования.
- Мобильное меню, узкий экран, клавиатурный поиск Ctrl+K / Cmd+K.

## Файлы

`src/` — HTML, CSS и JavaScript интерфейса. `build.mjs` читает архив и создаёт `dist/`: готовые HTML-фрагменты документов, каталоги, поисковые индексы, свидетельства и локальные библиотеки. `preview.mjs` обслуживает только `dist/` на loopback-адресе.

`dist/` и `node_modules/` исключены из Git. Источники исследований при сборке не меняются. Во время просмотра не используются CDN, аналитика или внешние API; GitHub и первичные источники открываются только при переходе по ссылкам. Полнотекстовый индекс загружается при первом поиске.

После изменения архива выполните `npm run build`, затем обновите вкладку. При запуске сборки на уже существующем `dist/` удалённые из архива документы не очищаются автоматически; для публикации используйте чистую рабочую папку сборки.

## Публикация

Команда `npm run publish:pages` выполняет чистую сборку и отправляет готовые файлы в отдельную ветку `gh-pages`. GitHub Pages публикует корень этой ветки. Исходники сайта и архив остаются в `main`. После изменения архива сначала сохраните и отправьте изменения в `main`, затем выполните команду публикации из `site/`. Навигация использует hash-маршруты, ресурсы — относительные пути, поэтому сайт рассчитан на адрес проекта `/bitcoin-puzzle-research/`. Состояние публикации и журналы доступны в GitHub Actions, workflow «pages build and deployment». Текущая авторизация GitHub CLI не имеет scope `workflow`, поэтому пользовательский Actions workflow не используется.

Зависимости зафиксированы в `package-lock.json`: Marked для Markdown, DOMPurify для очистки HTML, KaTeX для формул. Их лицензии включаются в `dist/vendor/`.

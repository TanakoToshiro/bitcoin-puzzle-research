# ATT-01 — архивные вложения Puzzle

Дата: 02.11.2026, Москва. **Ограниченный проход завершён. Пригодного связанного с генератором Puzzle журнала Armory, unsigned/partial Electrum `.txn` или публичного экспорта mSIGNA не найдено.** Это результат проверенного набора, не доказательство отсутствия таких материалов в Интернете.

Получен и разобран ранее не загруженный E8/E10 архив доказательств Puzzle. Отдельно найден и проверен ложный след: строка «Pub Address (Extended)» для №66 имеет правильный Base58Check, но не содержит chaincode. Нового ключа, бита или сокращения реального пространства поиска нет. Перебор, recovery и запуск скачанных программ не выполнялись.

## 1. Реально полученный архив доказательств

[Bitcoin-Puzzle-Evidence-Archive.zip](https://archive.org/download/the-1000-btc-bitcoin-puzzle-case-funding-payouts-and-on-chain-connections/Bitcoin-Puzzle-Evidence-Archive.zip) опубликован Virtuose как исследовательское досье версии 1.0. Метаданные Internet Archive указывают 10.09.2026; [форумное сообщение](https://bitcointalk.org/index.php?topic=1306983.msg67129963#msg67129963) описывает сбор блокчейн-доказательств. Это поздняя коллекция исследователя, не файл, атрибутированный создателю.

ZIP: **8 793 699 байт**, 195 элементов, 31 722 749 байт после распаковки. SHA-1 `160532802621116fd9616e0deffeb737fca0643e` совпал с метаданными Internet Archive. Независимо проверены все **194 записи SHA-256** внутреннего манифеста, расхождений нет; сам `SHA256.json` закономерно не хеширует себя. Совпадение хешей подтверждает целостность полученных байтов, не авторство или истинность интерпретаций. Проверка — артефакт исходного исследования (`ARCHIVE_INTEGRITY.json`; вне снимка).

Фактические форматы: 190 JSON, README, манифест входит в эти JSON, три PNG и Python-скрипт. JSON содержат транзакции/связи, результаты запросов WalletExplorer и ссылки на источники. Имена и содержимое целевых журналов/экспортов не обнаружены. Все три PNG просмотрены: это экраны обозревателя с входами/выходами и RBF для №66, не изображения wallet logs. `verify_evidence.py` из архива **не исполнялся**; хеши проверял наш короткий код.

Получена также [сопутствующая XLSX](https://archive.org/download/the-1000-btc-bitcoin-puzzle-case-funding-payouts-and-on-chain-connections/Bitcoin-Puzzle-Evidence-Ledger.xlsx), 3 149 136 байт. ## 2. «Extended public key» №66: новое разобранное ложное совпадение

В [сообщении TamactiJun от 13.09.2024](https://bitcointalk.org/index.php?topic=5218972.msg64526265#msg64526265) строка начинается `4MfFsKsaz…`. Она не попадёт в обычный поиск строк с префиксом `xpub`. Позднее участники обсуждали её как возможный master key. Декодирование сохранённого исходного текста даёт:

| Поле | Результат |
|---|---|
| Base58-строка | 68 символов |
| Декодировано | 50 байт, из них 4 checksum |
| Payload | **46 байт вместо 78** |
| Version | `04b24746`, версия zpub из BIP84 |
| Depth / parent fingerprint / child number | 5 / `00000000` / 0 |
| После 13-байтового заголовка | Сразу 33-байтовая compressed public point |
| Chaincode | **Отсутствует** |
| Base58Check | Верен: `b968b15d` |
| Адрес точки | `13zb1hQbWVsc2S7ZTZnP2G4undNNpdh5so`, №66 |

Длина и поля сверены со [структурой BIP32](https://github.com/bitcoin/bips/blob/master/bip-0032.mediawiki#serialization-format), версия — с [BIP84](https://github.com/bitcoin/bips/blob/master/bip-0084.mediawiki#extended-key-version). Точка проверена на secp256k1, адрес вычислен независимо. Это нестандартная оболочка уже опубликованной точки №66, не пригодный extended public key. Она не сообщает коэффициенты деривации и не является экспортом mSIGNA. Программа, создавшая эту оболочку, не установлена. Все байты и происхождение: PSEUDO_XPUB_66.json — артефакт исходного исследования (`PSEUDO_XPUB_66.json`; вне снимка); воспроизведение — `verify.py`.

## 3. Историческая Armory-находка

Найден [ответ разработчика etotheipi от 17.11.2014](https://bitcointalk.org/index.php?topic=860923.msg9574473#msg9574473), объясняющий журналирование множителей как вспомогательную защиту при ошибках вычисления/памяти. Пользователь показывает форму PrvChain/PubChain, включая пустой parent HASH160, но вместо чисел стоят placeholders. Это современное версии подтверждение назначения файла, дополняющее прежнее чтение исходников. Ни настоящих множителей, ни связи с Puzzle публикация не даёт.

Остальные десять совпадений — общие обсуждения Armory, списки файлов и поддержка. Их нельзя атрибутировать создателю по одному названию программы. Материалы посторонних кошельков не превращались в recovery-входы.

## Форматы и пределы отрицательного результата

Точная карта пригодных полей, ограничений проверок и ссылок на прежние строгие parsers находится в [FORMATS.md](<FORMATS.md>). Проверены имена файлов и содержимое, включая переименованный файл внутри ZIP; расширение само по себе не служило доказательством формата.

Неизвестным остаётся содержимое [Drive-файла без описания](https://drive.google.com/file/d/1au9y4npBxKaCjV3fIrn_ytemEBr0KTzN/view). Connector вернул 404, публичный endpoint — 401: это может быть ограничение доступа, а не доказательство удаления. Для `u.teknik.io/7fNYf.txt` получен 404 и пустой точный CDX; для старой ссылки Anonfiles — пустой CDX. Это не исключает другие URL, зеркала или сохранённые копии. Контекст двух последних ссылок говорит о статистике решений и производном списке адресов, но сами файлы здесь не прочитаны.

Не выполнялись полный обход GitHub histories/всех файловых хостингов, OCR всего исторического корпуса, поиск произвольных закодированных/зашифрованных wallet records, скачивание всех программ и многомиллионных производных баз. Публичное индексирование неполно; общий журнал Armory может быть смешанным и не иметь известных индексов. Нулевой результат данного прохода не исключает Armory, Electrum или mSIGNA как генератор.

**Следующий содержательный вход** — новая прямая ссылка/сохранённая копия файла, для которого есть проверяемая связь с созданием Puzzle, либо открывшийся неописанный Drive-файл. Для Armory нужен настоящий фрагмент строк с множителями; для Electrum — KeyID/MPK с raw-child metadata; для mSIGNA — public point вместе с chaincode и происхождением. Найденная сегодня оболочка №66 эти требования не удовлетворяет.

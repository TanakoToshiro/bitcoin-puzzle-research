# DN-G01 — GPU-перенос исторического System.Random

9 ноября 2026, Europe/Moscow. **Перенос завершён и принят на NVIDIA GeForce
RTX 3070 Ti Laptop GPU. Все прежние исторические векторы и 33 синтетических
поиска совпали с CPU. Скорость пяти новых пилотов — 34.37 млн seed/с
по CUDA-event времени, 33.47 млн seed/с с API. Все 16 схем
обрабатываются одновременно. Полный проход seed-пространства не запускался.**

## Сохранённая модель

Те же 16 схем DN-R01: NextBytes/Next(256), big/little endian, stride1/2,
phase0/1. Источник — официальный System.Random от 12 ноября2014; CPU-снимок
и его 482 файла сохранены без изменений. Train: решения1–50;
holdout:33 опубликованных решения выше50. Пропуски не сжимаются, расход32
внутренних выходов на raw-блок. Связь автора Puzzle с C# по-прежнему не установлена.

Одному CUDA thread соответствует один seed. Для всех схем используется
общий поток. Для каждого номера вызова таблицы содержат маски схем,
отвергаемых наблюдаемым байтом. Вызовы генератора не пропускаются; после
исключения всех схем поток этого seed заканчивается.

Unchecked Int32 реализован через uint32 modulo2^32 и явный знаковый бит.
Signed overflow C++ не используется. Next(256) сохраняет два double-умножения
с явным округлением RN и преобразование к целому с усечением; fast-math
не включён. Семантика этих примитивов описана в [CUDA Double Intrinsics](https://docs.nvidia.com/cuda/archive/12.4.0/cuda-math-api/group__CUDA__MATH__INTRINSIC__DOUBLE.html)
и [CUDA Type Casting Intrinsics](https://docs.nvidia.com/cuda/archive/12.3.2/cuda-math-api/group__CUDA__MATH__INTRINSIC__CAST.html).
Seed2147483647 включён; его нельзя заменить seed0, как установлено в DN-R01.

## Что проверено

- 40 signed seed ×8704 выхода для каждого из трёх потоков: InternalSample,
  NextBytes, Next(256). Все 1,044,480 значения совпали с
  сохранённым историческим C#-эталоном.
- Полные наборы GPU-совпадений всех33 синтетических диапазонов совпали с
  CPU, включая диапазон2^20. Python независимо проверил train и holdout.
- Для256 seed сравнены все16-битные маски, а не только число кандидатов.
  Мутация train-бита отдельно отвергнута для каждой из16 схем.
- Диапазоны нулевой длины, один seed,129 seed, неполный CUDA-блок и верхняя
  граница2^31 проверены с сохранением каждой маски. Неверный диапазон отвергается
  и Python-обёрткой, и C ABI.
- При64 seed и ёмкости буфера4 счётчик сообщает64, результат имеет статус
  `incomplete_overflow`; checkpoint завершения не создаётся. Ошибка не
  превращается в ноль кандидатов. В нормальном режиме GPU возвращает
  seed+маску, затем Python разворачивает пары seed/схема.
- Возобновление не меняет готовые файлы; живой flock запрещает параллельный
  runner; пилот импортируется без повторного kernel. Полный план интервалов
  [0,2^31) проверен арифметически, **сам поиск по этому плану не выполнялся**.

Артефакты: CONTROLS.json — артефакт исходного исследования (`CONTROLS.json`; вне снимка), VECTOR_CONTROLS — артефакт исходного исследования (`VECTOR_CONTROLS.json`; вне снимка),
BOUNDARY_BUFFER_CONTROLS — артефакт исходного исследования (`BOUNDARY_BUFFER_CONTROLS.json`; вне снимка), аудит — артефакт исходного исследования (`AUDIT.json`; вне снимка).
Ошибка в `controls/overflow-checkpoint/ERROR.json` намеренно создана тестом.
Во время принятых нормальных контролей/пилотов неожиданных CUDA-ошибок не было.

## Ресурсы и прогноз

GPU: NVIDIA GeForce RTX 3070 Ti Laptop GPU,8GiB, compute capability8.6. Сборка CUDA13.2,
`-O3 -arch=sm_86 --fmad=false`,128threads/block. Сканирующее ядро использует
76 регистров/thread; атрибут localSizeBytes
равен0. Это не измерение полного VRAM:
контекстCUDA и служебные расходы не входят в размер явных буферов.
Метаданные в GPU.json — артефакт исходного исследования (`GPU.json`; вне снимка) и BUILD.json — артефакт исходного исследования (`BUILD.json`; вне снимка).

По пяти коротким пилотам полное время только kernel примерно
**62.5 с**. С учётом API и измеренной записи checkpoint оставшаяся
работа оценивается примерно в **147.0 с (2.45 мин)**,
плюс однократный запускWSL, созданиеCUDA-контекста, загрузка фильтра и
финальный независимый аудит. Стоимость checkpoint измерена пятью пустыми
диапазонами, без повторного seed-поиска; медиана40.65мс.

Это экстраполяция короткого пилота, не измеренный полный проход. Нагрев,
ограничение мощности ноутбука, фоновые задачи и файловая система могут
увеличить время. Постоянный GPU-контекст сохраняется между блоками; отдельный
запускWSL на каждый миллион seed в подготовленном runner отсутствует.

## Готовность полного прохода

Команда подготовлена в README. Runner пишет в новую серию, проверяет код,
входы и библиотеку, держитOS-lock, сохраняет хэш-цепочку и останавливается
при кандидате или ошибке. План состоит из2051 интервалов:
8 уже проверенныхGPU-диапазонов импортируются, остаётся2043 новых блоков.
Границы дополнительно разделены вокруг коротких парных пилотов, поэтому
нет пропусков или двойного подсчёта. Кандидат независимо проверяется Python
по50 train и33 holdout до любого утверждения о ключе.

Полный поиск **ещё не запущен**. После него потребуется отдельная проверка
точного покрытия и файлов, а не только наличие COMPLETE. GPU-перенос
не добавляет гипотез о кошельках и не доказывает использование.NET автором.

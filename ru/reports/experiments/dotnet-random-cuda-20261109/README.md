# DN-G01 — GPU System.Random

[FINAL_REPORT.md](<FINAL_REPORT.md>), [PROTOCOL.md](<PROTOCOL.md>),
[RESULTS.md](<RESULTS.md>). Полный seed-поиск пока не запускался.

`engine.cu` — точный CUDA RNG и фильтр16 схем; `gpu.py` — ctypes API;
`reference.py` — неизменённый CPU-эталон из DN-R01. `test_gpu.py` — история
приёмки и ограниченных пилотов. Исторический CPU-эксперимент не изменяется.
GPU-библиотека `libdotnet.so` работает через WSL Ubuntu24.04 / CUDA13.2.
Флаги сборки/версии/хэши в BUILD и MANIFEST. Fast-math не используется.

Все команды ниже выполняются из этой папки в PowerShell. Повторять
`test_gpu.py` в запечатанной папке не нужно: это повторит испытания и журнал.

Команда будущего полного прохода (подготовлена, **не выполнена**):

> Исполняемый код/команды опущены в документационной копии.


Один persistent CUDA-контекст, диапазон[0,2147483648), блоки не больше2^20.
8 принятых пилотных диапазонов импортируются без повторного GPU-вычисления.
Повтор той же команды после остановки проверит и пропустит законченные
блоки. При ошибке/overflow завершённый checkpoint не создаётся; кандидаты
проверяются CPU и останавливают очередь. `flock` защищает от второго runner,
PROCESS содержитPID для диагностики. Все результаты пишутся в новую папку.

Для контролируемой остановки после нескольких новых блоков существует
`--max-new-blocks N`, где N положительно. Для продолжения убрать этот аргумент.
Изменять seed-диапазон, размерблока, код или фильтры внутри существующей
конфигурации нельзя. Границы разбиваются вокруг импортированных пилотов;
полный план арифметически проверен. После завершения требуется независимый
аудит всех диапазонов, цепочек и кандидатов. COMPLETE runner сам по себе
об этом аудите не свидетельствует.

Контроли обвязки сохранены отдельно в
`../dotnet-random-cuda-runner-controls-20261109`, их SHA-256 связаны через
RUNNER_CONTROLS.json. ERROR в controls/overflow-checkpoint — намеренный
отрицательный тест, не ошибка реального пилота.

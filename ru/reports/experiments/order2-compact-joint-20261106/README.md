# O2-C01: компактный совместный поиск

Сначала читать [FINAL_REPORT.md](<FINAL_REPORT.md>), [RESULTS.md](<RESULTS.md>),
[PROTOCOL.md](<PROTOCOL.md>) и [SUPPLEMENT_PROTOCOL.md](<SUPPLEMENT_PROTOCOL.md>).

Основная программа: `run.py`; построитель/solver: `compact_solver.py`.
Дополнение: `reviews/run_supplement.py`, `reviews/interval_adapter.py`.
Python — `../../.venv/Scripts/python.exe`, версии зафиксированы в MANIFEST.json.
Все входы в `cases/*/INPUT.json`; EXPECTED используется проверяющим кодом.
Сохранены исходные SMT, ответы, статистика, SHA-256, найденные свидетели.

Цикл закрыт по фиксированному бюджету. Его 18 частичных поисков **не завершены**.
COMPLETE означает завершение экспериментального цикла с отчётом, не полное
восстановление состояний. UNKNOWN не является исключением гипотезы.

Для независимой проверки целостности, из этой папки, только чтение:

> Исполняемый код/команды опущены в документационной копии.


Для новых вычислений сначала создать отдельную папку и новый протокол.
В существующей папке ядро возвращает сохранённый OUTPUT, включая incomplete,
а не начинает незаметно новый поиск. Сохранённые SAT-запросы позволяют восстановить
блокировки; это проверено в reviews/resume. Увеличение лимита — новый запуск,
который должен ссылаться на старый, сохраняя его результаты и статус.

`reviews/finalize.py` пересобирает числовые таблицы и отчёт из результатов без
перезапуска решателей и обновляет COMPLETE. Делать это следует только при
намеренном обновлении отчёта. `reviews/audit.py` заново пишет аудит; для нового
независимого аудита использовать копию серии, чтобы сохранить старый COMPLETE.
Старые матрицы и checkpoint других экспериментов не изменяются.

# E1c: выбор среди совместимых состояний MT

Продолжение E1b: исследуется, даёт ли распределение совместимых состояний основание выбирать ключ №71 лучше случайного. Существование состояния для каждого ключа само по себе этого не решает.

Активный запуск: `20261030-124415-78192a38`. В нём 18 наборов: 12 синтетических и шесть реальных комбинаций API/цели. Заранее назначено 1728 случайных историй отказов. Реальный №75 исключён из ограничений соответствующих наборов, но его ключ уже был известен исследователю: это диагностический отложенный пример, не новый слепой тест.

Во всех вероятностных выводах prior явно задан: равномерное ненулевое состояние MT в 19937-мерном пространстве. Это не установленный способ создания исходного кошелька. Взвешивание историй учитывает число совместимых состояний и вероятность предложения; равные веса разных историй вообще неверны.

## Будущие эксперименты

1. При признаках вырождения весов — отдельный протокол условного предложения историй, с точной калибровкой на малых моделях.
2. Проверяемое аналитическое ограничение массы неувиденных историй, либо точный подсчёт для более коротких участков.
3. Дополнительные обоснованные ограничения на seeding/реальный скрипт; произвольный prior по состояниям их не заменяет.
4. Схемы `randrange(1, n_secp256k1)` с точным, а не достаточным линейным описанием accepted/rejected диапазонов.

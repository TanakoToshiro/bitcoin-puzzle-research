# E1c: вероятности среди совместимых состояний

Дата фиксации: 2026-10-30. Продолжение E1b, без перебора seed. Отдельная локальная проверка уже сохранённых кандидатов по Bitcoin-адресу лежит в address-audit и не участвует в настройке вероятностного метода.

## Вопрос и prior

Совместимое состояние может выдавать настоящий №71; сертификаты E1b обеспечивают существование такого состояния для любого значения в диапазоне. Это не выделяет настоящий ключ. Проверка его адреса подтверждает ключ, не уникальность состояния.

Для этого эксперимента **явно предполагается равномерное распределение по ненулевым 19937-битным координатам достижимого MT**. Это исследовательский prior, не установленный факт о создателе и не утверждение об образе Python seed(). Другие prior — отдельные эксперименты.

1. Для 12 конфигураций E1b без скрытых отказов (переменная ширина, getrandbits(8), Python2 randrange(256)) использовать уже проверенные ранги. При d=70 и ненулевом RHS каждый №71 имеет одинаково 2^(19937-rank(A)-70) прообразов. Поэтому posterior №71 **точно равномерен** при этом prior; Monte Carlo не нужен.
2. Для randrange с неизвестными отказами выполнить ограниченный importance-sampling пилот: interval2 stride1, interval3 stride1, byte_range3 big-endian stride1. Здесь степенные границы дают точные линейные условия любой фиксированной истории. Никаких дополнительных условий вроде bit255=0 из order-моделей не использовать. Общий randrange(order) в этот вероятностный пилот не входит.

## Корректные веса историй

История H содержит число отказов перед каждым принятием. Proposal — независимые геометрические числа P(r)=2^(-r-1) для вызовов с rejection; для float-ветви Python2 число отказов всегда 0. Генерация из воспроизводимого SHAKE-потока битов, без намеренного ограничения числа отказов. При g однобитных условиях истории q(H)=2^-g.

A включает точные условия истории и m известных битов ключей. Если система несовместна, вес 0. Если RHS не нулевой, число состояний в ветви = 2^(19937-rank(A)); нулевое состояние автоматически исключено. После общего масштабирования вес importance равен **2^(g+m-rank(A))**. Для данных с полностью нулевым RHS требуется отдельная поправка на исключённое нулевое состояние; большие реальные/синтетические наборы допускаются только с ненулевым RHS наблюдений.

Нельзя просто усреднять совместимые истории и нельзя дополнительно умножать полученный вес на q(H): proposal уже учтён. Внутри фиксированной совместимой ветви вероятность линейного бита/XOR равна 0/1, если он определён, иначе 1/2. Это Rao–Blackwell усреднение, а не частота одной произвольной точки affine-семейства.

## Контроли и объём пилота

До настоящих данных: исчерпываемая небольшая линейная модель с rejection и равномерным prior; точное перечисление состояний/историй; сравнение с рангами, весами и Monte Carlo. Отдельный искусственный пример обязан обнаружить отличие правильных весов от равных весов историй.

Для каждой из трёх моделей — четыре новые синтетические задачи с равномерными воспроизводимыми состояниями, теми же 83 номерами и обрезкой, целевым №71. Исторический Python сверяет генерацию. На каждую синтетику: 64 истории для interval2/3 и 16 для byte_range3. Истинная скрытая история используется **только после оценки** для диагностики, не добавляется к proposal-выборке и не используется для подстройки.

Настоящие данные: цель №71 со всеми 83 решениями; отдельно цель №75 с исключённым решением №75. Для каждой цели: 256 историй interval2/3 и 64 истории byte_range3. №75 уже публичен и ранее просматривался: это проверка с исключением из fitting, не новая слепая репликация. Всего 1728 proposal-историй, плюс диагностические истинные синтетические истории. Количество не увеличивается после просмотра результата этого пилота.

Сохранять совместность, точные ранги, log2 веса, число фиксированных битов, размерность цели, четыре непересекающихся батча, ESS, максимальную долю веса и условные вероятности. Первичные величины: биты 0/35/69 и XOR 0^35,0^69,35^69, всех неизвестных битов. Остальные биты — диагностические. Малая синтетическая калибровка не достаточна для заявления о практическом предикторе.

**Пилот не может доказать охват всех posterior-мод.** Даже высокий эмпирический ESS не исключает неувиденных историй с большим весом. При нулевой совместимости, малом ESS, доминировании одного веса или нестабильности батчей результат маркируется как ненадёжный для posterior. Никакой «найденный бит» не объявляется только по этой выборке. Если все увиденные ветви дают 1/2, это относится к выборке, не автоматически ко всему объединению.

Из совместимых реальных историй можно сохранить по одному равномерному условному состоянию и проверить его ключ по адресу; это проверка конкретных кандидатов, не доказательство повышенной вероятности успеха и не импорт в кошелёк.

# EL-NW-01 — Electrum 1.9.8 NewWallet

Дата постановки: 04.11.2026, Europe/Moscow. Отдельное исследование пробела из WALLET_COVERAGE_20261104.md. Перебор неизвестного seed и повтор SXN-04 не входят в этап.

## Входы и изоляция

- Electrum tag 1.9.8, commit `f92b483942d3f8ee51506e0436d9b524db33a336`.
- Полный архив upstream; ранее закреплённые wallet/account/bitcoin/version, CLI, wizard, setup и release notes сверяются с E9 побайтно.
- Python-ecdsa 0.11, slowaes 0.1a1, PBKDF2 1.3 из исходных пакетов PyPI; SHA256 пакетов проверяются по metadata. Это выбранный воспроизводимый набор, не доказанный состав каждой распространявшейся сборки 2014 года.
- Уже подготовленный CPython 2.7.9 Windows amd64 и Linux64. Исторические модули не переписываются под Python 3. Все кошельки синтетические, файлы исключительно в `runs/`; сокеты запрещены стендом. Реальный GUI PyQt4, сеть и транзакции с денежными средствами не запускаются.

## Контроли

1. Factory/default/config selection; создание трёх seed из фиксированных значений входной энтропии; штатный nonce/filter, mnemonic, PBKDF2, master, hardened root, accounts, receive/change.
2. Восстановление, сохранение/повторная загрузка, пароль шифрования, watch-only, фактические форматы MPK и KeyID.
3. Gap 256, реальный метод CSV с подменой только оболочки диалога, выборочный dumpprivkeys, второй аккаунт и следующий адрес. Формат Python2 dict order ограничен исполняемым профилем.
4. Необычные случаи: неверная seed-checksum, NFC/case/whitespace, предел entropy, публичная hardened-деривация, IL=n, multisig 2of2/2of3 и повторная загрузка.
5. Независимый Python3: собственная аффинная арифметика secp256k1, HMAC/хеши стандартной библиотеки, полный CSV, положительные и отрицательные условные восстановления из публичного корня и маскированного синтетического наблюдения. Официальный BIP32 vector 1.

## Критерии вывода

Нужно отличать работоспособную условную формулу от доступности параметров настоящего автора. Без достоверных K, chain code и отображения индексов приложение к Puzzle не заявляется. Ограниченный набор seed допустим только при обнаружении конкретного исторического источника малой энтропии; наличие OS entropy или приём произвольной фразы сами по себе такой набор не задают. Полный GUI/все бинарные сборки/все зависимости этим протоколом не покрываются.

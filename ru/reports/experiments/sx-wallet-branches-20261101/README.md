launch.py запускает run.py all, сохраняя stdout/stderr и сведения о среде.
Повторное `python3 run.py all` продолжает с первого отсутствующего блока, проверив
уже записанную цепочку; успешные приёмка/пилоты не повторяются. SERIES.lock использует
flock, PROCESS.json содержит PID/start ticks/cmdline. Для штатной остановки создать
файл STOP; убрать его перед продолжением. Кандидат/ERROR требует разбора, не пропускается.
Не запускать prepare.py/configure_controls.py поверх принятой серии. Сборку воспроизводить
из pinned исходников. Старые эксперименты/checkpoints не меняются.

Полнота определяется корневым COMPLETE.json и независимым аудитом. Частичный проход
не исключает модель во всём диапазоне. BIP44 не означает BIP39: используется точная
SX entropy32 напрямую для master. Другие варианты не включены в этот эксперимент.

## Текущий автономный запуск

launch_and_audit.ps1 — Windows-координатор фонового выполнения. Он держит именованный
mutex, выполняет WSL launch.py, после успешного COMPLETE автоматически запускает
Windows readback.py и finalize_report.py. Последний пишет FINAL_REPORT.md, дополняет
общий RESULTS.md и создаёт READBACK_COMPLETE.json. POSTRUN_STATUS.json содержит состояние
координатора, HOST_PROCESS.json — его PID/время старта. POSTRUN_MANIFEST.json фиксирует
код этой последовательности. Закрытие чата не требуется для работы и не служит остановкой.

Кандидат/ошибка не запускают отчёт об исключении: последовательность остановится с
HOST_ERROR.txt/POSTRUN_STATUS:error. Отрицательный итог допустим только при наличии
READBACK_COMPLETE.json и POSTRUN_STATUS:complete. Для просмотра прогресса читать
STATUS.json и `<mode>/full/STATUS.json`; не создавать второй worker.

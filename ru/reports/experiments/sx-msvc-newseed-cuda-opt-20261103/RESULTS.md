# SXN-02 — CUDA-оптимизация newseed/genpriv, 03.11.2026

Принят ускоренный конвейер для подтверждённой в [SXN-01](<../sx-msvc-newseed-audit-20261103/RESULTS.md>)
модели. На RTX 3070 Ti Laptop получено **10 845,81 seed/с**, включая все четыре
схемы: receive/change × индексы 49/50. Прямое парное сравнение даёт **+11,32%**
пропускной способности и снижение времени на **10,17%**. Экстраполяция полного
uint32-домена — **4,583 суток**. Полный поиск не запускался; все цели синтетические.

**Что изменено.** Развёрнуты SHA-256 rounds с фиксированными переменными;
для второго, постоянного padding-блока заранее вычислены schedule и суммы K+W.
Выбран обычный CUDA C++ вариант 1: 256 threads, 1000 итераций на запуск,
рекомендуемый пакет 65536 seed. Public-point, четыре SHA256d, сложение по порядку
группы и фильтр выполняются на GPU. В обычном режиме на CPU возвращаются только
счётчики и кандидаты. Устранены выдача всех корней на CPU, повторная отправка
их в EC-ядро маленькими пакетами и Python-цикл по дочерним ключам.

Не изменены MT19937, первые 16 draw `%255`, lowercase hex ASCII с сохранением
нулей, ровно 100000 SHA256 и исторический X-only MPK. Это четыре схемы старого
Electrum private export, а не 20 BIP32-схем завершённого SXM-03. Старые исходники,
бинарники и результаты SXN-01 не редактировались.

**Где расходуется время.** Пакет 65536 seed; CUDA events для device-фаз.

| Операция | Измерение |
|---|---:|
| Исходный stretch, 256 threads | 6161,82 мс GPU |
| Специализированный stretch | 6032,80 мс GPU |
| Public-point в новом конвейере | около 4,9 мс GPU |
| Все четыре дочерних ключа и фильтр | около 0,33 мс GPU |
| MT + hex | обычно 0,09–0,46 мс GPU; в некоторых запусках около 3,3 мс |
| Возврат счётчиков, без кандидатов | около 0,13–0,18 мс CUDA-event span |
| Прежний Python child/filter с audit-данными | 0,53–0,59 с по host monotonic |
| Облегчённый CPU child/filter без audit-данных | около 0,39 с по host monotonic |

Stretch составляет более **99,8% измеренных device-фаз** нового конвейера.
Каждый seed требует **200000 compression blocks** SHA-256: вход каждой из
100000 итераций имеет длину 64 байта, поэтому нужен ещё отдельный padding-блок.
Микрозамеры на 10000 итерациях: data compression — 365,18 мс, padding compression —
242,58 мс. Это отдельные искусственные ядра, не действительные Electrum-хеши;
их времена нельзя строго складывать из-за различий регистров и планирования.
Они показывают, что даже постоянный padding-блок остаётся существенной работой.

CUDA SHA-ядро само ускорилось на **2,14%**. Остальная часть выигрыша получена
переносом завершающих операций и сокращением обменов с CPU. Дополнительные
варианты не дали существенного выигрыша относительно принятого:

| Вариант на полном stretch100000 | GPU мс | Регистров на поток |
|---|---:|---:|
| Исходное ядро | 6161,82 | 56 |
| Специализация, вариант 1 | 6032,80 | 56 |
| Явные funnel-shift / lop3, вариант 2 | 6047,61 | 61 |
| Две независимые цепочки на поток, вариант 3 | 6035,96 | 125 |
| Вариант 1, chunk 4000 | 6034,39 | 56 |
| Вариант 1, chunk 10000 | 6034,17 | 56 |

У SHA-вариантов нет spills/local memory по ptxas. EC-ядро: 96 регистров,
32 байта stack, без spill loads/stores; child/filter: 64 регистра, без spills.
Пакет 131072 почти точно удвоил GPU stretch до 12064,96 мс, поэтому больший
пакет преимуществ не показал. `ncu`/`nsys` отсутствуют в проверенной цепочке;
использованы CUDA events, host timers и ptxas. Hardware stall counters и SASS
instruction mix не измерялись. Сырые замеры — артефакт исходного исследования (`MEASUREMENTS.json`; вне снимка),
начальный профиль — артефакт исходного исследования (`BASELINE_PROFILE.json`; вне снимка), ptxas — артефакт исходного исследования (`build-tail.log`; вне снимка).

**Проверка времени.** Во время измерения обнаружено расхождение часов WSL:
`CLOCK_REALTIME` иногда скачет примерно на 0,92–0,95 с; `CLOCK_MONOTONIC`
также расходится с `CLOCK_MONOTONIC_RAW` и CUDA events. Причина поправок часов
не устанавливалась. Поэтому первые UTC-based `states_per_second` сохранены
как диагностика, но не используются для итоговой скорости или выбора варианта.

Повторены три пары на одних диапазонах, с порядком baseline→optimized,
optimized→baseline, baseline→optimized. Исходный CPU-конвейер для этого сравнения
облегчён: удалены hex-форматирование всех children, audit digest и witnesses,
префиксы подготовлены заранее. Обе стороны считают точные четыре скаляра и фильтр.

| Конвейер | Seed | CLOCK_MONOTONIC_RAW | Seed/с | Прогноз 2^32 |
|---|---:|---:|---:|---:|
| Исходный CUDA + облегчённый CPU | 196608 | 20,18003 с | 9742,70 | 5,102 суток |
| Оптимизированный GPU | 196608 | 18,12755 с | 10845,81 | 4,583 суток |

Внешний Windows Stopwatch дал 9754,10 и 10849,19 seed/с соответственно;
на каждом пакете расхождение с RAW меньше 0,04 с. Разброс трёх оптимизированных
пакетов: 10841,45–10848,17 seed/с. Это короткая серия; она не доказывает
стабильность ноутбука в течение нескольких суток. Температура в основных
замерах 56–63°C, наблюдаемая SM clock 840 MHz. Разгон и параметры питания
не менялись. Часы WSL — артефакт исходного исследования (`CLOCK_COMPARISON.json`; вне снимка), внешние часы — артефакт исходного исследования (`HOST_CLOCK.jsonl`; вне снимка),
пересчёт — артефакт исходного исследования (`READBACK.json`; вне снимка).

Предыдущая оценка SXN-01 в 5,49 суток получена в другой серии и с другими
накладными расходами; разницу с ней нельзя целиком приписывать CUDA-оптимизации.
Итоговый API optimized.py — артефакт исходного исследования (`optimized.py`; вне снимка) использует CLOCK_MONOTONIC_RAW.

**Проверки точности.**

- Все три SHA-варианта совпали с принятой исходной реализацией на границах
  uint32, нечётных размерах, разных threads, rounds и chunk. Проверены полные
  100000 итераций и сохранённые native-результаты.
- Новый полный GPU-конвейер совпал с **19 native-векторами / 76 children**,
  включая leading/trailing zero entropy. Это повторная сверка с сохранёнными
  результатами Windows, а не новые 403 native-вызова.
- **65536 полных записей / 262144 children** совпали с прежним конвейером
  по полным 256-битным результатам через SHA256 digests. Все промежуточные X
  отдельно проверены на native и affine контролях.
- 69 корней проверены независимым affine/hashlib расчётом; четыре 49-битных
  planted hits, отрицательная цель, принудительное совпадение всех схем,
  неполные блоки и верхняя граница seed прошли.
- 45 крайних случаев сложения включают offset ≥ n и сумму 0. Использована
  арифметика Electrum `(root + offset) mod n`, а не BIP32-отказы.
- Невалидные корни, переполнение candidate buffer и неверные параметры
  завершаются ошибкой. Успех требует `processed == count` и
  `checked_schemes == 4*count`; переполненный пакет нельзя зачесть.
- Повторное чтение отдельным процессом пересчитало hashlib/affine для 19
  native-векторов, проверило хеши измеренных файлов, новый API и все 86
  артефактов печати SXN-01. Это повторное чтение тем же агентом, не второй аудитор.

SHA-контроли — артефакт исходного исследования (`VARIANT_CONTROLS.json`; вне снимка), GPU-контроли — артефакт исходного исследования (`TAIL_CONTROLS.json`; вне снимка),
повторное чтение — артефакт исходного исследования (`READBACK.json`; вне снимка), происхождение EC-кода — артефакт исходного исследования (`TAIL_PROVENANCE.json`; вне снимка).

**Применимость к Puzzle.** Модель остаётся отдельной конечной гипотезой,
подтверждённой для private export исторического SX/MSVC. Оптимизация уменьшила
измеренную цену, но не установила связь с автором Puzzle и не исключила модель.
Покрытие настоящего Puzzle — **0**, новых ключей или битов нет. Полный поиск
требует отдельного runner с durable checkpoints, контролем диапазонов и
независимой проверкой кандидатов по другим известным индексам. Здесь принят
ограниченный batch API; многосуточный runner не запускался.

и FINAL_MANIFEST.json — артефакт исходного исследования (`FINAL_MANIFEST.json`; вне снимка).

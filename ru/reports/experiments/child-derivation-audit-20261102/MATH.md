# Формулы, условия и границы результата

Пусть n — порядок secp256k1, raw_i — исходный child private key. Гипотеза обработки экспорта:

`puzzle_i = 2^(i−1) + raw_i mod 2^(i−1)`.

Из решения известен `r_i = raw_i mod 2^b_i`, где b_i=i−1. Установленный старший бит — результат обработки, не наблюдение raw. В зафиксированном наборе максимальное b=134, сумма b по83 решениям=3767. Эту сумму нельзя механически вычитать из числа битов master.

## Аддитивное семейство: Electrum old и normal BIP32

Electrum old: `raw_i=(s+a_i) mod n`, `a_i=doubleSHA256(ASCII(index:branch:)+MPK_bytes) mod n`. MPK — публичная точка sG, а не один из адресов. BIP32: `I=HMAC-SHA512(c,serP(K)||ser32(index))`, `raw_i=(s+parse256(I_L)) mod n`, новый chaincode=I_R. Для известного xpub все non-hardened пути можно пройти публично и сложить offsets modulo n. Hardened путь использует приватное значение во входе HMAC и этому условию не отвечает.

При известных offsets:

`raw_i=s+a_i−t_i*n`, t_i∈{0,1} для приведённого a_i.

Порог каждого t_i — n−a_i. Сортируем пороги, разбиваем [1,n) на не более m+1 интервалов. Внутри интервала все t_i фиксированы, и наблюдения превращаются в совместные сравнения `s ≡ r_i−a_i+t_i*n (mod 2^b_i)`. Модули вложены; достаточно проверить совместимость с самым длинным остатком. Получаем точный набор арифметических прогрессий без перечисления корней. Исключаются raw_i=0. Это реализовано в additive.py и проверено исчерпывающе на800 малых системах, включая несовместные и полные наблюдения.

На24 синтетических BIP32-примерах с настоящим порядком,83 индексами и известным xpub до проверки `sG=K` осталось примерно2^114.78–2^117.69 арифметических вариантов; по одному самому длинному остатку их около2^122. Остальные наблюдения добавили4.31–7.22 бита сокращения в этих примерах. Это **не** распределение реальных master keys, не ограничение для всех возможных алгоритмов и не оценка стоимости лучшего DLP. При фиксированном xpub скаляр s математически единственен; речь о промежуточном пространстве предложенного арифметического метода. Ограничения происхождения BIP32 master от seed тоже не включены в этот счёт.

Для меньшей цели i≤j известного решения j уже достаточно:

`raw_i mod2^(i−1) ∈ {r_j+a_i−a_j+u*n mod2^(i−1):u=−1,0,1}`.

Это следствие применимо и к полностью non-hardened путям от одного известного xpub. Старый E7 уже проверил его для Electrum; новый результат расширяет проверку на BIP32. Маскированный целевой ключ выбирается проверкой адреса. Оно не позволяет восстановить неизвестный MPK/xpub. Пять REAL_RELAXED_WITNESSES показывают лишь, что уравнения с произвольно свободными a_i допускают разные родители. Они не доказывают существование соответствующего HMAC-ключа или кошелька.

## Мультипликативное семейство: Armory classic

Исторический шаг:

```text
m_j = BE_integer(C XOR doubleSHA256(uncompressed(P_j))) mod n
k_(j+1) = m_j*k_j mod n
P_(j+1) = m_j*P_j
```

При известных watch-only `(P_root,C)` публичный путь даёт все m_j и их произведения `a_i=product(m_j) mod n`. Тогда `raw_i=a_i*s mod n`, где s — приватный корень. Исходный секрет не нужен для вычисления a_i. **Один chaincode без подходящей публичной исходной точки недостаточен для этого пути**, равно как и точка без chaincode. В данном интерфейсе puzzle i соответствует i-му переходу от root (Armory chainIndex=i−1); другую схему индексов надо задавать отдельно.

Из `raw_i = r_i+2^b_i*q_i` следует:

```text
alpha_i = a_i * inverse(2^b_i) mod n
beta_i  = r_i * inverse(2^b_i) mod n
alpha_i*s − beta_i ≡ q_i (mod n)
0 ≤ q_i ≤ floor((n−1−r_i)/2^b_i)
```

Это экземпляр Hidden Number Problem с малыми q_i. Используем веса w_i=2^b_i. Базис решётки размерности m+1:

```text
diag(n*w_1, ..., n*w_m), последний столбец нулевой;
последняя строка (alpha_1*w_1, ..., alpha_m*w_m, 1).
```

Цель `(beta_i*w_i+floor((n−1)/2), ..., floor((n−1)/2))`. Для настоящего s существует вектор решётки с координатными ошибками порядка n/2. LLL сокращает базис; точный по рациональной арифметике Babai nearest-plane предлагает кандидата. Проверяются все наблюдения и `sG=P_root`; ложный ближайший вектор не принимается. Для каждого примера сохранены базис, unimodular transform (проверены det=±1 и U*B=B_reduced), reduced basis, target, Babai coefficients и candidate. Это воспроизводимый положительный эксперимент, не доказательство успеха Babai для всех кошельков/размеров утечки.

На12 независимых синтетических root с историческим default chaincode восстановление сработало по четырём индексам120/125/130/135 (119/124/129/134 известных младших битов).79 остальных известных индексов каждого случая используются после recovery, не как вход решётки.36 изменений residue/chaincode/index отвергнуты. Отдельный процесс recover_watchonly.py получает только watch-only данные и четыре masked private key, заново считает публичные множители и восстанавливает корень. Это не перебор коротких seed: алгоритм решает256-битный scalar и не получает его при подборе.

HNP/LLL — известный класс методов: [Boneh–Venkatesan, CRYPTO 1996](https://cs.stanford.edu/people/dabo/pubs/abstracts/dhmsb.html). Здесь проверено конкретное преобразование исторической Armory-цепочки и наблюдений Puzzle; новизна в мировой литературе не заявляется.

## Чего это не решает

Для настоящего Puzzle `(P_root,C)` Armory не найдено. При неизвестном C множители требуют XOR с неизвестными байтами и хеширования неизвестных полных исходных точек. Линейный HNP-вход тогда не получен. Нельзя подставлять `puzzle_i*G`: это точка изменённого ключа, а не raw_i*G. Прежний E6H исследовал другую задачу неизвестного C; его MITM сохранял масштаб порядка2^128, а feedback E7 не является штатной цепочкой.

Для BIP32 неизвестны chaincode и публичный родитель; простое вычитание двух потомков убирает s, но оставляет два неизвестных HMAC-выхода. Code + masked private keys сами по себе не дают использованные выше коэффициенты. Наличие множества ограничений может означать единственность решения, однако не предъявляет дешёвого способа его найти. В этом исследовании без дополнительных параметров не получен практический поиск до2^32 или доказанное ускорение настоящего №71.

Корень/seed/предок — разные цели: восстановленный Electrum exponent не обязательно раскрывает mnemonic; BIP32 account private key за hardened-уровнем не раскрывает master выше него; private scalar без chaincode не равен xprv. В положительном Armory-тесте восстановлен именно корневой приватный scalar классической цепочки.

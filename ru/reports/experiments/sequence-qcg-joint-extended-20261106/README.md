# SEQ-24 — расширенный повтор полноразмерного SEQ-23

Повторяются те же шесть FF-входов с исходными масками, с 8 GiB внешней памяти и 600 с check-sat на вход. Очередь последовательная. [Протокол](<PROTOCOL.md>), [итоговый отчёт](<FINAL_REPORT.md>).

`encoding_seq23.py` — побайтная копия прежнего построителя. Рабочий процесс сверяет каждое SMT-тело с сохранённой задачей до поиска. Меняются только два ресурсных параметра; старые файлы не изменяются. Новое состояние Z3 начинает поиск с начала, checkpoint старой попытки не существует.

## Сохранённые данные

- `inputs/full*/` — прежние публичные INPUT.json и query-seq23.smt2; `INPUT_MAP.json` связывает их хеши с прежними попытками.
- `CHECKER_TRUTH.json`, `reference/GAUGE_WITNESSES.json` — эталон аудитора; рабочий процесс их не читает.
- `runs/full*/query.smt2`, `MODEL.json` — новая задача и проверка совпадения с прежним телом.
- `runs/full*/PROCESS.json`, `START.json`, `CHECK_STARTED.json` — PID, параметры, начало построения/поиска.
- `runs/full*/MEMORY.jsonl`, `RESOURCE_WAIT.json`, `OUTER.json` — ресурсная трасса, ожидание системного резерва и итоговая причина завершения.
- `RESULT.json` появляется при ответе Z3; при внешней остановке итог хранится в OUTER.json. `ERROR.json`, если возник, содержит техническое исключение. stdout/stderr сохраняются всегда для запущенных процессов.
- `RESULTS.json`, `AUDIT.json`, `CLOSURE.json` — сравнение шести случаев, аудит и список оставшихся ограничений.
- `MANIFEST.json` фиксирует код/план/входы до запуска; `ARTIFACTS.json` — окончательный архив, включая отчёты.

Не запускать стадии повторно поверх завершённого каталога. Для следующего увеличения лимитов использовать отдельную папку и сохранить связь с конкретной прежней записью. Наличие COMPLETE означает завершение указанной очереди и отчёта, не получение ответа для каждого ограниченного случая.

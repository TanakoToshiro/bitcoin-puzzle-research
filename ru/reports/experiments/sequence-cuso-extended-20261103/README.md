# SEQ-16 — увеличенные лимиты cuso

Продолжение 32 ограниченных записей SEQ-15 на тех же 16 blind-входах.
Старые результаты не перезаписываются. Успешное завершение серии
подтверждается только совокупностью `COMPLETE.json`, `ACCEPTANCE.json`
и `ARTIFACTS.json`; пока этих файлов нет, работа продолжается.

Итог после завершения: [FINAL_REPORT.md](<FINAL_REPORT.md>),
машиночитаемый учёт — `RESULTS.json`. Условия и история ресурсов:
[PROTOCOL.md](<PROTOCOL.md>), [EXECUTION_NOTE.md](<EXECUTION_NOTE.md>).
Разные версии планов и обёрток зарегистрированы отдельными манифестами.

`attempts/` хранит основную очередь; `graph_v2/` — повтор двух графовых
SEQ-12 с точным ускорением построения графа. `followup/` и `priority_graph/`
содержат отдельный вариант с доказанным отсечением непродуктивных ветвей.
`memory_retry/` заполняется только при необходимости отдельного повторения
случайного контроля, остановленного защитой общей памяти.
`diagnostics/` и `saved_lattice_retry/` не смешиваются с основными результатами.
Исходные timeout/error записи сохраняются после успешного продолжения.

Таймаут и нехватка памяти не означают отсутствия корней.
Доказательства ограничений стратегии находятся в
[OBSTRUCTION_PROOFS.md](<OBSTRUCTION_PROOFS.md>) и
[OBSTRUCTION_ORDER_EXTENSION.md](<OBSTRUCTION_ORDER_EXTENSION.md>).
Они имеют более узкий смысл, чем исключение скрытого генератора.

После принятия запускается только проверка без изменения артефактов:

> Исполняемый код/команды опущены в документационной копии.


Не запускать `status.py`, генераторы сводок или координаторы после принятия:
они записывают файлы и нарушат опечатанный снимок. Для будущего продолжения
нужна новая папка эксперимента с точными ссылками на сохранённые входы.

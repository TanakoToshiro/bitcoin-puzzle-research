# BMD-01: конечный новый вариант, подготовленный после binary controls

Объект — публичная Puzzle. Подтверждена реальная CLI-композиция официального
BX2.0.0 Windows x64; связь программы с автором по-прежнему не установлена.
Полный поиск и измерительный GPU-пилот в этой проверке не выполнялись.

## Точная цепочка и множество новых inputs

```text
uint32 s ∈ [0, 4294967296)
→ MT19937(s), первые32 uint32 outputs %255
→ 32-byte E
→ mnemonic-encode (8×3 слова)
→ mnemonic-decode (нефиксированная ширина hex каждого uint32)
→ строгий hex parser, hd-new minimum16 bytes
→ BIP32, 20 схем E15 для исходной entropy32
→ младшая puzzle-маска
```

Ровно эквивалентное сокращение для корректно сгенерированных слов:

```text
H = concat(format(BE32(E[4j:4j+4]), 'x') for j=0..7)
```

Ноль кодируется одним символом `0`. Рассматривать новое HD-семейство только
при `len(H) ∈ {32,34,…,62}`. HD seed равен `bytes.fromhex(H)` (16…31 байт).

Остальные классы исключаются **до HD**, с раздельными счётчиками:

- `len(H)==64`: entropy не изменилась, соответствующая схема уже покрыта E15;
- нечётная длина: официальный hex parser отвергает;
- чётная длина<32: официальный hd-new отвергает как менее128 бит.

Классы должны в сумме дать весь просмотренный интервал исходных RNG seed.
Не объявлять число новых состояний равным размеру всего uint32-домена и не
оценивать его по136 историческим тестовым seed. В future full-run исходный
домен всё равно проходит целиком для классификации, HD выполняется только
в changed_valid-классе. Возможные коллизии преобразованных seed не делают
поиск ошибочным и не дают права пропускать непроверенный RNG state.

Важный контроль: `01234567` и `0abcdef0` во внутренних chunks теряют по одной
hex-цифре. Общая потеря2 чётна, но последующие byte boundaries пересобираются.
Удаление только целых нулевых байтов по чанкам — неправильная оптимизация.

Для исходной entropy16 новый класс отсутствует: любое укорачивание либо даёт
нечётный hex, либо<16bytes; принятый исход длины16 равен прежнему E15.
У32→16 преобразования нельзя автоматически отбрасывать результат как E15
length16: полученные16bytes обычно не равны первым16 исходной entropy.

## Ровно20 HD-схем

SCHEMES.json — артефакт исходного исследования (`SCHEMES.json`; вне снимка) — побайтно те же поля20 строк E15 с length32,
исходные id20…39 сохранены. `length:32` обозначает длину **до codec**;
эффективная длина master seed переменная16…31 и нигде не дополняется нулями.

| Parent | Final child | Index |
|---|---|---|
| m | normal/hardened | i−1 / i |
| m/0 | normal/hardened | i−1 / i |
| m/0'/0 | normal/hardened | i−1 / i |
| m/0'/1 | normal/hardened | i−1 / i |
| m/44'/0'/0'/0 | normal | i−1 / i |
| m/44'/0'/0'/1 | normal | i−1 / i |

Это исследовательский набор, а не штатная конфигурация/автоматический выбор BX.
Индекс puzzle i сохраняется с пропусками; маска =2^(i−1)+(raw mod2^(i−1)).
Фильтр будущего поиска:49 младших бит training№50, потом все№1–50.
Holdout№51+ только после training-кандидата. Синтетические№71 в controls
не являются использованием реальных holdout данных.

Invalid master/child делает блок незавершённым с ошибкой; не относить его
к source-level reject и не сдвигать индекс. Любой кандидат сначала сохранять
с исходным RNG seed, E, H, effective seed и scheme ID, затем независимо
пересчитывать настоящим CLI/affine reference. Buffer overflow — ошибка блока.

## Что готово, что ещё необходимо для production search

- `search_reference.py`: точный transform, MT→entropy, BIP32/SEC на независимой
  affine арифметике,20 путей и маска. Нет словаря в hot path; эквивалентность
  формулы словарному и реальному бинарному путям проверена.
- `block_reference.py`: ограниченный CPU worker≤4096 states; явные категории,
  переменная master length, отказ при overflow/invalid HD. Реальных targets
  в коде нет. `BLOCK_CONTROLS.json`: targets взяты из native binary traces.
- Прежде полного прохода: перенести только этот transform/predicate и length
  в новую копию принятого CUDA HD-кода; проверить промежуточные bytes/узлы,
  все20 planted-positive/negative, крайние seed/блоки, candidate buffer,
  checkpoint corruption/stop/resume/concurrency и независимую сверку кандидатов.
- После приёмки —3–5 разнесённых пилотных блоков после прогрева, измерить
  RNG+codec, HD и wall/IO, долю eligible, GPU memory. Затем дать реальную
  стоимость всего `[0,2^32)`. Скорость E15 и46 секунд native controls не
  являются этой оценкой. Стоимость сейчас **не измерена**.

Полноценного search runner с checkpoints/GPU в текущей папке нет; CPU worker
не объявляется готовым к unattended full-run. Никакие реальные состояния
по фильтру настоящего Puzzle ещё не проверены. Новая область узкая и обоснована
бинарным поведением, поэтому следующий разумный этап — именно её CUDA-приёмка
и пилот, без новых RNG,passphrase,dict-order,масок или расширения путей.

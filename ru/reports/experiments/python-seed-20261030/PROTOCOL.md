# E2: точный исторический Python и ограниченные целочисленные seed

Зафиксировано 2026-10-30 до просмотра результатов поиска по настоящим решениям.

## Цель и предел

Проверить модели, ошибочно отождествлённые с Python random в рассмотренном внешнем сканере. Реальные CPython 2.7.9 и 3.4.2 собираются из официальных исходников в изолированной WSL-среде. Основной пилот рассматривает только явные неотрицательные целочисленные seed `[0, 2^20)`; это 0,0244140625% пространства 32-битных seed, не все Python seed. Диапазон не включает Unix timestamp создания puzzle. Утверждение об исключении Python в целом недопустимо.

Расчётный бюджет: до 1200 с wall time на контроль восстановления синтетических seed и основной поиск вместе, после сборки/разработки и получения контрольных векторов. Каждый завершённый блок сохраняется. При исчерпании бюджета указать фактические интервалы; не расширять автоматически до 2^32 и не запускать другие эксперименты.

## Точные модели

`rng = random.Random(seed)` исторического интерпретатора, один вызов инициализации до последовательности. Шесть описаний получения исходного 256-битного значения:

1. `bits256`: `getrandbits(256)`.
2. `words_forward_big`: восемь последовательных `getrandbits(32)`, каждое в big-endian, соединить в порядке выдачи, прочесть как big-endian.
3. `words_forward_little`: то же с little-endian байтами слова.
4. `words_reverse_big`: обратный порядок восьми big-endian слов.
5. `words_reverse_little`: обратный порядок восьми little-endian слов.
6. `randrange`: реальный `randrange(1, n_secp256k1)`, включая rejection sampling. Верхняя граница исключена; width=`n−1`, к принятому остатку добавляется 1.

Каждое описание проверяется для stride 1 и 2: puzzle i использует исходный элемент с нулевым индексом `(i−1)*stride`. Самый первый элемент используется для №1 и расходуется, хотя свободных битов у него нет. Маскирование `key_i = 2^(i−1) | (raw_i & (2^(i−1)−1))`. Маскированный ключ не возвращается в генератор; пропуски поздних задач не сжимают последовательность.

`words_reverse_big` и `bits256` являются эквивалентными сборками той же последовательности uint32. Эквивалентность должна пройти исторические векторы и проверку исходной семантики. При успехе выполняется один поиск с двумя логическими именами. Итого: 24 логических описания (2 версии × 6 API × 2 stride), 20 физических поисков (2 × 5 × 2); версии считаются отдельными проверками, не 20 независимыми криптографическими семействами.

## Контроли до допуска к поиску

Seed для векторов: `0, 1, 5489, 2^32−1, 2^64+0x123456789, 2^256−1`. Для каждой версии/API получить 320 исходных значений и хвост следующих 10 uint32. Это покрывает первые 160 использованных ключей при stride 2. Независимая Python-арифметика `init_by_array`/twist/tempering должна совпасть побитно с историческими интерпретаторами. Дополнительно проверить getrandbits на границах слов и принудительные отклонённые выборки randrange.

Обязательный положительный контроль: отдельно восстановить synthetic seed 42421 в пространстве `[0,2^16)` для каждого физического поиска. Контрольные решения №1–50 и отложенные №51–160 создаются независимой реализацией с теми же масками/stride. Ожидается ровно один совпавший seed и правильные все отложенные значения. Испорченная сборка должна отличаться на контрольных векторах. Числа `2^32−1` и большие seed проверяются векторами, а не якобы поиском за пределами пилота.

## Настоящие данные и приёмка

Снимок 83 ранее проверенных решений копируется в запуск с SHA-256. Подбор использует только №1–50. Выжившие seed проверяются по всем поздним известным решениям; только полное совпадение даёт кандидата №71 для независимой проверки точки/HASH160/адреса через coincurve. Тайм-аут не считается отрицательным результатом.

Обработка идёт блоками по 16384 seed; в каждом сохраняются точные полуинтервалы, число проверок, распределение номера первого несовпадения, выжившие seed, время и хеши входов. Завершённые блоки при resume пропускаются. Незавершённый блок может быть повторён, но никогда не засчитывается дважды. `RESULTS.md` обновляется после каждого завершённого физического поиска; журнал блоков и результаты доступны раньше.

Сохраняются исходные архивы, версии/логи сборки/архивы runtime, точные векторы, замороженный код/протокол/входы, результаты контролей и пилота, ошибки и интерпретации. Окружение старых Python используется только для локальных числовых задач, не для сетевых операций. Строковые seed, `seed(None)`, другие вызовы API, переменные пропуски, нестандартные начальные смещения и другие диапазоны seed исключены из данного протокола.

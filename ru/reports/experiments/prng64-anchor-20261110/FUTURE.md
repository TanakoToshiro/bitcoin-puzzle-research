# Неиспытанное продолжение: упростить переносы известной суммы

Это предложение для отдельной серии, не изменение RNG64-04 и не заявленное ускорение.
Текущая серия изолирует перенос координат, сохраняя прежнюю кодировку переносов.

В anchor известно целое слово z=x+y mod 2^64. Для каждого бита:

`y_j = x_j XOR c_j XOR z_j`, `c_0=0`.

Совместно с этим равенством обычный перенос majority(x_j,y_j,c_j) упрощается:

- при z_j=0: `c_(j+1) = x_j OR c_j`;
- при z_j=1: `c_(j+1) = x_j AND c_j`.

Проверяется подстановкой двух значений c_j и x_j. При z_j=0 и c_j=0 имеем
y_j=x_j, поэтому перенос равен x_j; при c_j=1 имеем y_j=NOT x_j, перенос 1.
При z_j=1 и c_j=0 имеем y_j=NOT x_j, перенос 0; при c_j=1 имеем y_j=x_j,
перенос x_j. Последний перенос за бит63 отбрасывается согласно modulo 2^64.

Значит, все y и переносы можно выразить через 64 бита x, а затем распространять
линейные переходы с явными XOR-уравнениями. Известная сумма должна быть использована
ровно один раз; нельзя забывать ограничение ненулевого состояния и перепутать
сложение с вычитанием/заёмом. Эта редукция алгебраически эквивалентна `(x,z-x)`
в прежнем Z3, поэтому сама по себе не новая информация и не гарантия выигрыша.
Проверяемое отличие — явная упрощённая сеть AND/OR и XOR для CryptoMiniSat,
а не общая bit-vector операция вычитания.

Возможная следующая серия: тот же набор открытых входов, сначала исчерпывающий
контроль переносов и recovery, затем сравнение с текущими сохранёнными формулами
при одинаковом бюджете. До такой проверки считать ускорение недоказанным.

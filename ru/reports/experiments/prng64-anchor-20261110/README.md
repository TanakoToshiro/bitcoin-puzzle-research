Каждый движок каждой строки должен завершить собственный слепой synthetic-контроль
до первого запроса по реальному ключу. Скрытое состояние читает проверяющая обвязка,
но не worker.py/решатель. Вход алгоритма содержит только family и observations.
Контроль не считается пройденным по одному найденному состоянию: требуется конечный
UNSAT после блокировки всех найденных состояний. UNKNOWN не исключает модель.

RUN.lock и WORKER.lock используют блокировку ОС, а не наличие файла. PROCESS.json
содержит последний PID, путь и время. Не запускать второй runner поверх живого.
При перезапуске завершённые OUTPUT/RESULT используются без повторных вычислений;
сохранённые ответы отдельных запросов восстанавливают перечисление состояний.
При незавершённом worker сначала проверить его живой процесс и блокировку.

Worker запускается напрямую через базовый python.exe с библиотеками локального
окружения в PYTHONPATH. Поэтому внешний watchdog завершает непосредственный
процесс solver, а не только промежуточный venv-launcher. Изменение исходного кода
после MANIFEST.json запрещено; новая модель требует отдельной серии.

formula-*.json — XOR/CNF, formula-*.smt2 — cvc5. query-*.json сохраняет и обычное
состояние перед выходом 0, и состояние в новых координатах сразу после anchor.
Блокировка SAT выполняется в новых координатах, числовая проверка — в исходных.
Подробности: cases/<id>/{synthetic,real}/<engine>.

RESULTS.md и JOURNAL.md пополняются после этапов. RUN_RESULT.json, SUMMARY.csv,
FINAL_REPORT.md и COMPLETE.json создают сводку с явно сохранёнными открытыми
случаями. Отчёт пересобирается из артефактов без запуска solver.

API решателей и источники исторических генераторов не менялись. Их снимки доступны
в предыдущих сериях prng64-solver-20261110/sources и prng64-state-20261105/SOURCES.json.
Новая серия фиксирует версии и хэши собственных бинарных библиотек в MANIFEST.json.

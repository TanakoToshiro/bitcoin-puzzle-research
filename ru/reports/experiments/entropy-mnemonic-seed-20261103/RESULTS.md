# EMS-01 — итог исторического аудита

03.11.2026. **Заданный BIP39/PBKDF2-пилот не запущен: в BX 2.0.0
обнаружен старый Electrum codec, а не BIP39.** Это установленное препятствие
на первом этапе handoff, не отрицательный результат перебора.

Полные деревья BX и libbitcoin, исходники команд, реестр и функции зависимости
подтверждают mnemonic-encode/decode: английский словарь1626, три слова на uint32,
без checksum и PBKDF2. Passphrase/salt/2048 iterations/64-byte PBKDF2 seed
не относятся к этому пути. [Подробный маршрут](<HISTORICAL_PATH.md>),
строки доказательств — артефакт исходного исследования (`SOURCE_FACTS.json`; вне снимка), источники — артефакт исходного исследования (`SOURCES.json`; вне снимка).

## Новый существенный результат

Исторический decoder теряет ведущие нули каждого 32-битного hex-блока.
Поэтому утверждение «mnemonic encode/decode всегда даёт те же bytes, что E15»
неверно. При entropy16 допустимые hd-new результаты сохраняют исходные bytes;
при entropy32 встречается допустимый сокращённый seed. Пример:
`00112233` + `baadf00d`×7 превращается в `112233` + `baadf00d`×7, то есть31 байт.
Это отдельная возможная source-backed композиция без PBKDF2; её поиск не выполнен.

На136 сохранённых RNG seeds для16 байт:107 сохранённых,27 odd-hex,2 слишком
коротких. Для32 байт:82 сохранённых,13 допустимых изменённых,41 odd-hex.
Это контрольные случаи, не статистическая оценка полного домена.

## Что проверено

- 136 RNG seed: Python MT, std::mt19937 и сохранённые исторические bytes,
  включая0,1,2³²−1; именно `%255`.
- 80 сохранённых бинарных сценариев / 50768 байт
  воспроизведены; оригинальный PE имеет прежний SHA-256. PE повторно не эмулировался.
- 330 entropy-case и9 decoder edge-case;
  вместе с RNG это475 команд на каждую C++-сборку. Python совпал с O0 и O2,
  официальный baadf00d-vector пройден, stderr пуст.
- Сохранены entropy, слова/UTF-8, decoded hex, статус hd-new и допустимые master
  scalar/chaincode. Нулевые/короткие/нечётные inputs не выданы за отрицательный поиск.
- Источники проверены по SHA-256 и Git blob SHA-1; прежние E15 input pins
  и readback hashes сверены. Новых реальных Puzzle keys в контроли не загружалось.

Приёмка касается **только исторического кодека и RNG-контролей**. Современный
g++ с type/hex/assert shims и -fwrapv не равен полному бинарнику2014 года.
Точная dependency-сборка релизного EXE не восстановлена; его mnemonic-интерфейс
подтверждён статическими строками, динамически mnemonic не проверена.
CONTROLS.json — артефакт исходного исследования (`CONTROLS.json`; вне снимка), run `e90010c1a91e738c`.

## Пилот, стоимость и рекомендация

Принятых новых поисковых схем0, pilot blocks0, реальных проверенных seed0,
GPU запусков0. Seed/s, отдельная PBKDF2/HD стоимость и прогноз полного домена
**не измерялись**; в JSON они null. Время синтетических контролей не является
пилотом и не экстраполируется. Прежние156,24 минуты E15 сюда не перенесены.

Рекомендация: не запускать BIP39-поиск под именем исторического BX2.0.0.
Для продолжения нужно конкретное подтверждение до2015 года композиции с другим
BIP39-инструментом либо отдельный протокол для найденного old-codec пути,
сначала с проверкой релизного декодера. Автоматического перехода на bitcoinj,
passphrase, новый порядок или новую маску не было.

Полный перебор не поручен отдельно и не начинался. Старые ядра/checkpoints не
менялись. Результат не исключает все BX/BIP39/кошельки и не устанавливает ПО автора.
Новых ключей или битов Puzzle нет. Решение — артефакт исходного исследования (`PILOT_DECISION.json`; вне снимка),
финальный read-only аудит — артефакт исходного исследования (`AUDIT_COMPLETE.json`; вне снимка).

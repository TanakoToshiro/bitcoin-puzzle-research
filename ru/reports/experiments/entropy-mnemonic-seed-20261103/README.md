Первичная сборка в новой копии без готовых результатов выполняется через
`bash build_controls.sh`, затем `python3 run_controls.py` в WSL. Исходную
принятую папку ради воспроизведения не пересобирать.

Если CONTROLS.json уже существует, `run_controls.py` сверяет input/result hashes
и не повторяет расчёт. При другом коде/бинарниках отклоняет переиспользование
готовых результатов: для новых inputs нужна новая серия/run ID. Run ID этой
версии содержит разделители путей платформы; Windows-запуск resume отклоняется,
поэтому его выполняют в исходной WSL-среде. `readback.py` работает и в Windows.
Существующие
принятые outputs не удалять ради повторного запуска. `readback.py` только читает
артефакты и печатает итог.

Это синтетические контроли, **не CPU-пилот поиска**. GPU-run, domain coverage,
training/holdout candidate checks и оценка 2³² здесь отсутствуют намеренно:
цепочка BIP39 не установлена. Следующий шаг требует нового исторического
основания, например точного импорта entropy в другой инструмент, либо отдельной
постановки old-codec варианта; эти направления автоматически не запущены.

# SEQ-25: уточнение причины и план сравнения

Булева замена на пилоте дала unknown/timeout за 60 с при выборочном пике 305 МиБ (счётчики ОС high-water около 311 МиБ). Но это составное изменение: наличие свободных Boolean заставляет ff-simplify пропустить устранение промежуточных полевых переменных. Более того, elim-term-ite снова вводит определения для 17225 ITE. Поэтому результат нельзя приписывать только «одному биту вместо 256».

Перед выбором основного варианта отдельно проверяется full00 с исходной формулой и параметром ff.preprocess=false. Это сохраняет промежуточные состояния/квадраты, избегая их разворачивания в большие полиномы; не удаляет уравнения. Все остальные параметры совпадают с пилотом B, лимит 60 с/2 GiB. Если этот вариант также уменьшает память, он будет включён как дополнительная точная оптимизация. Выбор режима для длинного запуска фиксируется после пилота.

Проверка малых задач: 20 запусков уже дали правильные SAT/UNSAT. Первые четыре малых запуска частично пересеклись по времени с окончанием пилота B; они используются только для проверки правильности, не для сравнения скорости. В итоговом упаковщике результата обнаружено повторение ключа mode (TypeError после закрытой подстановки); исправление находится в новом validate_completion.py, сохранённые прогоны не меняются. Полноразмерное парное сравнение будет строго последовательным.

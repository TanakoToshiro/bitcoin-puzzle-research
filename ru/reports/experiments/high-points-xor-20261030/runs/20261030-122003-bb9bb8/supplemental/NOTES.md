# E6H — интерпретации и ошибки

## 2026-10-30 — область исследования

По уточнению пользователя полезен результат для любой нерешённой puzzle, в том числе с раскрытым публичным ключом. Известные приватные решения используются как эталоны. Название общей папки puzzle71-hypotheses оставлено для сохранения путей; научная цель больше не ограничена №71.

## 2026-10-30 — первая проверка запуска

Run `20261030-121919-311766`: контроли игрушечной группы и независимые secp256k1-контроли прошли. Чтение catalog.csv остановилось с KeyError: puzzle: CSV E5 имеет UTF-8 BOM. Исправлено только чтение на utf-8-sig. Старый запуск, код и traceback сохранены как ошибочный; научного результата по реальным точкам/совместному поиску в нём нет. Изменение исходника требует нового ID. Это ошибка загрузчика, не противоречие данным или математической гипотезе.

## 2026-10-30 — успешный запуск 20261030-122003-bb9bb8

Все 13 стадий завершены. Построены 254 условные исходные точки №250–256, 64 ветви №254–256; совпали coincurve и независимый эталон. 96 контролей маскирования и 16 контролей XOR-перехода прошли. Реальные публичные цепочки только сформулированы как ограничения: неизвестный 256-битный chaincode не искался.

В 30 уменьшенных задачах совпали полные множества решений совместного MITM и одного DLP с последующим отбором. На 12/16 битах проверен ещё и полный независимый перебор. По одному переходу в каждой из десяти цепочек осталось два C, по двум — единственное решение в 9/10, по трём — в 10/10. Это в значительной мере свойство выбранного q около половины диапазона w-битного множителя: на secp256k1 частоты неоднозначности другие.

Дополнительные уравнения отсекают ложные C, но текущий MITM всё равно перебирает две половины по 2^(w/2) назначений, увеличивая число точек в записи и арифметическую работу. Сравнение не обнаружило преимущества перед обычным DLP. Для 256 бит оценка этого алгоритма остаётся порядка 2^128 назначений половины. Это структурное ограничение испытанного метода, не доказательство невозможности всех атак на связанные XOR-множители.

Успешный научный прогон занял 3,824 с; меньшая длительность связана с конечными маленькими моделями и не является пропуском запланированных стадий. Увеличивать размеры ради заполнения 1200-секундного бюджета не требуется. Числовые таблицы и итог формирует finalize.py из сохранённых JSON. Моментальные времена имеют шум; точные счётчики групповых операций и назначений половин дают более надёжную картину роста. Пик RAM не измерялся, учитываются записи и число точек в таблице.

Проверены остановка после трёх стадий, продолжение оставшихся десяти, повторный resume с нулём вычислений и пересборка отчёта без изменения хешей/mtime стадий. Три повреждения на изолированных копиях отвергнуты; нулевой бюджет не запускает оставшиеся стадии. Старые исследования и рабочие проекты не изменялись.

Изменение цели на любую нерешённую puzzle учтено: путь именно к №71 больше не обязателен. Однако C и исходные публичные точки не дают числовые приватные ключи автоматически. Для продолжения нужны новый алгоритм связанных уравнений, обоснованное ограничение энтропии C или иной приватный/публичный якорь с доказанной связью с исходной цепочкой. Нового бита или ключа реальной задачи не найдено.

# SEQ-03 — скрытая аффинная цепочка modulo n

Постановка 02.11.2026, до вычисления результатов настоящей последовательности.
Пользователь разрешил начать восстановление скрытого состояния и связей.
Это отдельная конечная серия; SEQ-01/02, GPU и общая среда не изменяются.
Локальный предел вычислений этой серии: 15 минут CPU/wall вычислительных
подпроцессов, без расширения гипотез ради использования остатка времени.

## Гипотеза и данные

`s[i+1] = (a*s[i] + c) mod n`, `0 <= s[i], c < n`.
`n = FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141`.
Наблюдаем только `r[i] = s[i] mod 2^(i-1)` из полного puzzle key,
обязательный старший бит исключаем. Это гипотеза о происхождении,
не установленный способ создания Puzzle. Нулевое скрытое состояние
допускается: модель шире генератора допустимых Bitcoin private keys.

Один шаг на номер, прямой порядок, постоянные a,c, никаких перестановок,
неизвестных пропусков или смен параметров. Копия 83 решений SEQ-02;
пропущенные номера сохраняются. Все данные ранее изучались.

Главный вычислимый класс: **все целые -2^32 <= a <= 2^32**,
с любой 256-битной c и любым s[1]. Отрицательные a — представители
множителей n-u. Это 8589934593 представителей, не все множители modulo n.
Подбор/восстановление использует наблюдения до №70; №75..135 —
дополнительная проверка, не новый закрытый тест.

## A. Необходимое условие, не требующее знания старших битов

Вводим q[i]=floor((a*s[i]+c)/n). При a>=0: 0<=q[i]<=a;
при a<0: a<=q[i]<=0. Поэтому |q[i]-q[i+1]|<=|a|.

Для тройки j,j+1,j+2, M=2^(j-1), d1=(r[j+1]-r[j]) mod M,
d2=(r[j+2]-r[j+1]) mod M:

`h = (d2-a*d1)*inverse(n,M) mod M`,
где существует целое представление h с `|h|<=|a|`.

Сначала расслабляем границу до B=2^32 и точно считаем/перечисляем a
в [-B,B] для тройки №68,69,70 (M=2^67). Это задача подсчёта попаданий
модульной линейной функции в два интервала. Используются целочисленные
евклидовы floor sums и деление диапазона, а не 8.6 млрд итераций.
Если число >4096, статус `candidate_budget`, не отрицательный вывод.
При <=4096 перечисляем все, затем проверяем точные |h|<=|a|
для всех доступных последовательных троек до70. Пустое множество
есть точное противоречие всему ограниченному классу независимо от c,s[1].
Непустое множество — только необходимые условия, не найденный генератор.

## B. Восстановление полного состояния при найденном a

Для каждого допустимого a вычисляем известные коэффициенты
`s[i]=(A[i]*s[1]+C[i]*c) mod n`.
По 12 наблюдениям №59..70 строим взвешенную решётку с ДВУМЯ
неизвестными s[1],c. Используем LLL и точный рациональный Babai.
Предложенный кандидат принимается лишь при проверке всех наблюдений
№1..70; дополнительно прогнозируются №75,80,...,135 без истинных состояний.
Метод приближённого CVP не полный: неудача Babai не доказывает
отсутствие состояния. При слишком многих a не делаем произвольный выбор.
Синтетические наблюдения содержат только остатки; истина не передаётся
восстановителю. Восстановление s[1],c сравнивается с истиной после расчёта.

До реального анализа: четыре полноразмерных положительных цепочки
с a=1664525, -1664525, 2147483647, -4294967296 и независимыми SHAKE
256-битными c,s[1]; те же 83 индекса/маски. Отдельно проверяем a=0,1,-1
и случаи неоднозначности как границы, не требуем уникального recovery.
Сильные контрольные параметры не являются утверждением о реальном RNG.

## C. Полностью неизвестный 256-битный множитель

Отдельный пилот точного нелинейного SMT: a,c,s[1] произвольны modulo n,
промежуточные состояния ограничены [0,n). Проверяем полный состав
наблюдений, без объявления test. На малых модулях результаты сверяются
с исчерпывающим перебором; маски масштабируются как floor((i-1)*w/256).
На настоящей разрядности сначала ОДНА положительная синтетическая
цепочка с полным a и тайм-аутом20 секунд. Только если восстановитель
действительно получает согласованный результат, допускается реальный
пилот с тем же лимитом. `unknown`/тайм-аут — ограничение алгоритма;
не отрицание модели и не доказательство неидентифицируемости.

## Проверки и критерии вывода

- floor sums/подсчёт/перечисление против прямого перебора на малых данных;
- q-границы и необходимое условие для положительных/отрицательных a;
- независимая рекурсивная формула floor sum для сертификата реального счёта;
- положительные полноразмерные recovery и испорченные наблюдения;
- точное равенство U*B=B_reduced и det(U)=+-1; проверка прогнозов;
- небольшие случайные последовательности как отрицательные контроли.

При точном пустом пространстве не проводится поиск лучшей приблизительной
формулы и не требуется Monte Carlo p для этого логического противоречия.
Положительное совпадение само по себе не доказывает историческую модель;
тогда потребуется отдельный аудит и сопоставление альтернатив.

Прежние seals проверяются чтением/хешированием до и после. Новые код,
протокол, входы, параметры и результаты имеют SHA-256. Завершённые стадии
при повторе не вычисляются. Ошибки и тайм-ауты сохраняются в журнале.
Не изменять принятые старые отчёты или научные JSON.

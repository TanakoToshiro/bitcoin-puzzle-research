# E12 GPU: исторический SX

Изолированное продолжение ../sx-historical-20261101/GPU_HANDOFF.md.
Полная постановка: PROTOCOL.md; результаты: RESULTS.md; последовательные выводы: JOURNAL.md.
Старые SX/BX checkpoints и манифесты не изменяются. SOURCE_PINS.json фиксирует источники.

WSL Ubuntu-24.04, из этой папки:

> Исполняемый код/команды опущены в документационной копии.


`all` переиспользует завершённую приёмку и пилоты с теми же входами, затем выполняет
GNU и LLVM последовательно. `SERIES.lock` — flock на всё время процесса; PROCESS.json
сохраняет PID и /proc start ticks. Существование файла lock само по себе не означает
работающий процесс. Повторный запуск проверяет цепочки блоков и продолжает с первого
отсутствующего блока. Для контролируемой остановки создать файл STOP в этой папке;
для продолжения убрать его и повторить `python3 run.py all`. Завершённые блоки неизменны.
Кандидат или ERROR требует разбора причины; автоматического пропуска нет.

GPU filter №50 не доказывает модель: CPU verifier проверяет №1–50, затем holdout;
реальный кандидат останавливает серию до независимой affine/адресной проверки.
FULL COMPLETE появляется только после независимого audit.py. Аудиты сохраняются
новыми файлами, старые контрольные артефакты не перезаписываются.

`setup.py` сохраняется как журнал исходного переноса; не запускать поверх серии.
Для воспроизведения сборки используются текущие pinned исходники и build.sh.

## Возобновление после файловой гонки

Первый полный запуск остановился после 96 блоков на Windows/WSL sharing violation
при атомарной замене STATUS. GPU-ошибок не было. Исходный runner и FINAL_MANIFEST
сохранены неизменными; версия обвязки resume.py отдельно закреплена RESUME_MANIFEST.json.
Она повторяет только занятую файловую операцию и не перезаписывает принятый PILOTS.
После этой поправки актуальная команда продолжения: `python3 resume.py`;
для запуска с отдельными stdout/stderr: `python3 launch_v2.py`.
Разбор и контроль с тремя искусственными отказами: status-reviews/resume-review.json.
Завершённые 96 блоков сохранены побайтно, список SHA256 включён в разбор.
Оригинальные stderr.log и LAUNCH_RESULT.json сохраняют первую ошибку; итоговое
исполнение отражено в stderr-v2.log и LAUNCH_RESULT_v2.json.
Независимая проверка Windows после завершения: `python readback.py`.

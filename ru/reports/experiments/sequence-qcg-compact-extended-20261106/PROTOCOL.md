# SEQ-26 — повтор шести совместных QCG-задач с десятиминутным бюджетом

Запрос: повторить шесть полноразмерных сохранённых задач с ff.preprocess=false и ресурсами SEQ-24. Выполняются full00..full05: четыре положительные QCG-цепочки и два случайных контроля. Реальные ключи не запускаются.

Единственное изменение стратегии относительно SEQ-24 — solver.set("ff.preprocess", False), выбранное и проверенное в SEQ-25. Построитель encoding_seq23.py, входы, модуль и математические тела SMT сохраняются. Сохраняются 83 позиции наблюдений, 82 информативные маски, 3767 известных битов, все 135 состояний, 134 равенства z=s², 134 перехода, a≠0, точные бинарные верхние границы и gauge. Никакие истинные состояния не поступают рабочим процессам.

Ресурсы совпадают с SEQ-24: timeout 600000 мс на check, max_memory=8192 МиБ; внешний лимит 660 с и 8 GiB по максимуму working/private, один процесс за раз. Опрос памяти каждые 0.25 с, трасса каждые 5 с, progress каждые 30 с. Перед стартом требуется 10 GiB свободной физической и commit-памяти, ожидание до 120 с; аварийный останов при остатке менее 2 GiB. Внешнее превышение приводит к остановке процесса и не считается UNSAT. Небольшое превышение из-за дискретного опроса фиксируется как фактический пик.

Каждый процесс строит исходную FF-модель, проверяет побайтовое равенство тела SMT с сохранённым запросом SEQ-24 и записывает математический запрос и SOLVER_OPTIONS.json с параметрами Python API; повтор выполняется replay.py. Временные строки сериализации освобождаются до check; это точная экономия Python-памяти, не изменение формулы. Записываются память после построения/сериализации/решения, выборочный пик и high-water ОС, ответ, причина unknown и статистики Z3. Рабочий процесс запускается через base executable, чтобы измерять сам решатель, а не venv-перенаправитель.

Малые 30/30 проверки и восемь закрытых подстановок SEQ-25 переиспользуются по хешам: новых математических преобразований нет. Проверяется разбор математического SMT и применение параметров через Python API на малом примере. Глобальные SMT-директивы max_memory/smt.ff.preprocess отклонены при предварительной проверке; исходники неудачного экспортного варианта сохранены в preflight_failed, рабочие задачи с ним не запускались. Любой найденный кандидат проверяется независимой целочисленной арифметикой, включая все исходные маски и каждый переход. UNSAT на положительном контроле — ошибка; остальные UNSAT не получают независимой сертификации без отдельного доказательства.

По окончании сравниваются сохранённые исходы SEQ-24 и SEQ-25 с текущими. Таймауты/память остаются открытыми вычислительными случаями, даже если организационный объём серии завершён. Данные уже изучались: это повтор, не новая независимая выборка.

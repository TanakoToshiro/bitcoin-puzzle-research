# SEQ-15 — независимый cuso на сохранённых задачах

До научных запусков фиксируются 16 входов: вся панель SEQ-11 (12),
SEQ-09 p13 h24 обе семьи (2), SEQ-12 p6 h20 обе семьи (2).
Каждый запускается в двух режимах: OptimalShiftPolys и GraphShiftPolys
поверх OptimalShiftPolys. Это 32 зарегистрированные попытки.

Вход — сохранённые исходные модульные кубики разностей, а не полученные
прежним LLL целочисленные сертификаты. Экспорт сверяется с сохранённой
системой и её повторным построением. Truth не передаётся cuso.
В API cuso границы строгие: включительный интервал [a,b] экспортируется
как (a-1,b+1). Набор допустимых целых значений сохранён.

Сравнение сквозное: cuso сам выбирает сдвиги, порядок мономов,
масштабирование, использует flatter и свой алгебраический решатель.
Это не изолированное сравнение одного правила сдвигов при одинаковом LLL.
SEQ-10 не участвует в решении. Старый декодер применяется только после
получения корней cuso, для проверки всей цепи и масок.

Лимиты одинаковы: 180 секунд на попытку после запуска процесса,
8 GiB адресного пространства, максимум 256 строк или столбцов построенной
решётки. Два процесса, по одному потоку native-библиотек. Превышение
лимита — незавершённая проверка, не отрицательный результат. Сохраняются
входы, логи, решётки до/после редукции и полученные целые отношения.
Убийство по времени охватывает всю группу процессов, включая flatter/msolve.

Авторские контрольные примеры и проверки строгих границ должны пройти
перед выборкой. Проверяется каждый возвращённый корень: точные кубики,
границы, невырожденный переход без полюсов, 135 состояний и 83 маски.
Пустой список или невозможность найти корень не исключает гипотезу.
Этот этап синтетический; реальный поиск ключа не запускается.

До научных запусков авторский многомерный контроль выявил удалённый
в Sage 10.9 псевдоним MPolynomial.is_generator. Отдельный sage_compat.py
заменяет единственный вызов проверки типа аргумента на is_gen в памяти.
Это прежний и новый имена одного предиката (Sage issue 38942).
Исходники cuso остаются чистыми; алгоритмы сдвигов/редукции/решения не меняются.
Предварительная ошибка и прежний манифест сохранены в setup_logs.

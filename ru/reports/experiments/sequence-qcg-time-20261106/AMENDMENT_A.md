# Диагностическая сборка в WSL

До любых полноразмерных измерений выяснилось: имеющийся Windows MSVC содержит cl.exe, но не стандартные заголовки/библиотеки C++. Ошибки подготовки среды и CMake сохранены; решатели при этом не запускались. Глобальная установка Visual Studio не изменяется.

Диагностический контроль и таймерная сборка выполняются в уже доступной Ubuntu-24.04 WSL (GCC 13.3, CMake 3.28). Исходник тот же. Для соответствия отсутствующему в MSVC __uint128 F4-ветвь принудительно компилируется с Z3_FF_HAS_UINT128=0. Это характеристика диагностической сборки, не изменение формул. Проценты/времена Linux нельзя прямо приписывать установленной Windows DLL: платформенные различия будут явно отделены. Окончательное сравнение ускоряющих параметров выполняется на неизменённой установленной Windows DLL.

Временные объектные файлы компиляции находятся в /tmp/seq27-430d19e-20261106; исходный архив, патч, команды, логи и конечные библиотеки сохраняются в новой серии. Исходники прежних серий не меняются. До профилирования сборки проходят малые эталоны; построение библиотек и измеряемый поиск не выполняются одновременно.

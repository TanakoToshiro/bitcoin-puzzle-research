# SEQ-04 — большой неизвестный множитель через полиномиальные связи

[Итог](<FINAL_REPORT.md>), [протокол](<PROTOCOL.md>), [журнал](<JOURNAL.md>).

Новый решёточный метод: переменные младшие маски → приближённые
геометрические разности → короткие полиномы → gcd → кандидат a.

совместимых результатов на нулевых данных. На настоящих решениях
кандидата нет; это не точное исключение произвольного множителя.

Завершённые stages пропускаются. Для полного пересчёта или изменения
кода использовать отдельную копию с отдельными результатами. `setup`
и `audit` записывают файлы; поверх принятого seal их не запускать.
Достаточно `verify.py`, который только читает.

`relations.py` реализует новый метод. `recovery.py` — неизменённая
копия helper SEQ-03; SHA и источник в `HELPER_SOURCE.json`.
Старый driver не исполняется. В JSON `state`/`increment` — исходное
предложение Babai, которое может не подходить. Принятые состояния
задаются `state_families`/`all_families`; флаг `accepted` относится
к непустому множеству, а не к исходному представителю.

`controls/` и `replication/` содержат наблюдения, синтетическую истину,
все матрицы/полиномы, предложения и множества состояний. `null/` —
64 случайные последовательности (воспроизводятся по домену в коде).
`degenerate/` — четыре случая границ метода. `REAL.json` — однократный
реальный пилот. Никаких настоящих неизвестных ключей там не получено.

`MANIFEST.json` фиксирует код/протокол/входы до реального расчёта;
`ARTIFACTS.json` — окончательный seal. Журнал исключён из immutable.
`ACCEPTANCE.json` и `RESUME_CHECK.json` содержат проверку повтора.

Python3.11 из существующей `.venv`; SymPy/FLINT из сохранённого
`child-derivation-audit-20261102/vendor`. Запись bytecode отключена,
библиотеки не устанавливались, GPU не использовался.

# E7 — оценка предложений, промежуточные выводы и продолжение

## 2026-10-30 — оценка до запуска

Из четырёх предложений новый короткий цикл оправдан для обращения инициализации MT и поиска MPK Electrum среди уже известных точек. Извлечение nonce и сравнение с RFC6979 повторяет существенную часть E5; повтор не выполнялся. Маскирование внутри Armory — отдельная спекулятивная модель, для неё назначен ограниченный точный запрос с контрольными примерами.

Источники проверены непосредственно: [Stackered, 22.04.2024](https://stackered.com/blog/python-random-prediction/), [опубликованный код](https://github.com/StackeredSAS/python-random-playground), [Electrum 1.9.8 OldAccount](https://raw.githubusercontent.com/spesmilo/electrum/1.9.8/lib/account.py), [Hash из bitcoin.py](https://raw.githubusercontent.com/spesmilo/electrum/1.9.8/lib/bitcoin.py). Снимки с URL, UTC и SHA-256 — sources/SOURCES.json; исторические CPython — архивы E2 с проверенными хешами.

## 2026-10-30 — MT: положительный контроль, затем предел применимости

Run `20261030-124911-1a7e70`. На CPython 2.7.9 и 3.4.2 состояния/выходы всех девяти фиксированных seed длиной 64/96/128 бит совпали с независимой реализацией. Полные 8/10/12 специальных выходных слов дали кандидатов seed, проверка прочих выходов оставила правильный seed во всех девяти случаях. Четыре разных положения локального окна тоже восстановили правильный seed. Это подтверждает перенос метода на исторические версии и корректность индексации, но не его применимость к частично наблюдаемым puzzle-данным.

Просканированы 29 664 локальные проекции: восемь схем E1, два набора наблюдений и окна 4/5/6 слов, все допустимые начала. Дополнительно введён известный бит I[0]=0x80000000. При использовании только №1–50 каждое такое окно полностью свободно: 128/160/192 координаты. При всех 83 решениях лучшие размеры — 68/100/132 для seed64/96/128. Канонические окна I[228...] остались полностью свободными. 48 сертификатов лучших проекций содержат конкретные состояния и независимые направления; они проверены по наблюдениям и отдельно по целевым координатам.

Для девяти синтетических seed во всех восьми упаковках проверено точное воспроизведение наблюдений с теми же масками и пропусками: 72 случая. Ранг проекции одинаков для всех совместных правых частей, поэтому эти контроли имеют тот же предел прямого дополнения. Полного восстановления seed из замаскированных синтетических данных не заявляется: прямой перебор дополнений не запускался, потому что минимум 68 превышает заранее заданный предел 20.

Вывод ограничен стратегией «линейная проекция → перечислить недостающие координаты окна → обратить init_by_array». Число дополнений здесь больше числа seed соответствующей ширины; стоимость одной попытки различается, поэтому это сравнение числа комбинаций, не универсальная оценка времени. Ограничения образа короткого seeding нелинейны и в этот размер не включены. Другие совместные алгоритмы seeding остаются открыты; новые seed64/96/128 не исключены.

В общей папке также имеется завершённый E1b (mt-state-api-20261030): дополнительные API/истории дают неопределённость произвольного состояния. Настоящий E7 использует именно восемь матриц E1; результаты проекций E7 не переносятся автоматически на модели E1b. Их прежние расчёты не повторялись.

## 2026-10-30 — Electrum: отрицательный поиск MPK и положительное условное следствие

42 исторических get_sequence-вектора совпали с новой реализацией. Деривация и маскирование проверены на 12 синтетических мастер-ключах/отображениях по семи индексам: 84 случая, с совпадением публичного, приватного и аффинного путей. Реальный пул: 254 точки E5 + 254 кандидата E6H, после удаления семи совпадений — 501. Проверены обе ветки и index=stride*(puzzle−1)+offset для stride=1/2, offset=0/1/2: 6012 кандидат–отображение проверок. Ни один не прошёл даже фильтр №256; до проверок №255/254 реальные кандидаты не дошли. Это не исключение Electrum и не доказательство отсутствия MPK в иных источниках.

Дополнительный контроль после основного прогона подтвердил содержательную часть предложения: при настоящем MPK одно известное маскированное решение более высокого номера позволяет вычислить три кандидата для меньшего номера. В 24 синтетических случаях (№71 и №100, известный №135, все 12 отображений) каждый раз получилось три кандидата, HASH160 оставил правильный. Предиктор получает только MPK и d_135, не мастер-приватный s; s используется снаружи для проверки. Артефакт: electrum-conditional-prediction.json.

Точное обоснование: пусть известны публичные добавки a_j,a_i, приведённые по n, и j>=i. Имеем K_j=s+a_j−t_j*n, K_i=s+a_i−t_i*n, t_j,t_i∈{0,1}. Тогда K_i = K_j+(a_i−a_j)+(t_j−t_i)*n, где разность переносов равна −1,0,1. Из d_j известен K_j mod 2^(i−1), поэтому:

```
b = (d_j + a_i − a_j) mod 2^(i−1)
d_i ∈ { 2^(i−1) + ((b + u*n) mod 2^(i−1)) : u∈{−1,0,1} }
```

Для j=i следует использовать r_j=d_j mod 2^(j−1), что даёт ту же формулу по модулю; практически интересен j>i. Это не раскрытие s и не результат на настоящих puzzle. Требуются настоящий MPK, правильная деривация/индексы и гипотеза маскирования. Главный отсутствующий параметр сейчас — подтверждённый MPK. Поэтому архивный поиск именно этого публичного параметра имеет ясный критерий полезности.

## 2026-10-30 — feedback Armory: результат ограничен тайм-аутом

Построена точная модель с известными d_i во входе переходов и постоянным 256-битным C. XOR выражен линейной суммой бинарных переменных, редукция по порядку secp256k1 сохранена через целочисленные частные/остатки. Это иной объект, чем E6H, где исходные скаляры неизвестны.

Маленький контроль (C8, порядок 251, семь ключей) восстановил единственное C=173; при изменённом последнем бите система стала несовместной. Полные множества совпали с исчерпывающим перебором 256 вариантов. Реальная система по 49 переходам №1–50 остановилась с unknown/timeout за 30,239 с при лимите 30 000 мс. Сохранены feedback.smt2, версия Z3, статистика и все входные коэффициенты через известные ключи. Это не доказательство несовместности. Образец C не получен, проверка единственности/отложенных №51–70 не запускалась за отсутствием модели.

Продолжение возможно с другой точной кодировкой, разбиением по частным или другим решателем. Простое увеличение времени — новый запуск с отдельным бюджетом; нельзя заменять результат timeout словом «опровергнуто». Большая система не масштабировалась вслепую.

## Будущие эксперименты

1. Искать подтверждённый Electrum MPK/публичный descriptor в конкретных исторических источниках, с происхождением и проверкой по верхним точкам. Не расширять произвольно пул случайных точек.
2. Для feedback Armory — исследовать более сильные ограничения/кодировку и сравнить решатели на увеличивающихся синтетических случаях перед новым реальным запросом.
3. Для MT — совместные ограничения инициализации и наблюдений без полного перечисления окон; сначала продемонстрировать восстановление seed на синтетических данных с теми же масками. Перенос аудита на E1b требует отдельной постановки с неизвестной историей отказов.
4. Новые дефекты nonce — только с точной моделью и происхождением подписей; уже выполненный E5 не повторять.

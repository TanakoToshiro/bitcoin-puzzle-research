# E7 — применимость обращения MT, публичный параметр Electrum, feedback Armory

2026-10-30. Протокол до расчётов. Цель — любая нерешённая puzzle. CPU, без GPU/облака; суммарный предел новых вычислений 1200 секунд, без подготовки кода/загрузок. Сохранённые результаты повторно не вычислять. При изменении кода новый ID; ошибки и тайм-ауты сохранять.

## Оценка присланных идей

1. Обращение init_by_array — новая по отношению к E1/E2b проверка; опубликованный метод требует определённых полных слов. Проверяется его применимость, не обещается восстановление из произвольных частичных ключей.
2. Nonce из известных приватных ключей и RFC6979 уже проверены в E5: 324 подписи, 218 извлечений/сопоставлений nonce, 15/15 совпадений в выбранном пакете 2019 года. Повторять этот пункт не нужно. Иные строго определённые дефекты требуют отдельного протокола, авторство подписантов не угадывается.
3. Кандидат на старый Electrum MPK — новый, дешёвый и конечный тест. Предпосылка о наличии MPK среди наблюдаемых точек не подтверждена.
4. Маскирование внутри цепочки — спекулятивная, но отличная от E3/E6H модель. Проверяется один точный вариант classic Armory с постоянным неизвестным 256-битным C, а не набор произвольных хешей.

## A: MT init_by_array

Первоисточник: Stackered, Florian Picca, 22.04.2024; functions.py и recover_64bitSeed.py сохраняются с URL/UTC/SHA-256 и лицензией. Сверить на реально исполняемых CPython 2.7.9/3.4.2 из E2 и независимом reference_mt. Для 64/96/128 бит — по три фиксированных SHA-256-derived seed с установленным верхним битом. Сохранить состояния до twist и первые 2160 uint32. Восстановить seed из полных локальных окон I и из 8/10/12 специальных выходных слов; проверять кандидатов по независимым остальным выходам. Полные скрытые слова — положительный контроль, не доступные данные puzzle.

Взять неизменённые сертифицированные матрицы E1 для восьми упаковок/шага. Подтвердить SHA-256 по DONE.json. Добавить точное ограничение Python I[0]=0x80000000 (в координатах E1 это один бит; низшие 31 бит I0 не влияют на поток). Рассмотреть отдельно наблюдения №1–50 и все 83 решения.

Для L=2,3,4 слов seed необходимы L+2 полных последовательных слова I: формула восстановления K использует тройки, индексы восстановления 4..623. Просканировать все начала a=2..624−(L+2), включая каноническое a=228. Размер проекции: rank([A;T])−rank(A), не сумма неизвестных битов по отдельности. Сохранить все размеры, фиксированные биты и лучшую проекцию со свидетельствами и входной матрицей. Независимо сверить минимум добавлением целевых строк к исходной системе. Дополнительно измерить проекцию специальных выходов Stackered на канонических позициях.

На синтетических seed с теми же упаковками, масками и пропусками проверить наблюдения/истинное состояние и размер пространства проекции. Если минимум свободных координат <=20, перечислить допустимые дополнения локального участка, обратить seed и проверить по остальным наблюдениям в пределах бюджета. Если больше 20, явно записать остановку этого способа без перебора. Размер проекции — до нелинейного ограничения длины seed; он не является нижней границей сложности любых seeded-атак.

## B: Electrum 1.9.8 OldAccount

Сохранить account.py и bitcoin.py. Точно H=doubleSHA256(ASCII('%d:%d:'%(index,branch)) || X_BE32 || Y_BE32); MPK — 64 байта без 04. Публичная деривация P_child=P_master+(H mod n)G. Исполнить исторические AST-функции get_sequence/Hash/sha256 в CPython 2.7.9; сопоставить с текущей реализацией и независимыми приватными/аффинными путями.

Фиксированный пул кандидатов: все 254 уникальные точки E5 и 254 условные исходные точки №250–256 из E6H, объединить по compressed SEC. Фиксированные отображения: index=stride*(puzzle−1)+offset, stride∈{1,2}, offset∈{0,1,2}, branch∈{0,1}. Проверять №256,255,254 против полных наборов E6H, сначала №256 как ранний фильтр. Не подбирать параметры после результата. Для совпадения всех трёх — проверка №250–253 и известных младших остатков, затем отдельная проверка любого предсказанного кандидата по адресу. Отрицательный результат исключает лишь данный пул/12 отображений.

Контроли: синтетические известные MPK, все 12 отображений; правильная деривация должна попадать в наборы после маскирования. Известные s позволяют проверить формулу двух остатков s mod 2^(i−1) с учётом переноса по n. Наличие настоящего MPK не обещает полного s; проверка целевого публичного ключа/адреса обязательна.

## C: feedback classic Armory

Модель: d_(i+1)=2^i + (((d_i*(C XOR H(uncompressed(d_i G)))) mod n) mod 2^i). Постоянный C, последовательные puzzle без пропусков/переиндексации. Подбор по №1–50, проверка найденного C на №51–70. Это модифицированный пользовательский алгоритм, не штатная схема Armory.

Точная линейная целочисленная кодировка: C XOR H = H + sum c_j*(1−2h_j)2^j, c_j∈{0,1}. d_i*a_i = q_i*n + r_i + l_i*2^i, 0<=r_i+l_i*2^i<n, q_i>=0. Не заменять mod n на mod 2^256. Положительный/отрицательный маленький контроль (8 бит C, порядок 251, семь puzzle) сравнить с полным перебором 256 значений. Реальный запрос Z3 максимум 30 с; при sat проверить численно, отдельный запрос единственности максимум 30 с. unknown/timeout не опровержение. Включить SMT2 и статистику решателя в артефакты.

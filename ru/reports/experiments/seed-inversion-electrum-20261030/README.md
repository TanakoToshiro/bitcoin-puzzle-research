# E7 — обращение seed MT и проверки исторических кошельков

Изолированный CPU-эксперимент. [Протокол](<PROTOCOL.md>), [результаты запусков](<RESULTS.md>), [интерпретации](<NOTES.md>). Цель — любая нерешённая Bitcoin puzzle, включая задачи с раскрытой публичной точкой. Рабочие поисковые проекты не изменяются.

Проверены три разные идеи: доступность локальных окон для обращения init_by_array, конкретный пул возможных Electrum MPK, точная модель маскирования внутри classic Armory. Предложенный аудит nonce не повторяется: его основная часть выполнена в E5.

`prepare.py` скачивает только указанные первоисточники и сохраняет URL/UTC/SHA-256; они уже получены, повтор не нужен. `study.py` работает с сохранёнными данными. Исторические runtime запускаются в WSL Ubuntu-24.04 через проверяемые архивы E2; при очистке /tmp launcher восстанавливает их. Новый запуск сохраняет код и входы; resume проверяет хеши и не повторяет готовые стадии. Изменение кода/данных требует нового ID. Бюджет задаётся на вызов; матричные стадии проверяют его периодически, запрос feedback отдельно ограничен 30 секундами.

MT использует сертифицированные матрицы E1, добавляя точное ограничение Python I[0]. Все окна 4/5/6 слов проверены для восьми схем и двух наборов наблюдений. Сертификаты показывают размер пространства неизвестных локальных слов до нелинейных ограничений короткого seed. Невыгодность прямого дополнения не исключает другие алгоритмы seed recovery. Если встретится окно с <=20 свободными координатами, текущий код явно остановится для реализации и валидации перечисления; в завершённом запуске таких окон нет.

Исторические полные выходы MT — положительные контроли. Они не используются как скрытая подсказка при анализе реальных масок. Для Electrum исторические функции get_sequence/Hash/sha256 исполнены из AST в CPython 2.7.9, без загрузки полного кошелька. Криптографическая деривация сверена coincurve, известными синтетическими приватными ключами и аффинной арифметикой.

`postchecks.py ID` проверяет сертификаты проекций другим выбором опорных битов, stop/resume и повреждения на изолированной копии. Дополнительный синтетический контроль показывает, как известный MPK и одно решение №135 дают до четырёх кандидатов для меньшего индекса без передачи мастер-приватного ключа предиктору. Это не результат для настоящих puzzle. `finalize.py ID` формирует итоговые таблицы только из сохранённых JSON.

Файлы источников сохраняют исходные лицензии/уведомления. Stackered functions.py используется как опубликованный эталон обращения; локальный код сканирования проекций написан отдельно. Старые эксперименты, источники E1/E2/E5/E6H и их checkpoints не изменяются.

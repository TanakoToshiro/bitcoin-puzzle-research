# E4 — поиск рядом с ключами, совпавшими по префиксу HASH160

**Пилот завершён: 0/12 значимых преимуществ соседей.** Проверены 1 048 576
центров, 256 508 новых соседей и столько же нового контроля для 32 целей.
Для редких 12-битных совпадений чувствительность ограничена; отсутствие всех
возможных локальных эффектов не доказано. Приёмка — артефакт исходного исследования (`runs/20261030-111717-d89c4fca/ACCEPTANCE.json`; вне снимка).

Проверяется преимущество **новых** соседей над равным числом **новых** равномерных
ключей после отбора центрального ключа по совпадению префикса. Диапазон скаляров
[2^70,2^71), сжатый secp256k1 pubkey, SHA256 → RIPEMD160. Цели синтетические;
поиск по адресу настоящей задачи №71 не производится.

32 цели × 32768 центров = 2^20 исследованных центров. Пороги 8/12 **битов**,
радиусы 16/4096/16777216, максимум 2^18 соседей и равный контроль. Необходимые
размеры каждой подгруппы и критерии зафиксированы до вычисления статистики.
Восемь следующих битов не используются при отборе центров. Семья из 12 тестов
исправляется Holm при alpha 0.01; перестановки и bootstrap делаются по целям
целиком. Нулевые/редкие события не превращаются в доказательство отсутствия эффекта.

## Запуск из этой папки в PowerShell

> Исполняемый код/команды опущены в документационной копии.


Python 3.11 и существующее исследовательское venv; используются coincurve, NumPy
и SciPy. Фактические версии и хеш кода находятся в config.json каждого запуска.
Только локальный CPU; BLAS/OpenMP ограничены двумя потоками. Бюджет проверяется
между стадиями; после остановки текущая незаконченная стадия может быть повторена,
законченные с правильным хешем пропускаются. Не запускать два resume одного ID
одновременно. Изменение кода/протокола требует нового запуска.

## Артефакты и границы

`target-vault.json` содержит публичные синтетические тестовые приватные ключи
и seed целей. Алгоритм кандидатов получает только `targets.json` (HASH160),
отдельный seed кандидатов и результаты центров; содержимое vault использует
лишь аудит. Все ключи предназначены исключительно для проверки, не для хранения средств.

`centers-XX.npz`: скаляры как 9 байт big-endian (`uint8`, N×9), HASH160 как
20 байт. `neighbors-XX.npz`: те же данные плюс плечо (0 — соседи, 1 — контроль),
номер ячейки p/R, номер выбранного центра (-1 для контроля) и таблица счётчиков.
Порядок ячеек: p=8/12, внутри каждого R=16/4096/16777216. Столбцы `counts`:
число пар, префикс соседей/контроля, next8 соседей/контроля, совместное p+8
соседей/контроля, полный HASH160 соседей/контроля. Все массивы загружаются с
`allow_pickle=False`. Выбранные центры и изначальные числа совпадений — в JSON.

Стадия `audit` независимо проверяет непересечение всех скаляров, диапазоны,
расстояния до выбранных центров, равенство размеров плеч и счётчики по сохранённым
хешам. 128 центров проверены независимой аффинной Python-арифметикой. Успехи
синтетических контролей проверяют работоспособность метода, не доказывают
свойства secp256k1/HASH160. Границы интервалов и ориентира мощности описаны
в протоколе и отчёте. Ускорение полного поиска №71 из коротких префиксов не выводится.

Замороженные вычислительные входы и код — `runs/ID/code`, хеши — config/state;
ошибки при возникновении — errors.jsonl. После каждой стадии обновляется отчёт,
ручные интерпретации дописываются в NOTES.md. Рабочие проекты puzzle/puzzle-ubuntu,
эксперименты E1–E3 и отдельный GPU-поиск E2b этот код не изменяет.

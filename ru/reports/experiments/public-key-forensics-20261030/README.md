## Команды PowerShell из этой папки

> Исполняемый код/команды опущены в документационной копии.


Среда: исследовательский Python 3.11 / coincurve; фактические версии сохранены
в config.json. Сеть — исключительно GET к общедоступным источникам. Внешние
программы кошельков, подписывание настоящих переводов и отправка транзакций
не используются. Подписываются только синтетические сообщения контрольных
примеров с открытыми тестовыми ключами.

`cache/` — снимок ответов, имя по SHA-256 URL, `.body` с исходными байтами и
`.json` с URL/временем/хешем ответа. Ошибки — `errors.jsonl` и тела HTTP-ошибок.
Прочитанный ответ кэшируется навсегда в этом снимке. `run` **не обновляет** текущую
цепь автоматически. Для нового сетевого снимка нужен новый каталог/cache и
отдельный протокол/ID; не удаляйте старый кэш ради обновления. `resume` одного
ID нельзя запускать одновременно в двух процессах.

## Область и формат данных

Исходная транзакция имеет 256 P2PKH-выходов. Индекс puzzle сопоставляется
порядку и сумме выхода и проверяется по сохранённой таблице первых 160 адресов.
Пять ориентиров и их txid находятся в config.json. Все 83 опубликованных
полных приватных puzzle-ключа служат контрольными значениями, а не частями ключей.

Для №71 сравниваются оба Esplora-провайдера: адресная статистика, полная
подтверждённая история с пагинацией, UTXO; mempool сохраняется отдельно для каждого.
Для остальных адресов проверяются непосредственные расходы исходных выходов,
а не вся история каждого адреса. Входящие переводы на №71 проверяются по raw;
публичные точки их отправителей также проверяются на соответствие №71, включая
другую SEC-сериализацию, но не объявляются ключами получателя автоматически.

В `runs/ID/tx` сохранены raw hex и JSON; txid пересчитывается без witness,
сериализация и поля сверяются. В `signatures/` — отдельные проверенные входы:
точный prevout, публичный ключ, DER, r/s, sighash type и digest, результаты
coincurve и независимой арифметики. High-S остаётся в записи; библиотечная
проверка использует эквивалентную нормализацию. Parent raw подтверждает script
и сумму prevout; это существенно для BIP143.

`catalog.json` / `catalog.csv` дают 256 адресов и найденные точки с источниками;
`points.json` включает все исследованные точки, в том числе не относящиеся к
puzzle. `signatures.json` содержит проверенные подписи, повторения r и явно
неподдержанные скрипты. `anchor-inputs.json` отделяет пять исторических ориентиров
от остальных расходов. `target-history.json` и `publications.json` задают точное
покрытие и ограничения поиска №71.

В подписи с уже опубликованным приватным ключом nonce вычисляется из ECDSA
уравнения и сверяется с его точкой, затем со строгим
[RFC6979/HMAC-SHA256](https://www.rfc-editor.org/rfc/rfc6979). Это не восстановление
неизвестного приватного ключа. Совпадение не доказывает конкретный кошелёк;
несовпадение не исключает RFC6979 с дополнительными параметрами/grinding.

Raw bytes/txid/подписи проверяются локально. Полнота истории и включение в
актуальную цепь опираются на ответы обозревателей: собственный full node и
глобальный архив mempool здесь не используются. Отрицательный поиск точки
не доказывает, что она нигде никогда не публиковалась.

## Возможное продолжение

1. При точном совпадении точки с №71 — отдельная подготовка kangaroo.
2. При реальном повторе r для одного ключа и разных сообщений — отдельная
   проверка конкретной слабости, с сохранением различия puzzle/посторонних ключей.
3. Дополнительные истории адресов и архивы публикаций — новый конечный список
   источников и новый снимок; уже проверенные байты повторно не скачивать.
4. Изменение модели генерации/seed — только на основании новых данных;
   подпись 2019/2023 года не определяет автоматически генератор 2015 года.

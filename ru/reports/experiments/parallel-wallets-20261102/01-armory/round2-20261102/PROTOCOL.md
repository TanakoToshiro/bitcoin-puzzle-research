# A1-R2 — повторный анализ связей и недостающих children

Дата: 2026-11-02. Авторизовано новым запросом пользователя. Первый цикл
сохранён неизменным; новые файлы только в этой вложенной папке 01-armory.
Без подагентов, GPU, установки пакетов и перебора слабых seed.

## Новые вопросы и заранее выбранные проверки

1. Заменить прежние четыре HNP-наблюдения точным решением **двух** masked
   children при известном произведении множителей между ними. Для
   x=r1+2^b1*q и A*x mod n=r2+2^b2*t получается одно модульное сравнение
   t=(a*q+d) mod n с прямоугольными границами q,t. Число решений считать
   точным Euclidean floor-sum; перечислять бинарным разбиением только непустых
   интервалов. Предполагаемая цена O(log n) для счёта и
   O((K+1)*log Q*log n) для K выходных кандидатов, не перебор всех q.
2. Проверить пары №130/135 (129+134 бит) и №125/130 (124+129 бит), а также
   точный счёт без перечисления №120/125 и №69/70. Коэффициент A остаётся
   дополнительным данным. Сумма битов сама по себе не гарантия единственности:
   отдельно тестировать вырожденный A=1.
3. Для пяти записей между соседними решёнными высокими номерами произведение
   множителей не зависит от порядка. После точного восстановления кандидата
   порядок восстанавливается по HASH160 parent и проверке единого C.
   Проверить перемешивание, дубликаты и отсутствие правильного множителя.
   Не заявлять автоматическое выделение нужных пяти строк из произвольного
   огромного смешанного журнала.
4. После восстановления scalar/C научиться идти назад по смешанному,
   неупорядоченному журналу: k_parent=k_current/m mod n; проверить parent
   hash и u=C XOR D(U(P_parent)). Существование совпадения проверяется по всем
   уникальным записям; неоднозначность не разрешается молчаливым выбором.
5. При разрыве обратного журнала остановиться. Дополнительная исходная точка
   до разрыва + C позволяет пройти короткий gap публично и обратить известное
   произведение. Отдельно проверить неправильную точку и отсутствие точки.
6. Измерить реальную пользу для неизвестных synthetic №71/100/140/160;
   известные частичные ключи сохраняют реальные маски/пропуски snapshot.
   Ни один новый реальный private key не обещается.

## Входы и бюджеты до запуска

- Используются ровно 83 закреплённых решения A1; SHA256 совпадает с HD-01.
  Проверку адресов первого цикла не повторять; подтвердить hashes приёмки.
- Toy: floor-sum против прямых сумм (включая отрицательный b), точный pair
  solver против полного перебора small odd moduli и всех малых остатков.
- secp256k1: 8 synthetic кошельков × две пары; положительные и три отрицательных
  изменения пакета для каждой пары. Solver получает только пару масок,
  unordered short log, индексы и целевые номера; никаких P/C/raw scalars.
- Предсказания проверяются по отдельному oracle; №135 для пары125/130 — holdout,
  №140/160 — новые synthetic цели. Solver запускается отдельным процессом.
- Reverse: 2 synthetic кошелька из тех же восстановлений; чужие записи и
  дубликаты; полный, повреждённый и bridged варианты; отдельный subprocess.
  Приватный старт берётся только из вывода первого solver, не из oracle.
- Не более 1024 перечисляемых арифметических кандидатов, 512 уникальных log
  записей, 256 шагов обратного хода, 100000 проверок parent на один пакет.
  Кандидатный count может быть огромным: вернуть точное число и отказ без
  перебора. Для bridge не более 8 переходов и 4 публичных якорей.
- На стадию <=60 секунд, общий новый CPU-пилот <=180 секунд; сохранять JSON
  после успешной стадии и stderr при ошибках. Завершённые стадии не повторять.
- Неизвестные реальные коэффициенты не подменять свободно выбранными;
  результат только с исторически обоснованными дополнительными артефактами.

Оценки о стоимости относятся к этому алгоритму, не являются нижними границами
всех атак. Полный набор арифметических кандидатов и достоверная Armory-цепочка
различаются и проверяются раздельно.

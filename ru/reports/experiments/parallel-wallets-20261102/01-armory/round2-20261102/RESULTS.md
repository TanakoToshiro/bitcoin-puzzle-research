# A1-R2 — второй анализ Armory

**Новый результат условный и синтетический: две маски известных детей и пять
записей журнала достаточны в проверенных цепочках для восстановления raw
ключа и chaincode. Реализованы также поиск позиции короткого фрагмента,
обратный ход по смешанному журналу и восстановление разрыва при наличии
дополнительной исходной публичной точки. Реального нового Puzzle key нет.**

## Два решения вместо четырёх

Новая программа точно решает `y=A*x mod n` при известных младших остатках
x,y. Она считает решения евклидовым алгоритмом суммирования целых частей и перечисляет только
непустые участки. Решётки не используются; при допустимом числе кандидатов
получается весь арифметический набор, а не только предложение Babai.
Алгоритм и доказательство — [MATH.md](<MATH.md>).

На8 разных synthetic Armory-цепочках пара№130/135 (129 и134 наблюдаемых бита)
дала по одному арифметическому кандидату. Для пары№125/130 оставалось8–21,
затем проверки журнала выбирали ровно один. В сумме16/16 positive,
48/48 неверных пакетов отвергнуты. Речь о реальных **размерах масок**, а не
о реальных private values автора. Все synthetic данные помечены отдельно.

Вход решателя содержит только две маски, пять переходов с parent hashes
(семь строк с двумя дублями в контроле), mapping и целевые номера. Нет
root, полного raw, P_raw или C. Сегмент перемешан; произведение множителей
не зависит от порядка, а после получения scalar порядок проверяется по
HASH160 и постоянному C. Восстановленный C позволяет идти вперёд даже без
последующих log-записей: проверены новые synthetic №140/160. Для пары125/130
№135 дополнительно использован как holdout.

Это уменьшение требуемых данных и точное перечисление, **не заявление об
ускорении по времени относительно уже быстрого HNP первого цикла**. Для
настоящего Puzzle подходящего A или пяти строк журнала у нас по-прежнему нет.

## Позиция короткого фрагмента может быть неизвестна

В двух контрольных журналах проверено по479 окон, и нужный фрагмент найден
без передачи его позиции. Журналы содержат последовательные блоки разных
кошельков; каждая проверка окна использует пару№130/135. Порядок внутри
пяти строк и точные дубликаты не мешают проверенному методу.

Это ограниченный поиск **окон**, а не произвольных подмножеств. При строгом
чередовании строк двух кошельков оба отрицательных контроля не нашли окна.
Результат не исключает подходящую цепочку среди не соседних записей.
Индекс строки в файле не принимается за Armory chainIndex.

## Ранее неизвестные дети и root при обратном ходе

Из вывода pair solver взяты raw key130 и C. Отдельный reverse-процесс получил
смешанные, перемешанные строки двух кошельков (291 уникальная запись и10
дублей), но не получил private root. Для каждого кандидата на предыдущую
строку он обращал множитель и проверял parent hash и C.

Оба полных журнала позволили дойти до root и проверить неизвестные synthetic
№71/100. При удалении одной записи оба прохода корректно остановились на
chainIndex80. Дополнительная **исходная** P_74 дала публичный путь через6
переходов, после чего снова восстановлены root и №71. С неправильной точкой
проход оставался остановленным. Итого4 полных восстановления и4 правильных
остановки, включая неверный дополнительный якорь.

Без предыдущих множителей или подходящего P до разрыва дешёвое обратное
обращение Armory всё ещё не получено. Наличие C само по себе этого не меняет.
Подробная карта достаточных/недостаточных входов — [RECOVERY_PATHS.md](<RECOVERY_PATHS.md>).

## Проверка полноты и пределы

Floor-sum проверена против26702 прямых сумм. Pair solver совпал с полным
перебором всех57660 малых систем (включая нулевые остатки, пустые множества,
композитный нечётный modulus и края). Ещё32 перехода secp256k1 сверены
независимой affine-арифметикой. Solver-пакеты, отдельный oracle, все ответы,
счётчики и времена сохранены. Данные взяты из закреплённого83-решённого
снимка; принятые проверки адресов первого цикла подтверждены хэшами.

Контрпример A=1 оставил примерно2^122 кандидатов даже при масках129/134;
перебор не запущен. Поэтому263 наблюдаемых бита не объявляются безусловной
гарантией единственности. Для одного synthetic A пара№69/70 оставила около
2^119 арифметических вариантов. Дешёвый count большого множества не равен
дешёвому нахождению правильного элемента.

Для известных **только** решений A неизвестно: SHA/XOR переходы зависят от
полных raw points и C. Алгоритм не вычисляет неизвестный коэффициент,
не обращает default C=g(root) и не заменяет условные raw points точками
masked keys. Условный маршрут от высокой окончательной публичной точки
описан отдельно как следующий анализ; он не выполнялся в этой серии.

Ни практический unconditional путь до2^32, ни причастность Armory к автору
Puzzle не установлены. Armory не исключён и невозможность других атак не
доказана. Мировая новизна floor-sum/Euclidean методов не заявляется.

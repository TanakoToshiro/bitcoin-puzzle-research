# Какие данные позволяют восстановить неизвестные дочерние ключи

Во всех строках речь о классической Armory-цепочке и отдельно заданном
соответствии Puzzle-номера исходной позиции. Штатный генератор не маскирует
детей; маска применяется после экспорта. P_raw и P_masked не взаимозаменяемы.

| Доступная информация | Что действительно получается | Чего не хватает / предел |
|---|---|---|
| Только 83 окончательных Puzzle private keys | Младшие остатки предполагаемых raw children | Нет C, исходных P и коэффициентов; нового практического поиска не получено |
| Только C | Фиксированная часть XOR | Без исходной P не вычислить следующий множитель |
| Одна исходная P и полный u её исходящего перехода | C=u XOR D(U(P)), затем публичная цепочка | Приватный scalar ещё неизвестен; для него нужны частичные private observations либо DLP |
| Исходная P_j и C до высоких известных решений | Публичные отношения между детьми; точный pair solver применим | Публичная точка сама по себе не сообщает scalar; после последнего известного решения нужны сведения для обратного хода |
| Пять подходящих строк130→135 + два masked решения | Полный raw ключ130, C; далее новые raw/masked children | Это продемонстрировано на8 synthetic цепочках, не реальный авторский журнал |
| Пять строк125→130 + два masked решения | 8–21 кандидатов в контролях, один после log-проверки; №135 остаётся holdout | Нельзя обещать одинаковое число кандидатов для всех A |
| Журнал с неизвестной позицией нужных5 строк | Bounded consecutive-window scan находит подходящее окно | Не решает произвольное interleaving и выбор любых5 строк из большого журнала |
| Восстановленный k_j,C и смешанные предыдущие log-записи | Обратный проход, ранее неизвестные дети, при полном пути — root | Для каждого шага нужна соответствующая запись либо дополнительный способ пройти gap |
| k_j,C, но предыдущая запись потеряна | Всё будущее от j; обратный проход останавливается | C не даёт дешёвого общего обращения нелинейного перехода |
| Предыдущий исходный публичный якорь перед gap + C + известный k после gap | Публичная деривация через gap, обратное произведение и все промежуточные private keys | Точка должна быть исходной и правильно индексированной; в тесте6 шагов, лимит8 |
| Полный raw private child + его исходящий u | Немедленно C и вся последующая цепочка | Окончательный masked key не считается полным raw child |

После получения k_j и C дальнейший **forward** путь не требует сохранности
журнала. Любые будущие строки можно заново вычислить. В опытах №140/160
предсказаны без записей после обучающего сегмента. Сложность линейна по числу
переходов: один raw point, doubleSHA256, XOR и modular multiplication на шаг.
Скаляры не обрезаются между шагами.

Для **backward** пути важны конкретные предыдущие множители. В контроле
удалена запись79→80, поэтому остановка произошла на chainIndex80. №100 и125
ещё достижимы, №71 — нет. Добавление P_74 дало путь74→80, после чего восстановлены
и №71, и root. Это пример того, какие именно отсутствующие данные меняют
результат; неправильная P_74 не дала ложного восстановления.

## Уровни проверки информации

1. **Арифметическая совместимость:** exact_pair возвращает полный список
   допустимых x для конкретного A. При A неизвестном такого списка нет.
2. **Связь с историческим генератором:** parent hashes, полный u и постоянство
   C проверяют фактический Armory-путь. Численное произведение случайных
   множителей не объявляется настоящей цепочкой.
3. **Предсказание вне обучения:** отдельный oracle/отложенные synthetic
   значения проверяют новые ключи. Два обучающих решения не считаются holdout.
4. **Атрибуция реальному Puzzle:** нужен подлинный артефакт автора или
   независимое совпадение с реальными ранее не использованными данными.
   Этого уровня текущие опыты не достигают.

## Условный маршрут с публичной точкой высокого нерешённого номера

Это алгебраический следующий путь, **не дополнительный проведённый recovery**.
Если известна окончательная точка Q_i, но не private key, то при b=i−1:

```
P_raw(h) = Q_i + (h−1)*2^b*G,
0 <= h <= floor((n−1)/2^b).
```

Это конечный наднабор исходных points; крайний h может требовать дополнительной
проверки диапазона. При b=255 не более двух точек. Для каждой такой P_current
и log-записи u можно получить `P_parent=inverse(u mod n)*P_current`, проверить
parent HASH160 и вывести C. Таким образом, журнал потенциально позволяет
начать **публичный** обратный проход, ещё не имея private scalar. После
достижения позиций высоких известных частичных ключей доступны коэффициенты
для pair solver. Пространство условных points не даёт известных младших
private bits само по себе.

В зафиксированном файле ровно83 solved records до№135; точек250–256 там нет.
В R2 этот маршрут не вычислялся и его масштаб/успех не приписываются контролям
выше. Нужны конкретная высокая окончательная точка, настоящий журнал и
обоснование позиционного соответствия. Это не замена недостающего журнала.

## Что изменилось относительно первого цикла

Требование четырёх масок и длинного упорядоченного сегмента не минимально:
для проверенных высоких пар достаточно двух масок и пяти записей, их порядок
восстанавливается после арифметического шага. Также реализован обратный ход
по доступным предыдущим множителям. Но требование **дополнительных данных
генератора** не снято. Ни один тест не сделал C, A или raw point публичными
для настоящего Puzzle автоматически.

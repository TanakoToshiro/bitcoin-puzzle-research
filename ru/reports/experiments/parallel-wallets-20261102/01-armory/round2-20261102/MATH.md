# R2 — точные связи частичных детей и обход цепочки

## 1. Два частичных ключа при известном отношении

Пусть n — порядок secp256k1; `0<x,y<n`, `y=A*x mod n`, `0<A<n`.
Из двух окончательных Puzzle keys в гипотезе маскирования известны только
`x mod w1=r1`, `y mod w2=r2`, где `w1=2^b1`, `w2=2^b2`, b=i−1.
Принудительный старший бит в r не включается.

```
x = r1+w1*q, y = r2+w2*t
a = A*w1*inverse(w2,n) mod n
d = (A*r1-r2)*inverse(w2,n) mod n
t = (a*q+d) mod n
```

Границы: `q_min=1` при r1=0, иначе 0;
`q_max=floor((n−1−r1)/w1)`. Аналогично t_min,t_max. Они исключают нулевые
private keys. Поскольку 0<=t<n, канонический остаток сравнения совпадает с t.
Каждое q, удовлетворяющее прямоугольнику, даёт ровно один полный x, и наоборот.
Это точное преобразование, не релаксация и не предположение об энтропии.

Обозначим `F(L,m,a,b)=sum_{i=0}^{L−1} floor((a*i+b)/m)`.
Для 0<T<m число q в [s,s+L), у которых `(a*q+d) mod m<T`, равно

```
F(L,m,a,d+a*s) − F(L,m,a,d+a*s−T).
```

Доказательство: для z=m*h+r, 0<=r<m, разность
`floor(z/m)−floor((z−T)/m)` равна 1 ровно при r<T. Условие t в [lo,hi]
получается как count(<hi+1)−count(<lo). Граничные T<=0 и T>=m обрабатываются
непосредственно. Отрицательный b требует floor-деления, не усечения к нулю.

F считается евклидовым обменом осей решётки. Предварительно извлекаются
целые части a/m и b/m; затем для 0<=a,b<m применяется отражение суммы с
новыми длиной `floor((a*L+b)/m)`, остатком `(a*L+b) mod m` и обменом m,a.
В реализации используются Python integers, никаких переполнений uint64.
Определение и стандартная O(log m) процедура описаны в
[официальной документации ACL](https://atcoder.github.io/ac-library/production/document_en/math.html).
Код библиотеки не копировался; ограничения её интерфейса до2^32 здесь не применяются.

После точного count бинарно делим q-интервалы и посещаем только непустые.
Так находится **весь** набор из K ключей, если K<=1024. Цена счёта O(log n)
арифметических итераций; перечисления O((K+1)*log Q*log n), память O(K+log Q).
Это оценки числа операций над большими целыми (до порядка512 бит), не EC.
При K>1024 возвращаются точное число и budget_refused до перечисления.
Ни перебор 2^127 возможных q, ни BSGS, ни LLL не требуются.

Для настоящих b=129/134 наблюдаемая пара обладает сильными ограничениями,
**если A известно**. Но сумма263 не гарантирует единственности. При A=1
и совместимых вложенных остатках сохраняется примерно2^122 ключей; этот
контрпример вычислен точно. Типичная оценка2^(256−b1−b2) не заменяет count
и не является доказательством независимости наблюдений Armory.

## 2. Почему достаточно короткого журнала

Штатный переход: `u_j=BE(C XOR D(U(P_j)))`, `m_j=u_j mod n`,
`k_(j+1)=m_j*k_j mod n`; C постоянен, U —65-byte uncompressed point,
D —double-SHA256. Между №130 и №135 при проверяемой последовательной
схеме экспорта ровно пять переходов: `A=product(m_129..m_133) mod n`.

Произведение коммутирует: порядок пяти строк не нужен для арифметического
шага. После восстановления candidate x вычисляем HASH160(U(xG)); он должен
совпасть с parent hash одной строки. По её полному u получаем C, вычисляем
следующий private key и повторяем. Проверяем каждый u, общий C и весь набор
строк. При нескольких записях с одинаковым parent hash и разными u
неоднозначность отвергается. Повторяющиеся идентичные записи удаляются.

Этот формат требует заполненного parent hash. Первый цикл принимал пустой
hash в некоторых unlock-строках, но новый способ восстановления порядка
на них не распространяется. Также не моделируется повтор одного адресного
состояния в настоящем цикле: удаление дублей рассчитано на повтор логирования,
а не на многократный обход криптографического цикла.

Для пары125/130 возможных x больше; их правильность определяется проверкой
фактических log hashes и цепочки. №135 остаётся holdout. Во всех опытах
chaincode/исходные points/полные keys отсутствуют во входном пакете.

Математически для генерации кандидатов достаточно одного A. Для последующего
получения C достаточно одного корректно привязанного полного u. Однако
отдельное поле «произведение пяти множителей» не заявляется штатным экспортом:
реальный проверенный источник этих величин — пять строк multipliers.txt.

## 3. Неизвестное расположение строк

Если нужные пять уникальных записей идут подряд, bounded window scan ищет
их позицию точным решателем пары. Внутри окна порядок может быть любым.
Для L уникальных строк проверяется L−4 окон, максимум512. Это O(L) вызовов
арифметического count плюс перечисление/валидация оставшихся кандидатов.
Полный перебор C(L,5) подмножеств не выполняется. Строго перемежающийся журнал
двух кошельков может не содержать подходящего окна — такой отрицательный
контроль пройден, и он не объявляется отсутствием цепочки вообще.

Позиция окна в файле и chainIndex — разные величины. Расстояние в пять
переходов задано гипотезой о порядке исходного экспорта; scanner не доказывает
её для реального автора, не восстанавливает accounts/пропуски автоматически.

## 4. Обратный ход по неупорядоченному смешанному журналу

После получения текущего полного k и C для каждой строки u:

```
candidate_parent = k * inverse(u mod n,n) mod n
P_parent = candidate_parent * G
HASH160(U(P_parent)) == log_parent_hash
BE(C XOR D(U(P_parent))) == u
```

При единственном совпадении получен предыдущий private key. Строки могут
принадлежать разным кошелькам; проверка общего C и hash отбрасывает чужие.
Сканируются все строки для обнаружения неоднозначности, не выбирается первое
совпадение. Цена реализации O(L*d) EC-вычислений для d шагов; L<=512,
не более100000 проверок и256 шагов на пакет. Каждая проверка — вычисление
point из scalar, HASH160, а при совпадении hash — double-SHA256 и XOR.
Modular inverses предварительно вычисляются по строкам один раз.

Наличие C не делает общий обратный переход `P -> m(P)*P` дешёвым. Здесь
неизвестный m берётся из конкретной конечной коллекции журнала. Если запись
предшественника отсутствует, обычный обратный проход останавливается.
Секретный старт reverse.py передан из вывода pair solver, не из test oracle.

## 5. Восстановление разрыва с дополнительной исходной точкой

Для известной P_a до разрыва и C публично проходим g шагов, вычисляем
B=product(m) mod n и проверяем `B*P_a=P_current`. Тогда
`k_a=k_current*inverse(B,n) mod n`. Это также даёт все промежуточные keys.
В опыте использованы chainIndex74→80, шесть шагов, лимит8.
Неправильная точка не проходит проверку. Указанная P_a — **новое исходное
public datum**, не точка окончательного masked puzzle-key.

## 6. Что не восстанавливается из одних решений

Без A два численных остатка №130/135 задают около2^127 вариантов первого
raw и2^122 второго, то есть около2^249 **пар концов**. Каждая пара порождает
свой ratio; это не число различных ratio, не доказанная энтропия и не
нижняя граница атаки. Связь A с Armory всё ещё требует неизвестных SHA/XOR
множителей и полного пути. Новый быстрый exact count не вычисляет неизвестное A.

Default C=g(root) не отменяет это препятствие: g использует исторический
SHA256/HMAC256-подобный вывод, а не линейное правило. Коммутативность численного
произведения полезна, когда множители уже извлечены; сами множители зависят
от состояния и нельзя переставлять переходы генератора при создании цепочки.

Реальные неизвестные children в этом этапе не получены. Нет ни настоящего A,
ни короткого журнала, ни исходной точки автора, подтверждающих Armory-гипотезу.

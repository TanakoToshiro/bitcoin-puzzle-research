# Armory R2 — команды

Итог: [RESULTS.md](<RESULTS.md>), формулы: [MATH.md](<MATH.md>), данные для
восстановления: [RECOVERY_PATHS.md](<RECOVERY_PATHS.md>).

Из корня проекта:

> Исполняемый код/команды опущены в документационной копии.


Среда: существующая Python3.11.9 .venv, coincurve21.0.0; дополнительные
пакеты не нужны. Код точного счёта — стандартный Python с большими целыми.
Среда используется только для чтения, bytecode отключён. При чтении входов
проверяется первый105-файловый manifest; текущие данные скопированы с SHA256.

ACTIVE_RUN.json указывает принятую серию. PROTOCOL.md и WINDOW_PROTOCOL.md
сохранены до запусков соответствующих тестов. Основные стадии имеют timeout
60 секунд, основной пилот180 секунд; дополнительный window stage30 секунд.
Частично выполненная стадия при продолжении выполняется заново, завершённая
не повторяется. Code pins не дают продолжить старый run изменённым решателем.
Для независимого повтора использовать новую копию/новый ID, сохранив старый
run; новый вход не подменять в существующем принятом snapshot.

Отдельные процессы:

> Исполняемый код/команды опущены в документационной копии.


Примеры входов — PAIR_INPUT.json, WINDOW_INPUT.json, REVERSE_INPUT.json в run.
PAIR/WINDOW получают только2 observations, log_lines и targets. Отдельный
SYNTHETIC_ORACLE.json решатели не читают. REVERSE получает полный стартовый
scalar/C **из вывода первого решателя**; публичный bridge — явно добавленное
сведение в вариантах bridge. Все эти ключи исключительно контрольные.

Допустимы только полные parent hashes; пустые unlock hash-строки здесь
отвергаются. Log deduplication удаляет точные повторения, не моделирует циклы
с повторяющимися исходными адресами. Short segment должен быть полным;
scanner ищет только consecutive windows, reverse сканирует все записи.

`exact_pair.solve` возвращает точное count даже при превышении cap, но не
перечисляет кандидатов. Это budget_refused, а не отсутствие решения.
`reverse.py` сообщает missing_predecessor/ambiguous/budget отдельно.
Targets имеют explicit puzzle/chain_index: интерпретация этого mapping
остаётся частью гипотезы, а не выводом из количества строк журнала.

`report.py build` собирает числа/STATUS/SUMMARY/ACCEPTANCE из готовых файлов.
`report.py seal` создаёт manifest один раз; `verify` проверяет его и старый
manifest, не повторяя исследования. Первоначальные документы первого цикла
намеренно оставлены неизменными; новая сводка лежит в этой папке.

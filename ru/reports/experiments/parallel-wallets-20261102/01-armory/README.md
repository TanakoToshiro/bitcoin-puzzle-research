# A1 Armory — воспроизведение

Итог: [RESULTS.md](<RESULTS.md>). Краткая сводка: [SUMMARY_FOR_MERGE.md](<SUMMARY_FOR_MERGE.md>).
Математика: [MATH.md](<MATH.md>). Форматы: [ARTIFACT_PROFILE.md](<ARTIFACT_PROFILE.md>).

Из корня проекта, PowerShell:

> Исполняемый код/команды опущены в документационной копии.


ACTIVE_RUN.json указывает принятую серию. Ранний ошибочный запуск не удалён.
PROTOCOL записан до вычислений, дополнение о multiplier log — до первого
запуска. Для каждой стадии timeout 60 секунд; на новый запуск 180 секунд.
Стадии сохраняются атомарно в смысле «JSON появляется только после успешного
возврата», завершённые не повторяются. При прерывании незавершённая стадия
может быть выполнена заново. `--new-run` создаёт отдельный ID и переносит
принятую inputs-проверку; применять только при неизменных данных/коде этой
проверки. Новые данные требуют отдельного исследования, не замены снимка.

Для чистого независимого повторения скопировать эту папку без runs/ACTIVE_RUN/
MANIFEST в новое место внутри разрешённой области и настроить bootstrap.py
на доступный vendor. Нужны Python3.11.9, coincurve21.0.0, sympy1.14.0,
python-flint0.9.0, mpmath1.3.0. Сейчас coincurve берётся из общей .venv, а
sympy/flint/mpmath — из HD-01/vendor **только для чтения**; bytecode отключён.
Никакие пакеты в общую среду не устанавливались. `prepare.py` закрепляет
копии входов; `fetch_release.py` загружает только v0.92.3 и больше не скачивает
уже закреплённые файлы. Сетевой доступ для вычислений не требуется.

Отдельный восстановитель (создать новый output, не перезаписывать принятый):

> Исполняемый код/команды опущены в документационной копии.


Формат solver-пакетов описан в ARTIFACT_PROFILE; примеры PUBLIC_PACKETS.json
в активной серии. `log` не содержит P/C, `anchor` получает их явно. Parsers
выдают metadata; для решателя нужно добавить observations, mapping и targets.
Они не ищут и не модифицируют wallet files. Запуск чужого исторического GUI
не требуется. Реальное происхождение артефакта нельзя установить checksum.

SYNTHETIC_ORACLE.json хранится отдельно от входов решателя; solver его не
читает. Все контрольные private keys предназначены только для тестов.
SOLVER_OUTPUT сохраняет ответы и решётки, а не только флаг успеха.
NUMERIC_REPORT строится из результатов; audit.py проверяет дополнительные
независимые переходы и исторический serializer однократно. seal.py проверяет
хэши кода, источников и артефактов без повторения recovery.

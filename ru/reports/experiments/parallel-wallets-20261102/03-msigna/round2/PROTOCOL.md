# Второй заход, 02.11.2026

Первые результаты и запуск f38837a65fce неизменяемы. Новый вопрос: не скрывается ли за CoinVault в том же репозитории другая историческая деривация (legacy CoinQ), а также менялся ли реальный HD-переход до отсечения? Не расширять произвольно BIP32 path tree. При обнаружении иной формулы сначала подтвердить её доступность пользователю и конечными примерами.

План: до100 commits по пути hdkeys.cpp (не более2 страниц истории), legacy CoinQ_vault и его CLI, затем один ограниченный native-build пилот при наличии уже установленного компилятора/OpenSSL. Не устанавливать зависимости и не менять общие окружения. Новые source snapshots и pins только в round2. Старые source-model тесты не повторять.

Бюджет: сеть ≤40 новых файлов/запросов, запрос ≤30с; build ≤120с; каждый контроль ≤120с, суммарно ≤300с CPU; ≤1024 EC-дериваций и ≤65536 малых вариантов. Каждый запуск с отдельным ID, входами и выводами, повторное исполнение завершённых контролей запрещено. Перед математическим контролем дополнить конкретную гипотезу, если код покажет новый путь. Отсутствие native dependencies — ограничение бинарной проверки, не повод устанавливать пакеты или запускать длительный перебор.

Дополнение перед legacy-контролем: CoinQ binary export имеет deterministic flag,78-byte xpub, saved_count и doubleSHA256(xpub). Проверить123-byte формат на4 synthetic root/branch xpub,6 повреждениях и10 изменениях счётчика. Гипотеза: saved_count не связан с контрольным хешем, поэтому его нельзя считать доказанной границей/индексом; это не reduction секрета. ≤4 EC-дериваций, ≤1с ожидаемого CPU, жёсткий общий предел120с. Оригинальный ODB-exporter не запускать под видом этого независимого parser-контроля.

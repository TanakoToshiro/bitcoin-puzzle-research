# MSIGNA-03 — протокол, 02.11.2026

Исследуется только ciphrex/mSIGNA ace0c828bed7441ef6ddda314674d882ecf4dbbe (13.01.2015), штатный CoinDB/CoinCore и экспорт. Цель: выявить специфическую связь accounts/keychains/cosigners либо обосновать сведение просмотренного пути к HD-01 BIP32. Слабый seed не предполагается.

Входы: сохранённые первичные исходники HD-01, дополнительные файлы того же commit, исторические BIP32-векторы, фиксированные 83 решения HD-01. SHA-256 копий и Git blob проверяются. Из решений используются только младшие i−1 битов исходных children; публичные точки Puzzle не подменяют исходные точки.

План: проследить GUI → Vault → Schema → HDKeychain, экспорт и порядок; проверить leading zeros, invalid child, version/depth/fingerprint, наследование/повтор keychains. Сравнить независимую Python-модель с архивными векторами. Проверять выявленные отличия отдельными конечными примерами; стандартную HMAC-аддитивность не считать новой атакой.

Бюджет до запусков: один CPU-процесс; каждый контроль ≤120 секунд, весь набор ≤300 секунд; ≤2048 обычных EC-дериваций, ≤65536 малых перебираемых элементов, ≤512 искусственно заданных граничных случаев. При отсутствии новой recovery-гипотезы не запускать перебор master/seed/путей. Сохранять отдельный run ID, входы, выходы, времена; завершённый идентичный запуск не повторять. Старые GUI/полная C++-сборка не считаются выполненными без фактического запуска.

Новый вклад относительно HD-01: конкретные CoinDB пути и serialization/identity, межаккаунтные зависимости, проверка исторического поведения реализации. Условный результат требует явного описания недостающего артефакта; единственность ключа не равна дешёвому восстановлению.

# E9b: первая нативная версия BX → BIP32

[Результаты и покрытие](<RESULTS.md>), [скорость, оптимизация и стоимость](<COSTS.md>), [журнал завершённых этапов](<JOURNAL.md>), [зафиксированные гипотезы](<PROTOCOL.md>).

`bx-search` — Linux CPU executable, C++17/OpenMP, libsecp256k1 0.2.0 и OpenSSL 3.0.13. Собран под текущий Ryzen 9 6900HX с `-march=native`; на другом CPU пересобрать. CUDA-ядра в этой версии нет. Наличие 4090 само по себе этот executable не ускорит.

Проверяются 16 исторических гипотез BX 2.0.0/GNU: 16/32 байта entropy; родители m, m/0, m/0'/0, m/0'/1; последний индекс puzzle−1 / puzzle. Полное пространство нормализованных состояний 1..2147483646. Обычный случай с неизвестным случайным seed кошелька этим не покрывается. Ключи опубликованных решений полные; маскирование предполагается в гипотетическом генераторе, а не в публикации.

`driver.py prepare` выполнен Windows Python 3.11 из исследовательского venv с coincurve; для управления native в WSL используется имеющийся Python 3.12.3, только стандартная библиотека. Новые Python-пакеты и системные библиотеки не устанавливались. Старый E9 и рабочие проекты не изменяются.

Новый полный run повторно проверит небольшие интервалы прежних бенчмарков; это намеренное перекрытие разных запусков. Сводка объединяет интервалы и не засчитывает их дважды. Внутри run завершённые блоки не повторяются. Остановка между блоками штатная; после жёсткого прерывания незаписанный блок будет выполнен заново. Для плановой короткой остановки есть `--max-blocks N`. Входные хэши и конфигурация привязаны к ID; изменение конфигурации требует нового ID. Для изменения кода/данных/протокола создавайте **новую версию папки эксперимента**: текущая сводка рассчитана на единый неизменный набор данных и схем, смешивать версии нельзя.

При полном совпадении обучающих решений native записывает состояние и схему, проверяет отложенные решения; driver останавливает дальнейший поиск для независимого рассмотрения. До независимого вычисления ключей и адресов это кандидат. Недопустимый BIP32-узел сохраняет ошибку и не считается отрицательным результатом. Это первая версия без модели skip/retry для таких крайне редких случаев.

## Воспроизводимость

- `search.cpp`: RNG, BIP32, baseline/filter, OpenMP, промежуточные узлы для сравнения.
- `driver.py`: подготовка по E9, контрольные и поисковые блоки, возобновление, отчёт.
- `EXPECTED.json`, `synthetic/`: официальные векторы и искусственные наблюдения. Положительные восстановления не являются находкой puzzle.
- `CONTROLS.json`, `controls/`: проверки и точное сопоставление первой гистограммы E9.
- `benchmarks/`: все короткие и продлённые замеры, входные хэши, время ядра и процесса отдельно.
- `extended.py`, `runs/acceptance-resume/`: длинные измерения и реальный stop/resume без повторения первого блока.
- `profile.cpp`, `PROFILE.json`: независимые микрозамеры компонентов, не предсказание GPU.
- `BUILD.json`: версии, аппаратная конфигурация, параметры сборки, хэши executable.
- `COST_ESTIMATE.json`, `analyze.py`, `sources/`: расчёт затрат и снимки официального прайс-листа.
- `ACCEPTANCE.json`, `FINAL_MANIFEST.json`: итоговая приёмка и хэши текущего снимка.

Исходные известные решения и Python-эталон находятся в E9 и его ссылках; `EXPECTED.json` фиксирует их SHA-256. Старый пилот можно проверить без его перезапуска. `RESULTS.md` и числовые таблицы пересобираются, прежние интерпретации и новые поправки сохраняются добавлением в `JOURNAL.md`.

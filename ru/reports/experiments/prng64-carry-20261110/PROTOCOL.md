# RNG64-05 — точная сеть переносов известной суммы

10 ноября 2026. Ровно те же 10 synthetic_incomplete из RNG64-04; входы копируются
побайтово. Исторические семейства, packing, маски, known/fitting/holdout и шаги
между ключами не меняются. Старые результаты только читаются.

Состояние — сразу после первого полностью известного выхода z. Представление:
64 свободных бита x, c0=0, y_j=x_j XOR c_j XOR z_j; c_(j+1)=x_j OR c_j при
z_j=0 и x_j AND c_j при z_j=1. Последний перенос отбрасывается modulo 2^64.
Других независимых битов y нет. При z=0 запрещён x=0; при z!=0 нулевое состояние
невозможно. Возврат свидетеля — в прежнее состояние перед offset0; блокировка
только по x, поскольку y однозначно определяется суммой.

CMS: явные AND/OR-переносы и аффинные XOR-формы, включая константы. Их точное
распространение через прежние прямые/обратные переходы. Ограничение anchor-суммы
использовано конструктивно и повторно общей сетью сложения не добавляется.
Сложения остальных наблюдаемых выходов кодируются как прежде: меняется только
сеть anchor и её подстановка. Cvc5: независимая bit-vector кодировка того же
упрощения, одно 64-битное x и явные однобитные переносы, y собран конкатенацией.

Те же pycryptosat 5.18.0/cvc5 1.4.2, параметры, 120 секунд/запрос,
240 секунд/движок/случай, до 8 состояний. Два движка на всех десяти synthetic-
входах, четыре независимых CPU-случая одновременно. Baseline RNG64-04 только
читать. Это проверка кодировки; алгебраическая редукция (x,z-x) уже известна.

До основной серии: все 8 локальных комбинаций x_j,c_j,z_j; исчерпывающие суммы
для ширин 1..8; полное recovery на уменьшенных задачах с ранними/поздними
частичными наблюдениями; фиксация полного состояния/испорченного бита для всех
20 пар case×engine; нулевая сумма, максимальные слова, переполнение, неоднозначность,
UNKNOWN. Оба решателя должны отвергать второе y при фиксированных x,z.

Каждый движок получает реальные данные только после собственного полного слепого
synthetic-восстановления, содержащего посаженное состояние, и проверки 83 масок,
81 holdout и скрытого №71 для обоих прежних межключевых шагов. Секреты не передаются
worker. Фиксированные состояния служат проверкой реализации, не заменяют blind recovery.
Все SAT проверять обычным исполнением. UNKNOWN/cap/budget — незавершённость.
Локальный UNSAT исключает лишь указанную схему; при состояниях проверять только
два прежних шага. Полный holdout-кандидат останавливает новые задания до проверки адреса.

Формулы, свидетели, время, ошибки, версии, хэши и промежуточные выводы сохранять.
ОС-блокировки runner/worker; возобновление без повторения завершённых этапов.
Финальный аудит, отчёт и RESULTS.md в новой папке; GPU и облако не нужны.

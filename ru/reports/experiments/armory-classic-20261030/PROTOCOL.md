# E3 — классическая цепочка Armory: протокол до вычислений

Дата: 2026-10-30. Объект — официальный исходный код BitcoinArmory, commit
`61a596fa94f9cacf9fb00c4e02d0eb65d8b17513` от 2015-01-08. Это проверка
исторической реализации и применимости к обрезанным ключам puzzle, не утверждение,
что создатель puzzle использовал Armory.

## Фиксированные проверки

1. Изолированно исполнить неизменённые AST-узлы `sha256`, `sha512`, `hash256`,
   `HMAC`, `HMAC256`, `DeriveChaincodeFromRootKey` исходного ArmoryUtils.py в
   настоящем CPython 2.7.9 из архива E2. Адаптер SecureBinaryData реализует только
   хранение байтов и double-SHA256. Весь модуль/GUI/кошелёк не импортировать.
2. Проверить опубликованные в `pytest/testPyBtcAddress.py` два дочерних приватных
   ключа и второй публичный ключ для root=`aa`×32, chaincode=`ee`×32.
3. Сверить 160 последовательных дочерних ключей в каждом из четырёх случаев:
   `aa`×32/`ee`×32; `aa`×32/default; root=1/default; root=n−1/default.
   Две реализации: coincurve/libsecp256k1 и независимая аффинная арифметика Python.
   Сверять приватное и публичное продолжение, полные 65-байтные точки, множители
   и младшие биты при условном наложении маски puzzle. Маска не подаётся обратно.
4. Отрицательные контроли: compressed вместо uncompressed, SHA256 вместо
   double-SHA256, little-endian множителя вместо big-endian; стандартный
   HMAC-SHA256 вместо исторической конструкции с 32-байтным дополнением.
5. Положительный алгебраический контроль: восстановление chaincode из двух
   **полных** соседних приватных ключей и проверка по третьему. Включить случай
   множителя `n+1`, чтобы проверить второй возможный прообраз остатка по n.
6. По сохранённому проверенному снимку 83 решений подсчитать реально наблюдаемые
   разряды исходных выходов. Не заменять усечённые ключи полными и не считать
   принудительный старший бит наблюдением генератора.

Контроли должны пройти до 160-шаговых серий. Каждый случай — отдельный checkpoint.
Лимит нового запуска 600 секунд вычислительного wall time (без подготовки кода и
архива); проверка бюджета между атомарными стадиями, исторический процесс имеет
timeout 180 секунд. Незавершённость/ошибка не служит отрицательным результатом.
Запуск с остановкой после первой стадии и последующее продолжение проверяют
пропуск завершённых работ. После завершения повторный resume обязан выполнить 0 стадий.

## Граница вывода

Совпадение с векторами подтверждает реконструкцию конкретной цепочки; не подтверждает
её связь с puzzle. Отсутствие полного корня/chaincode/обоснованного малого множества
seed означает остановку на реконструкции. Произвольные словари, timestamps,
корни малого размера и схема с обратной подачей обрезанного ключа здесь не ищутся.
Никакое число неизвестных разрядов не выдаётся за доказанную сложность атаки.
Предсказание бита/XOR №71 допустимо заявлять только при отдельном проверяемом выводе;
этот протокол не обещает такого вывода из одного устройства кошелька.

Результаты сохраняются в runs/<ID>, таблицы RESULTS.md строятся из JSON,
промежуточные интерпретации дописываются в NOTES.md. Старые эксперименты не меняются.

# E2b: расширение точной гипотезы Python

Зафиксировано 2026-10-30 до просмотра результатов нового поиска. Пользователь разрешил расширение без временного лимита, включая GPU. Рабочие puzzle/puzzle-ubuntu и предыдущие запуски не изменяются.

## Область проверки

Полное пространство явных integer seed `[0,2^32)`, один seed перед всей последовательностью. Python использует `init_by_array`, а не scalar MT init_genrand. Отрицательные integer seed имеют эквивалентное абсолютное значение. Произвольные большие int, строки, float, seed(None), SystemRandom не входят. В частности, обычный seed(None) берёт системную энтропию; fallback `int(time.time()*256)` уже выходит за 32 бита для 2015 года. Нельзя объявлять Python в целом исключённым.

Десять точных способов выдачи × два шага × шесть начальных смещений = **120 физических схем**:

0. `bits256`: getrandbits(256); эквивалент words_reverse_big.
1. `words_forward_big`: восемь getrandbits(32), прямой порядок, big-endian слова.
2. `words_forward_little`: прямой порядок, little-endian слова.
3. `words_reverse_little`: обратный порядок, little-endian слова.
4. `randrange_order_py2`: CPython 2.7.9 randrange(1,n_secp256k1), 257 бит с отклонением.
5. `randrange_order_py3`: CPython 3.4.2 тот же вызов, 256 бит с отклонением.
6. `bits_i`: getrandbits(i) и принудительный старший бит.
7. `bits_i_minus1`: getrandbits(i-1) и принудительный старший бит; для i=1 вернуть 1 **без вызова RNG**, поскольку исторический getrandbits(0) недопустим.
8. `interval_py2`: CPython 2.7.9 randrange(2**(i-1),2**i).
9. `interval_py3`: CPython 3.4.2 такой же вызов. randint(lo,hi-1) эквивалентен.

Общие API 0–3,6–7 сверяются на обеих версиях, но одинаковые последовательности не пересчитываются как якобы независимые семейства. Начальные смещения **в 32-битных выходах**: 0,1,8,16,32,64; это только конечные выбранные смещения, не все возможные. Шаг 1/2: перед задачей i>1 отбросить stride-1 вызовов той же функции для текущего i. Для фиксированных 256-битных API это эквивалентно исходным индексам `(i-1)*stride`. Для переменной ширины явно выбрана именно описанная схема, не произвольный поток.

После draw: `key_i = 2**(i-1) | (draw & (2**(i-1)-1))`. Пропуски puzzle не сжимаются.

## Доказательность фильтра

GPU/C++ является только ускоренным **фильтром по №1–12** (66 свободных битов). Все прошедшие и все случаи выхода за ограниченный буфер MT передаются историческим Python для точной проверки №1–50, затем всех отложенных известных решений и адреса №71. Переполнение никогда не отбрасывает seed. Если ни один seed не проходит №1–12, он тем более не совпадёт со всеми №1–50. Полное пространство seed обходится непересекающимися полуинтервалами; пропущенный/ошибочный блок не считается проверенным.

Перед поиском: сравнить GPU и CPU с реальными историческими интерпретаторами для всех 120 схем и граничных/детерминированных seed; синтетическое восстановление каждой схемы; контроль неверных наблюдений; проверки границ 2^32 и seed>2^32; сверка полных 135 шагов независимой Python-арифметикой; проверка сохранения и продолжения. Ограниченный буфер тестируется искусственно, положительные кандидаты воспроизводятся обычным историческим исполнением. Сохраняются код, хеши, конфигурации, бинарник/компилятор, данные, векторы, покрытие и ошибки.

## Организация

Сначала измерение скорости и контроли. При пригодности GPU — полный диапазон; при ошибке GPU — остановка с сохранением точного покрытия, а не отрицательный вывод. Порядок блоков: сначала секундные timestamp 2014-01-01 UTC — 2015-02-01 UTC, затем остальная часть полного пространства. Это приоритет проверки, **не утверждение о дате генерации**. Ранее проверенный малый диапазон для старых схем будет повторён как часть совмещённого полного сканера: эта небольшая избыточность явно учитывается, результат не называется новым уникальным покрытием.

`RESULTS.md` пересобирается из артефактов; `NOTES.md` дописывается. Старые выводы не стираются. Строковые seed, float timestamp, fallback time*256, повторное seeding для каждого ключа и другие модели требуют отдельных последующих протоколов, а не молчаливого расширения этого.

# Расширенная проверка Python (E2b)

[Протокол](<PROTOCOL.md>), [результаты](<RESULTS.md>), [промежуточные выводы](<NOTES.md>). Текущий запуск: [20261030-105921-2f40f0fd](<runs/20261030-105921-2f40f0fd/RESULTS.md>).

**Завершён:** [итоговый отчёт](<runs/20261030-105921-2f40f0fd/CONCLUSION.md>). Все 2^32 seed и 120 схем проверены без совпадений. Повторное продолжение пропустило все 1024 блока без изменения их хешей/времени записи.

План покрытия: все 4 294 967 296 явных целочисленных seed и 120 схем выдачи/шага/смещения. Это конечная проверка конкретных способов использования исторического `random`, не всего Python. Полный перебор включает секундные Unix timestamp, попавшие в 32 бита, но не произвольные float, строки и системную энтропию.

Вычисление — CUDA на локальной RTX 3070 Ti Laptop (8 GiB) через WSL Ubuntu-24.04, CUDA 13.2, sm_86. Аппаратная информация и точная команда компиляции: BUILD.json — артефакт исходного исследования (`BUILD.json`; вне снимка). GPU перебирает seed генератора, а не приватные ключи диапазона puzzle. Каждый seed инициализируется один раз для всех 120 схем. CPU-реализация того же фильтра используется для контроля; независимыми эталонами являются настоящие CPython 2.7.9/3.4.2 и отдельная Python-арифметика MT.

GPU проверяет младшие биты известных №1–12. Первый блок MT ограничен 624 словами: при нехватке буфера seed передаётся историческому интерпретатору и **не отбрасывается**. Настоящий кандидат проверяется по №1–50, всем отложенным решениям и адресу №71. Если нет даже кандидатов первых 12 задач, этого достаточно для исключения проверенных seed/схем. Полное состояние MT и 70 неизвестных битов №71 этим сами по себе не восстанавливаются.

Не запускать две команды `resume` одновременно для одного ID. Незавершённый блок можно повторить; блок без `.sha256` не учитывается. При ручной остановке Ctrl+C текущий блок может не сохраниться; ранее подтверждённые блоки остаются на диске. Изменение кода требует нового ID. Старые исторические runtime/исходники не копируются многократно: используются архивы соседнего `python-seed-20261030`, их хеши и метаданные сохранены.

`validation/` хранит 518 400 сравнений исторических выходов, CPU/GPU векторы, синтетические восстановления для всех 120 схем, отрицательный контроль, контроль переполнения и seed у границы 2^32. `runs/ID/code` и `inputs` заморожены. `shards/START-END.json` с парным SHA-256 содержит точный полуинтервал и кандидатов. `SUMMARY.json` хранит машинное покрытие, `RESULTS.md` обновляется после каждого блока, `EVENTS.jsonl` дописывается. Прежние E1/E2/E3 и основной проект не меняются.

Методические источники: сохранённые официальные исходники [CPython 2.7.9](https://www.python.org/downloads/release/python-279/) и [3.4.2](https://www.python.org/downloads/release/python-342/). Для размещения большого состояния MT в памяти GPU использована документация [CUDA Programming Guide](https://docs.nvidia.com/cuda/cuda-programming-guide/pdf/cuda-programming-guide.pdf); это инженерная реализация проверки, не новая криптографическая атака.

Дополнения к интерпретации: [область строковых/float seed Windows Python 2.7.9](<SEED_DOMAIN_AUDIT.md>), [точные исключения трёх float-конструкций](<PRECISION_EXCLUSIONS.md>), [сопоставление соседних версий 2.7.8/3.4.1](<ADJACENT_VERSIONS.md>). Это отдельные аргументы по исходникам и арифметике; они не меняют замороженный протокол GPU.

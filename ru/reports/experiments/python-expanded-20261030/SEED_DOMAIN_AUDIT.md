# Что действительно покрывает полный перебор integer seed32

Это **дополнительный вывод по исходникам**, не изменение замороженного протокола E2b и не заявление о запуске Windows CPython. Машинный аудит и SHA-256 — артефакт исходного исследования (`source-domain-audit/AUDIT.json`; вне снимка).

В CPython 2.7.9 Windows строковые seed (включая unicode), float и другие успешно хешируемые нецелочисленные объекты сводятся к `unsigned long` через `PyObject_Hash`. Windows-конфигурация задаёт 32-битный long, в том числе на Win64. Поэтому все такие успешно созданные состояния MT входят в множество состояний `Random(integer_seed)` при `0 <= integer_seed < 2**32`. Это также покрывает любые значения рандомизированного хеша: они всё равно помещаются в тот же конечный диапазон.

Если полный E2b завершится без кандидатов, отрицательный вывод для **96 схем, соответствующих Python 2.7.9**, распространяется и на эти виды seed на Windows. Для этого не требуется перебирать словарь строк. Важно: покрываются способы генерации ключей из протокола, а не произвольная Python-программа.

Доказательство состоит из трёх проверенных звеньев:

1. `Lib/random.py`: кроме None аргумент без преобразования передаётся в базовый seed.
2. `Modules/_randommodule.c`: для не-int/long берётся хеш типа long, затем unsigned long преобразуется в неотрицательный Python integer; дальше используется тот же init_by_array.
3. `PC/pyconfig.h` и `Include/object.h`: long и результат PyObject_Hash имеют 32 бита на Windows. Приведение отрицательного хеша выполняется по модулю 2^32; точное значение хеша не важно для включения в полный диапазон.

Источники зафиксированы на commit `a5f49f5bb46b6b8c7bf1ffedbaf3009186b94b50`: [Windows configuration](https://github.com/python/cpython/blob/a5f49f5bb46b6b8c7bf1ffedbaf3009186b94b50/PC/pyconfig.h), [hash API](https://github.com/python/cpython/blob/a5f49f5bb46b6b8c7bf1ffedbaf3009186b94b50/Include/object.h), [MT seeding](https://github.com/python/cpython/blob/a5f49f5bb46b6b8c7bf1ffedbaf3009186b94b50/Modules/_randommodule.c), [Python wrapper](https://github.com/python/cpython/blob/a5f49f5bb46b6b8c7bf1ffedbaf3009186b94b50/Lib/random.py).

## Что остаётся вне покрытия

| Инициализация | Причина |
|---|---|
| random.Random(None) в обеих версиях | Обёртка получает 2500 байт os.urandom и превращает в большой integer; это не автоматический 32-битный timestamp |
| Fallback обёртки при недоступности urandom | int(time.time()*256): для 2015 года около 39 бит |
| Большой явный int/long | Используются все слова абсолютного значения, не только младшие 32 бита |
| Python 2.7.9 на Linux x86_64, строка/float | В сохранённой сборке long имеет 64 бита; общий хеш может выйти за seed32 |
| Python 3.4.2, стандартная строка version=2 | Байты строки дополняются SHA-512, получается большой integer |
| Низкоуровневый _random.Random(None) без обёртки | Другая ветка C-кода: init_genrand от времени, не проверяемый здесь init_by_array |
| Повторное seeding между ключами, другое смещение/расход | Не соответствует единой последовательности из конечного протокола |

Не утверждается, что создатель использовал Windows или Python. Это уточнение множества уже проверяемых состояний. Ранее зафиксированная оговорка протокола «строки не входят» описывает отсутствие прямого словарного поиска; данный отдельный аудит доказывает включение конкретного случая Windows Python 2.7.9. Полный результат и фактическое покрытие следует читать в RESULTS запуска.

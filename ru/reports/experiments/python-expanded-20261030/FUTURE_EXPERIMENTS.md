# Следующие проверки Python — пока не запускались

Этот список явно отделён от выполненного E2b. Разрешение пользователя на длительные вычисления сохраняется, но множество возможных Python-программ бесконечно: каждая следующая проверка должна иметь конечную постановку, исторические векторы и собственный ID. Само число вариантов не является мерой вероятности найти уязвимость.

1. **Генерация ключа по байтам или hex-символам.** 32 вызова getrandbits(8), 32 вызова randrange(256), либо 64 выбора символа из явно зафиксированного hex-алфавита. Здесь расход MT отличается от восьми getrandbits(32). Python 2.7/3.4 также расходуют поток по-разному. Сначала сверить точные исторические API, порядок байтов/символов и использование каждого/каждого второго ключа, затем проверять seed32. Нынешние 120 схем этого не исключают.

2. **Прямой getrandbits(i) с повтором до установленного старшего бита.** Это отличается и от принудительной установки бита, и от randrange по ширине 2^(i-1), где отбрасывается противоположная половина предложений. Заранее определить, расходуется ли вызов для №1 и как выполняются пропуски. Отдельная модель, не новая интерпретация E2b.

3. **Повторное seeding для каждой задачи.** Только конкретные формулы, например seed+i или seed XOR i, с заранее указанным началом индекса и без/с модулем 2^32. Общий отрицательный результат для непрерывной последовательности не распространяется на reseeding. Основание выбирать эту ветку должно быть сильнее произвольного увеличения числа формул.

4. **Временной seed вне 32 бит.** Для fallback int(time.time()*256), миллисекунд или микросекунд сначала установить обоснованное историческое окно и конкретный путь инициализации. Обычный random.Random(None) в изученных версиях предпочитает os.urandom: проверка timestamp не проверяет этот обычный путь. Без подтверждения временной слабости расширять диапазон до всех больших integer мало обоснованно.

5. **Низкоуровневый _random.Random(None).** В C-ветке seeding используется init_genrand от времени, в отличие от стандартной Python-обёртки с init_by_array. Это отдельный API; отрицательный результат стандартного integer seeding его не исключает. Публичные сканеры с scalar MT seeding нужно оценивать именно для этой модели, учитывая их реальный порядок слов и подтверждённое покрытие.

6. **Строковый seed там, где он не сводится к seed32.** Python 3.4 version=2 использует строку вместе с SHA-512; Linux x86_64 Python 2.7 может использовать 64-битный хеш. Нужен конкретный словарь/формат с историческим основанием. Перебирать слова для Windows Python 2.7 при тех же 96 схемах после полного отрицательного E2b бессмысленно: соответствующие состояния уже входят в проверенные seed32.

Не переносить результат ни одной из этих будущих проверок на системную энтропию, произвольные дополнительные преобразования или все программы Python. При отсутствии конкретного исторического основания разумнее искать исходный генератор/кошелёк, чем перебирать бесконечные варианты использования random.

# E2b: полное расширение проверки Python завершено

Запуск `20261030-105921-2f40f0fd`. **Все 4 294 967 296 целочисленных seed проверены для 120 фиксированных схем. Ни один не воспроизвёл известные ключи №1–12.** Следовательно, ни один не воспроизведёт все №1–50/отложенные решения в этих схемах. Кандидата №71, определённого неизвестного бита или XOR не получено.

E2b содержит 120 физических конфигураций API/шага/смещения; одинаковое поведение двух версий не пересчитывается как разные семейства. Полная спецификация: замороженный протокол — артефакт исходного исследования (`code/PROTOCOL.md`; вне снимка). Число проверок seed–схема: **515,396,075,520**; это не столько различных seed и не столько независимых гипотез. Небольшое прежнее покрытие E2 повторено как часть объединённого сканера и не прибавляется к общему пространству.

## Проверяемость

- 518 400 исторических значений сопоставлены с независимой Python-арифметикой на 135 последовательных puzzle; 57 594 доступных префиксных значений сверены CPU/GPU. Два переполнения ограниченного буфера в векторах явно отмечены и согласуются на CPU/GPU.
- Все 120 синтетических схем восстановили seed 42421 и на CPU, и на GPU. Проверены отрицательные наблюдения, передача переполнения вместо отбрасывания и крайние seed 2^32−1/2^32.
- 1024 непересекающихся блока точно покрывают `[0,2^32)`, каждый имеет SHA-256. Сверены 2061 хешей артефактов запуска.
- Проверены остановка/продолжение с одного готового блока и повторный resume завершённого запуска: все 1024 блока пропущены, хеши и время изменения сохранены.
- На изолированных копиях проверено отклонение повреждённого checkpoint, повторного интервала и изменённых входов; превышение ёмкости списка кандидатов инвалидирует весь GPU-блок. Артефакт — артефакт исходного исследования (`INTEGRITY_CONTROLS.json`; вне снимка).
- Приёмка — артефакт исходного исследования (`ACCEPTANCE.json`; вне снимка), машинное покрытие — артефакт исходного исследования (`SUMMARY.json`; вне снимка), промежуточный журнал — артефакт исходного исследования (`EVENTS.jsonl`; вне снимка), контроли — артефакт исходного исследования (`../../validation/VALIDATION.json`; вне снимка), [история выводов](<../../NOTES.md>).

Сумма времени внутри сканера: **579.997 с**; включает вычисление, выделение памяти и передачу результатов, но не запуск процесса/CUDA-контекста и ведение отчёта. Сумма сессий supervisor, включая прерванную по отметкам журнала: **1668.593 с**. От создания ID до последнего блока: 1793.530 с, включая паузы управления. Подготовка/валидация указаны отдельно в validation. GPU — локальная RTX 3070 Ti Laptop; показатели этого MT-сканера нельзя сравнивать со скоростью перебора Bitcoin-адресов.

Один сеанс прерывался из-за временной блокировки Windows при замене SUMMARY.json. Все готовые блоки сохранились. Продолжение использовало обёртку повторной записи — артефакт исходного исследования (`continuation/resume_robust.py`; вне снимка), не меняя замороженный вычислительный код/входы. Число уже сохранённых блоков без последующей записи block-complete в EVENT из-за прерывания: 1; их хеши и покрытие проверены по файлам. Это эксплуатационная ошибка отчётности, а не отрицательный результат вычисления.

## Дополнительные обоснованные выводы

1. **Windows CPython 2.7.9: охвачены и нецелочисленные seed, сводимые к хешу**, включая строки и float. Исходники сводят их к unsigned long из 32 бит. Поэтому полный перебор integer seed32 охватывает все получаемые так состояния для соответствующих 96 схем Python 2.7.9. Это вывод по исходникам, а не исполнение Windows runtime и не перебор словаря: [точное доказательство и ограничения](<../../SEED_DOMAIN_AUDIT.md>).
2. **Три конкретные float-конструкции исключены при любом seed** обязательной кратностью: первая противоречит №2, вторая №56, третья №54. Формулы, границы вывода и код: [арифметический отчёт](<../../PRECISION_EXCLUSIONS.md>).
3. **Соседние Python 2.7.8 и 3.4.1 имеют те же использованные алгоритмы**: у 2.7.8 оба файла совпадают побайтно, у 3.4.1 совпадают C-ядро и AST вызываемых методов, а отличие обёртки относится к неиспользуемому triangular(). Это перенос по исходникам, без отдельного исполнения runtime: [сопоставление](<../../ADJACENT_VERSIONS.md>).

## Что остаётся открытым

Не исключены обычный seed(None) с системной энтропией, большие integer seed, fallback int(time.time()*256), стандартные строковые seed Python 3, 64-битные хеши Python 2 на Linux, другие начальные смещения/расход выходов, reseeding между задачами, другие преобразования и версии. Прямой низкоуровневый _random.Random(None) использует другую ветку seeding; его нельзя отождествлять с обёрткой random.Random(None).

Следующий содержательный шаг требует отдельной конечной гипотезы. [Список будущих экспериментов](<../../FUTURE_EXPERIMENTS.md>) включает непроверенные побайтовые/посимвольные способы, другой rejection sampling, reseeding и обоснованные большие seed. Увеличивать прежний малый integer диапазон для тех же 120 схем больше не нужно: seed32 уже покрыт полностью. Ни существование полезного сигнала по HASH160, ни его невозможность из этого результата не следуют.

## 2026-10-30 — предварительная проверка ограниченного буфера

До настоящего поиска векторы обнаружили нормальный выход за 624 слова для некоторых длинных последовательностей randrange с отклонениями. Сканер уже передавал такие случаи на полную проверку (reason=2), но тест векторов ошибочно требовал вместить каждую последовательность в один блок MT. Исправлен формат векторов: проверяется каждый доступный элемент, остаток явно null, статус переполнения сверяется CPU/GPU. Переполнение не является несовпадением seed. Первые 518400 значений исторических API уже совпали с независимой арифметикой; весь допуск повторяется после исправления.

## 2026-10-30 — дополнительный аудит пространства seed

[Аудит исходников](<SEED_DOMAIN_AUDIT.md>) доказывает включение строковых/float и других успешно хешируемых нецелочисленных seed Windows CPython 2.7.9 в полный integer seed32. Это условное расширение интерпретации будущего полного результата для соответствующих 96 схем, а не изменение GPU-поиска. Windows runtime не запускался; типы и переход от хеша к init_by_array проверены по официальному commit. Обычный seed(None) — отдельный большой integer из os.urandom, он этим не охвачен. Материалы сохранены в source-domain-audit с хешами.

[Арифметическое дополнение](<PRECISION_EXCLUSIONS.md>) исключает три точно заданные float-схемы независимо от seed. Первые противоречия: №2, №56, №54. Научная новизна не заявляется.

CUDA compute-sanitizer в локальной установке отсутствует; проверка им не выполнялась и не считается пройденной. Допуск основан на независимых исторических векторах, CPU/GPU восстановлении, отрицательных и граничных контролях.

## 2026-10-30 — соседние исторические версии

[Сопоставлены официальные исходники 2.7.8 и 3.4.1](<ADJACENT_VERSIONS.md>). В 2.7.8 оба файла RNG и обёртки побайтно совпадают с 2.7.9. В 3.4.1 C-ядро совпадает с 3.4.2, AST используемых __init__/seed/randrange/randint/_randbelow совпадают; единственное отличие обёртки относится к triangular(), который не вызывается. Это перенос поведения по исходникам, не отдельное исполнение дополнительных runtime. Commit, SHA-256 и diff сохранены; исходные результаты исторических интерпретаторов не переписаны.

## 2026-10-30 — продолжение после Windows sharing violation

На 716 готовых блоках (3003121664 различных seed) Windows отказал в атомарной замене SUMMARY.json во время параллельного чтения файла. Один блок успел сохраниться с SHA-256 до ошибки отчёта, поэтому соответствующего block-complete в EVENT нет. Научное покрытие определяется сохранёнными блоками и хешами, не числом строк логов.

Создана отдельная I/O-обёртка resume_robust.py с повтором записи при PermissionError; её снимок и хеш записываются в continuation/EVENTS. Замороженный сканер, протокол, конфигурации и study.py не изменены. Продолжение пропускает все 716 готовых блоков. Во время записи больше не читается mutable SUMMARY.json внешним Get-Content; мониторинг использует завершённые иммутабельные блоки.

## 2026-10-30 — полный E2b завершён

Запуск 20261030-105921-2f40f0fd полностью покрыл [0,4294967296) для всех 120 схем: 1024 блока, 515396075520 проверок seed–схема, ноль кандидатов даже фильтра №1–12. Это 4294967296 различных seed, а не 515 млрд разных seed. Все эти конечные схемы с seed32 исключены; бит/XOR №71 не получен.

Продолжение после ошибки отчёта пропустило 716 блоков и вычислило оставшиеся 308. Заключительный resume пропустил все 1024 без изменения хешей и mtime. Полное покрытие позволяет применить ранее записанный вывод по исходникам о Windows Python 2.7.9: хешируемые нецелочисленные seed также входят в проверенное множество состояний для соответствующих 96 схем. Большие integer, системная энтропия и другие схемы остаются открытыми. Итоговая приёмка и числовой отчёт формируются только из сохранённых артефактов; прошлые записи сохраняются.

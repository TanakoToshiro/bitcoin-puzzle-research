# RND-01 — журнал исследования

## 02.11.2026 — выбор кошелька и первичные снимки

Выбран официальный Blockchain.info My Wallet, срез29.12.2013 commit031863d30590754f5d02fc10488236b1dc30f7f7. Сохранены также ближайшие предшествующие01.01.2013 и15.01.2015 снимки для проверки версионных различий. Названия файлов2013/2014/2015 обозначают **границу выборки**, фактические даты соответственно25.12.2012/29.12.2013/07.01.2015. Coinpunk рассматривался при поиске, но не выбран: официальный архив My Wallet доступен и позволяет проследить цепочку по первичным источникам.

Подтверждены штатные вызовы _seed → ECKey(false) → ECDSA.getBigRandom → JSBN → общий SecureRandom/RC4. В пути создания ключа не найден HD-master/BIP32: каждый ключ забирает следующий участок общего потока. Пароль служит дополнительным входом pool, это не словарный brainwallet-поиск.

## 02.11.2026 — предварительные существенные различия

Срез2013 использует getRandomValues(Int32Array32) при наличии, иначе128 вызовов Math.random для256байт. Перед созданием ключа _seed подмешивает время, SHA256 пароля и extra_seed с сервера/DOM, если доступны. После первого запроса RC4 rng_state не пересоздаётся, дальнейшее смешивание pool по чтению кода не должно влиять на поток; требуется динамическая проверка. UI клики/клавиши/мышь также меняют pool до первого запроса. Известность адреса не означает наблюдаемость значений Math.random.

Срез2012 ещё содержит старую ветку Netscape4 window.crypto.random и игнорирует современный getRandomValues в проверенном rng-коде. Срез07.01.2015 уже содержит seed_large_int32_array, _window.msCrypto и проверки pool. Это разные реализации; нельзя описывать весь период2011–2015 одной32-битной моделью.

В V8 3.22.24 найдено **18273/36969 и сложение (state0<<14)+(state1&0x3ffff)**. Это отличается от распространённой упрощённой записи36969/18000 и конкатенации16+16. Проверяется также инициализация и x64-ветки; современный Math.random в контроли подставляться не будет.

HTTP404 для README.md записаны в SOURCES.json; архивные корни не содержат этих предполагаемых файлов. Загрузки первичных исходников проходят отдельно, старые проекты/процессы не затрагиваются.

## 02.11.2026 — динамические контроли пройдены

24 сценария,115 синтетических ключей,230 адресов,23 affine-проверки,21 полная независимая pool-реконструкция.19 утверждений о влиянии входов прошли. minified/nonminified основной bundle совпал на контрольных пяти ключах. Контролируемый getRandomValues дал0 обращений к Math.random в основном срезе. Старый2012-код игнорирует современный getRandomValues при заданном navigator;2015 raw-вызов без seed_large блокируется с ожидаемой ошибкой. Этот отказ является положительным контролем и не числится неудачным экспериментом.

Воспроизведено:33байта на ключ, первый отбрасывается, затем modulo(n−1)+1; общий поток для новых объектов SecureRandom. Изменение ранних входов меняет ключи; позднее _seed не меняет RC4. Раннее искусственное потребление делает последующие пароль/server seed неэффективными; реальная достижимость такого порядка UI пока не доказана.

## 02.11.2026 — уточнение состояния V8 и пределы

Первоначальная запись о двух32-битных словах не равна оценке64битной энтропии: bootstrap V8 получает8байт из per-isolate48битногоLCG. Проверены маска/переход и106 Python/JS BigInt примеров. Начальное семейство при фиксированном bootstrap задаётся максимум2^48 состояниями; это не полный размер wallet-пространства. Источники начального seed могут быть callback/rand_s/urandom/time, после чего значение всё равно сводится к48битам. Современный Node Math.random не использовался.

Дополнительный предполагаемый Chromium32-путь Crypto.cpp дал404, ошибки сохранены отдельно. Это не основание считать API отсутствующим в том браузере. Наличие WebCrypto конкретной исторической сборки остаётся отдельным вопросом; в итоговом отчёте ветки сформулированы условно. Старый серверный файл2012 содержит SecureRandom для2FA — не доказательство алгоритма extra_seed2013.

## 02.11.2026 — приёмка и решение

Cache проверен с запретом subprocess: выполненные результаты сохранили hash/mtime.457 файлов старого E12 неизменны. Числовой отчёт пересобирается без вычислений, интерпретации сохранены отдельно. Реальные puzzle-ключи не использовались, поиск/аренда не запускались. Получена модель цепочки, но пока нет обоснованного маленького пространства для её перебора. Следующий этап при продолжении: конкретная историческая браузерная конфигурация и доказательство порядка/входов до первой KSA, затем синтетическое восстановление по маскированным ключам.

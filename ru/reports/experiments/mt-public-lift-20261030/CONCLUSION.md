# E1f — можно ли использовать связи E1e только по публичным точкам?

Завершено 2026-10-30. Run `20261030-175549-2d8c4a6e`. [Команды](<README.md>), [журнал](<NOTES.md>), [точные формулы](<DERIVATION.md>).

**Для исследованного способа подъёма E1e практического выигрыша не получено.** При этом показан работающий публичный алгоритм для действительно малой XOR-поправки: он извлекает нужные биты без знания полного верхнего приватного ключа. Причина неудачи на E1e конкретна: простое арифметическое тождество отсутствует, а найденные остаточные зависимости не допускают проверенную малую линейно-параметризованную поправку. Это не доказательство невозможности других нелинейных методов.

## Что проверено на готовых данных E1e

Прочитаны итог E1e, все 5566 сохранённых выбранных уравнений, SMALL_UPPER_SETS.csv и результаты E6H. Исходные MT-матрицы не пересчитывались: новые вычисления — постобработка сохранённых строк. Выбраны три модели начальных примеров и одна pre_increment-модель. Это 4 конкретные ветви, не все 40 ветвей E1e. В каждой рассмотрены все 173 неизвестных скаляра и 101 доступная публичная точка среди них.

Биты представлены как аффинные GF(2)-формы. Затем полные числовые скаляры разложены по характерам χ=(-1)^parity над F_n. Независимость характеров позволяет одним рангом проверить **все фиксированные коэффициенты modulo n** в равенстве Σ aᵢkᵢ=c, включая все линейные комбинации прежних строк.

|---|---:|---:|---|---:|
| fixed-reverse-big-s1 | 173/173 | 321 | 161,162 | 71,170,226: 432 |

Полный ранг означает: целевую точку нельзя получить универсальной фиксированной линейной комбинацией остальных точек и G в этих семьях. Это не запрещает коэффициенты, полученные нелинейным анализом конкретных точек, и не запрещает отдельные специально отобранные подсемейства.

Проверены 20200 пар и 20478 классов сокращения характеров. Для нескольких точек использованы глобально частные характеры: их нельзя сократить добавлением других столбцов. После дешёвого предварительного отбора потребовалось 63 проверки троек; только две оставались неясными. Для них все коэффициенты точно охвачены расположением двух прямых сокращения: фактические минимальные ранги 458 и 461. Наборы из четырёх и более отсечены монотонной оценкой, без перечисления всех наборов или состояний.

**Итог этой проверки:** у любой комбинации двух или более доступных публичных скаляров в четырёх выбранных семьях ранг линейной параметризации поправки не меньше 140. Малая поправка из ≤32 независимых двоичных параметров, пригодная для выбранного алгоритма, исключена. Для формулы с №71 и любой непустой комбинацией доступных публичных скаляров отдельные нижние оценки ранга — 180, 144, 115 и 178 соответственно.

Эти числа **не являются энтропией поправки или нижней границей для любого алгоритма**. Функция многих параметров может принимать мало значений; например, AND нескольких битов имеет большой ранг Fourier-поддержки, но только два значения. Мы не доказали нижнюю границу числа различных числовых поправок. Прямое перечисление именно полученных параметров имело бы 2^r назначений; обычный полный MITM по двум разделимым половинам — порядок 2^(r/2). Для произвольного Walsh-полинома даже такая разделимость не гарантирована. По этой параметризации выигрыша показателя относительно прямого поиска 70-битного остатка №71 не получено.

## XOR, маскирование и pre_increment

`x XOR y = x+y−2(x AND y)` — точное целочисленное равенство, также верное modulo n. Но по xG,yG неизвестна точка (x AND y)G. Отбрасывание битов при сдвиге также оставляет неизвестный остаток; это не операция над точкой, доступная бесплатно.

Для pre_increment использовано точное `k=2^w+x+1−2^w·[x=2^w−1]`. Переполнение не игнорировалось: отрицательная проверка сделана на непустом аффинном срезе с гарантированно нулевым индикатором. №256 дополнительно ограничен внутри 1..n−1. Тождество всей семьи обязано существовать и на таком срезе; его отсутствие на срезе достаточно для указанного отрицательного вывода. Срез не считается новым наблюдением реальных ключей.

## Публичный алгоритм, который действительно срабатывает при малой поправке

В положительном контроле X=2^w+x, Y=2^w+(x XOR C), C — известная маска с r единицами. Алгоритм получает только QX,QY,C и HASH160 цели. Он вычисляет

`D = QX−QY+C G = 2(x AND C)G`

и решает subset-sum по r известным точкам 2^(j+1)G, деля позиции пополам. Восстанавливаются только выбранные r битов, из них строится целевая точка и проверяется HASH160. Остальные w−r битов не передаются алгоритму и не восстанавливаются. Работа/память — O(2^ceil(r/2)) плюс подготовка. Для этой конкретной модели соответствие поправки выбранным битам однозначно: диапазоны малы относительно n.

18 случаев выполнены на secp256k1 с уменьшенными диапазонами. Независимые сравнения — interval BSGS верхнего X и прямой поиск цели по HASH160. Baseline выбран заранее по ведущей худшей оценке, а не по удачности конкретного x. Оба метода измерены; два повтора не дают статистически устойчивого временного бенчмарка. Основной счётчик — вызовы сложения, включая удвоения и нейтральный элемент; нетривиальные операции кривой, удвоения и хеши дополнительно приведены отдельно в CSV.

## Контроль смешанных XOR-членов

Дополнительно проверена более сложная модель Y=2^w+(x XOR ((x<<s) mod 2^w)). Поправка теперь неизвестна, простой split не работает: нужно фиксировать s граничных битов. После этого выполнен точный MITM по групповой разности, с обязательной проверкой кандидатов по QX — совпадение одной поправки ещё не доказывает правильность скрытых значений.

64 исчерпывающих малых контроля и 12 свежих сравнений прошли. Оценка работы по назначениям — O(2^((w+s)/2)) плюс проверки коллизий, память O(2^((w−s)/2)). Уменьшение памяти оплачивается дополнительными назначениями. Метод находит полный верхний x, поэтому не реализует желаемый обход его восстановления. Независимый BSGS имеет показатель w/2. Отдельное раннее совпадение иногда выгодно по числу операций, но улучшения показателя нет.

## Что именно установлено и что осталось открытым

1. Универсальный линейный арифметический подъём с фиксированными коэффициентами modulo n для выбранных четырёх семей исключён точным рангом.
2. Испытанный подход малой поправки работает по публичным точкам в положительных контролях; в E1e необходимой структуры не найдено. Наблюдавшиеся сокращения 70→39, 70→2, 70→0 сами по себе не дают нового алгоритма по публичным точкам.
3. Совместные ограничения могут давать выигрыш при специальной структуре. Для E1e не получено ни целевой публичной точки, ни нового ключа/бита, ни нового опровержения генератора. Нелинейные алгоритмы, компрессия множества числовых значений поправки, специальные подсемейства и другие ветви E1e остаются открытыми.

## Будущие эксперименты — не выполнены

1. Проверить возможность маломощного множества **числовых** поправок, не выводя его мощность из Fourier-ранга. Нужна структурная оценка или алгоритм, а не перебор всех состояний.
2. Исследовать нелинейные ограничения на конкретных опубликованных точках и специальные совместимые подсемейства с независимым контролем выигрыша. Текущий отрицательный результат их не исключает.
3. Перенести точный арифметический аудит на другие ветви E1e только при новом обоснованном предположении; простое увеличение числа точек или размера прежнего MITM не является новым методом.

# E1f — журнал промежуточных выводов

## 2026-10-30 — прочитанные предшественники и выбранная постановка

E1e `20261030-150813-643fdd30`: прочитаны итог, все 5566 записей MIXED_EQUATIONS.json (72 joint, 5487 transfer, 7 pair71) и SMALL_UPPER_SETS.csv. E6H уже проверял совместный MITM общего chaincode; увеличение числа переходов не улучшало показатель сложности. Эти цепочки и их вычисления не повторяются.

Новая гипотеза: если арифметическая комбинация полных скаляров имеет малую неизвестную поправку, соответствующая комбинация публичных точек может раскрыть поправку без полного восстановления верхних скаляров. Проверяются сначала возможность точного подъёма modulo n и размер поправки, затем публичный алгоритм на положительных/отрицательных уменьшенных примерах. Нельзя заменить XOR сложением или считать извлечение нужных битов верхнего ключа бесплатным.

## 2026-10-30 — точный арифметический тест

Новый запуск `20261030-175549-2d8c4a6e`. Из четырёх готовых матриц E1e получены разложения битов на свободных двоичных координатах и разложения полных скаляров по характерам χ=(-1)^parity над F_n. Проверка арифметических линейных зависимостей охватывает все коэффициенты modulo n и все 173 неизвестных скаляра; это не перебор избранных GF(2)-строк.

Для каждой из четырёх ветвей ранг равен 173. Значит, универсального арифметического равенства с фиксированными коэффициентами, позволяющего выразить один из неизвестных полных скаляров через остальные и константу, на этих семьях нет. Для pre_increment использован непустой срез без переполнения +1, для №256 — срез внутри допустимых скаляров. Отрицательный результат на срезе исключает тождество на всей семье; он не исключает отдельные полезные подсемейства или нелинейные алгоритмы на конкретных публичных точках. Исходные MT-матрицы не строились повторно и не изменялись.

## 2026-10-30 — поправки двух и нескольких публичных скаляров

Для 101 доступной публичной точки просмотрены все 5050 пар в каждой ветви. Для каждой пары рассмотрены все возможные типы оставшихся характеров при ненулевых коэффициентах: сокращения возможны только при конкретных отношениях коэффициентов. Всего 20478 классов поддержки. Минимальные ранги поправок для верхних №161–256: 321 (standard), 281 (forward), 163 (bits_i), 317 (order3 на срезе). Это ранг зависимостей от двоичных параметров, не число бит энтропии скаляра; значение скаляра modulo n не может содержать более примерно 256 бит информации.

Дополнительный постанализ, зафиксированный до вычисления соответствующих троек: глобально частные характеры каждого скаляра не могут сократиться при добавлении других скаляров. По ним проверены все пары, затем только треугольники графа с рангом пар <140; потолок — 10000 троек. В трёх ветвях таких треугольников нет. В bits_i: 49 слабых пар, 63 тройки; только две тройки не отсеклись этой нижней оценкой: (164,191,200), (164,194,200), с частными рангами 139 и 137.

Для этих двух исключений выполнен точный анализ всех коэффициентов тройки через расположение прямых сокращения над F_n. В каждом случае лишь две различные прямые и три представителя классов; минимальные фактические ранги 458 и 461. Корректность перечисления классов дополнительно проверена полным перебором 120000 пар коэффициентов над малым нечётным полем и контролем с известным тождеством.

Любой набор из четырёх столбцов содержит четыре различные тройки, а исключительных частных троек всего две. Поэтому наборы из четырёх и более также имеют частный ранг ≥140. Вместе с точным анализом пар и двух троек это даёт ранг поправки ≥140 для **любой** комбинации как минимум двух доступных публичных скаляров в четырёх выбранных семьях. Это препятствие линейно-параметризованному перечислению поправок, а не универсальная нижняя граница вычислительной сложности. Ранг сам по себе не гарантирует MITM за 2^(r/2): смешанные характеры могут не разделяться.

## 2026-10-30 — публичный алгоритм действительно работает при малой поправке

Положительная модель: X=2^w+x, Y=2^w+(x XOR C), маска C публична. Тогда QX−QY+C G=2(x AND C)G. MITM восстанавливает только r=popcount(C) выбранных битов; остальные w−r битов x алгоритму не передаются и не нужны для целевого HASH160. Алгоритмы запускаются отдельными процессами через JSON с публичными данными; истинные x,y текущего случая сохраняются проверяющим кодом лишь после завершения процессов.

Все 18 случаев основной серии прошли. При w=28,r=20 MITM использовал 1512 и 1201 сложений против 23880 и 19916 у заранее выбранного BSGS: примерно 16-кратное уменьшение числа операций. Пик Python-памяти около 135 КБ против 2.19 МБ. Прямой поиск целевого HASH160 измерен отдельно. При маленьких r накладные расходы и раннее попадание прямого перебора могут сделать его быстрее; такие результаты сохранены. При r=w преимущества по показателю нет. Этот положительный контроль не переносится на E1e: требуемая малая поправка там не обнаружена.

## 2026-10-30 — дополнительный контроль смешанных XOR-членов

После основной серии, до новых вычислений, сохранён [SEPARATOR_PROTOCOL.md](<SEPARATOR_PROTOCOL.md>): Y=2^w+(x XOR ((x<<s) mod 2^w)), неизвестная поправка. Для MITM приходится фиксировать s граничных битов. Стоимость назначений O(2^((w+s)/2)), память O(2^((w−s)/2)); коллизии поправок дополнительно проверяются по QX. Это не ожидаемое ускорение: проверяется конкретная причина, почему произвольный XOR не позволяет бесплатно разделить поиск пополам. 64 малых исчерпывающих контроля пройдены до серии; результаты 12 свежих задач сохраняются в `separator/`.

## 2026-10-30 — завершение и границы результата

Основная серия 18/18 и дополнительная 12/12 завершены. В XOR-со-сдвигом медианы числа сложений по парам повторов составили 419.5/651.5/1636.5/1384.5/5121.5/5299 против 118.5/150.5/461/494.5/1815.5/1919.5 у BSGS: примерно 2.8–4.3 раза больше операций в этих группах. Один отдельный ранний успех был дешевле BSGS; это не улучшение показателя сложности. Память при больших ширинах меньше, но алгоритм в итоге восстанавливает полный верхний x. Это конкретное препятствие проверенного метода, не утверждение об оптимальности BSGS для любых совместных ограничений.

Независимо проверены все 115492 приведённых бита по исходным строкам с противоположным порядком ведущих битов; все четыре треугольных свидетельства ранга 173; все 20200 пар рангов частных форм и все 404 оценки переноса на №71. По коэффициентам каждой исключительной тройки выполнена отдельная проверка. Приёмка: 26 основных контрольных точек, повторный run выполнил 0 новых стадий, 286 файлов неизменны, первые три файла исходной остановки сохранились; публичный replay воспроизвёл результат и точные счётчики. SHA-256 и mtime всех 20 входов, включая четыре исходные матрицы E1e, не изменились.

Отрицательный вывод ограничен универсальными фиксированными арифметическими комбинациями и выбранным способом перечисления поправок через линейные двоичные параметры. Высокий Fourier-ранг **не доказывает** большое число различных числовых значений поправки: даже AND многих битов принимает два значения. Компрессия числового множества поправок, нелинейные алгоритмы на конкретных точках и другие ветви E1e остаются открытыми. Новый реальный ключ, бит или публичная точка №71 не получены.

# E1e: MT19937 и исходные 256 адресов

Проверка завершена: [итог и границы вывода](<CONCLUSION.md>), [журнал](<NOTES.md>). Run `20261030-150813-643fdd30`: 40/40 ветвей, 32/32 синтетических моделей; 4 конкретные истории отвергнуты публичной точкой, нового приватного ключа нет.

Продолжение E1d с неизменными 83 опубликованными решениями. Верхние №161–256 включены в анализ независимо от баланса. Данные заморожены в `runs/<ID>/inputs`; свежие балансы для расчёта не нужны. [Предварительная оценка](<ASSESSMENT.md>) сохранена отдельно; [протокол](<PROTOCOL.md>) фиксирует фактический объём.

Проверяются 40 ветвей из 32 конфигураций. Все 173 неизвестных ключа рассматриваются по отдельности и совместно. L — 77 неизвестных номеров ≤160, U — 96 номеров >160. Число независимых смешанных ограничений равно `d(L)+d(U)−d(L∪U)`. `d(i|U)` означает остаточную размерность при гипотетическом знании числовых приватных ключей U. Публичные точки сами по себе не предоставляют эти значения. Все равенства условны относительно модели генератора и, где применимо, выбранной истории отклонений randrange.

Варианты `order` используют координату `(key−1) mod 2^(i−1)`. XOR этих координат нельзя автоматически читать как XOR битов исходного key. Для №256 отдельно учитывается верхняя граница порядка secp256k1. Если после её применения сохраняется больше половины аффинного пространства, его линейная оболочка остаётся прежней; это не утверждение, что остаются все исходные допустимые комбинации.

## Артефакты

- `RESULTS.md` — автоматически обновляемый индекс запусков; внутри каждого запуска — таблица завершённых ветвей.
- `NOTES.md`, `CONCLUSION.md` — датированные интерпретации и итог; прежние записи не переписываются.
- `MODEL_SUMMARY.csv`, `ALL_TARGETS.csv`, `TRANSFER_FROM_UPPER.csv`, `PAIRS71_UPPER.csv` — числовые результаты из завершённых стадий.
- `BASELINE_COMPARISON.csv` — отличие от E1d; дополнительные условия истории не являются информацией из публичных точек.
- `SMALL_UPPER_SETS.csv/.json`, `small-upper-sets/` — дополнительный точный расчёт переноса на №71 от небольших групп старших номеров, выбранных по коротким строкам сохранённого базиса. Команда `small_sets.py ID`; выбор групп разведочный, поиск не исчерпывающий.
- `MIXED_EQUATIONS.json` и `.md` — выбранные короткие строки сохранённого базиса, включая связи с №71; это не глобальный поиск уравнений минимального веса.
- `tasks/<ветвь>/matrix.bin`, `native.cert`, `native.json`, `layout.json` — все исходные строки, точные сертификаты, размерности и подписи переменных.
- `SCALAR_DOMAIN.json`, `SMALL_SPACE_CHECK.json`, `WITNESSES.json` — граница скаляра, исчерпывающая проверка малой проекции и проверка отдельных состояний.
- `MATRIX_READY.json`, `NATIVE_DONE.json`, `DONE.json` — отдельные контрольные точки. Несовпадение произвольного свидетеля не опровергает всю ветвь; полный перебор её проекции — опровергает, если ни одного совпадения нет.

Формат `native.cert`: заголовок `<8s3I>` (`MTCERT1\0`, P, A, T), далее записи `<4I>` (тип, номер, второй номер, RHS) и P слов uint64 little-endian. Биты доказательства 0..A−1 обозначают строки наблюдений, A..A+T−1 — целевые строки. Их XOR обязан дать нулевой вектор состояния, RHS наблюдений — заявленную константу. `begin/end` — номера записей с нуля, правая граница исключена. Для единственного состояния полный ранг A и его прямое исполнение заменяют огромный список поразрядных сертификатов; это отмечено `unique_state`.

## Продолжение

Сначала прочесть `CONCLUSION.md`, `NOTES.md` и состояние запуска. Новые истории отклонений, иные модели, реальные новые решения или использование нелинейных групповых уравнений требуют отдельного эксперимента с новым входом. Сам факт наличия большого числа XOR-связей ожидаем при числе целевых битов, превышающем размерность MT, и не подтверждает происхождение puzzle от MT19937.

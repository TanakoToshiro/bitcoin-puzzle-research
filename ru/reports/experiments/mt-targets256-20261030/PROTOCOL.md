# E1e: исходные 256 адресов и перенос информации со старших номеров

Зафиксировано 2026-10-30 до основных вычислений. Продолжение E1d; старые эксперименты неизменны. Данные: 256 адресов и публичные точки проверенного E5, 83 числовых решения прежнего снимка. Цели: 173 неизвестных ключа, 28873 непринудительных бита. №161–256 включаются независимо от отсутствия награды.

## Конечный объём

Сохранить все 40 ветвей E1d (32 конфигурации). Продолжить те же исходные состояния и числовые API до №256. В randrange сохраняются условия E1b до №135, затем выбираются допустимые условия естественного продолжения сохранённого свидетеля, как в E1d. Это предположенная история, не новые наблюдения. В order-схемах линейная координата — (key−1) mod 2^(i−1); переносы при +1 не заменяются XOR.

Для каждого варианта:

1. Проекция каждого из 173 неизвестных остатков: размерность, фиксированные биты, все независимые ограничения.
2. Проекции L (77 неизвестных №1–160), U (96 номеров №161–256), L∪U. Число дополнительных смешанных ограничений — d(L)+d(U)−d(L∪U). Подсчёт количества уравнений с обоими типами переменных в произвольном базисе не заменяет эту инвариантную величину.
3. Для каждого младшего неизвестного i вычислить d(i|U), оставшееся при гипотетическом знании числовых верхних ключей. Разница d(i)−d(i|U) показывает потенциальный перенос информации; верхние скаляры в действительности неизвестны.
4. Для №71 отдельно все 96 пар (71,j), j=161..256: d(71|j), число дополнительных ограничений и точные уравнения. Сохранить краткие смешанные формулы и формулы переноса для каждого младшего номера.
5. Сопоставить ранги нижних ключей с E1d. Изменения от дополнительных guard-условий №161–256 не выдавать за информацию, полученную из публичных точек.

Линейные отношения сохраняются с provenance: комбинация исходных строк A и целевых строк даёт нуль, RHS равен заявленному значению. Числовые таблицы строятся из артефактов. Равенства после сведения к известным RHS не являются безусловным подтверждением модели создателя.

## Скалярный диапазон и публичные точки

Для №256 проверить k<n_secp256k1. Из аффинной проекции нормализованного остатка точно подсчитать допустимые/недопустимые значения через непересекающиеся префиксы двоичного сравнения. Для order учесть +1 mod 2^255. Если отсечено менее половины состояний, линейная оболочка допустимого множества остаётся прежней, но это не означает полноту нелинейного множества значений. Не объявлять недопустимый скаляр приватным ключом.

Публичные точки проверяются отдельно по SEC/кривой/адресам и числовым кандидатам. Они не подставляются как известные приватные биты в GF(2). Для каждого полного предсказания d=0 проверять адрес/точку: несовпадение исключает всю эту ветвь, в отличие от несовпадения одного произвольного свидетеля при d>0.

Дополнительная конечная проверка: если после GF(2) какая-либо цель имеет d≤16, выбрать одну цель с минимальным d (предпочесть опубликованную точку), перебрать её полную аффинную проекцию и проверить по точке/адресу. Неудача исключает данную фиксированную ветвь. Совпадение независимо проверить secp256k1; не начинать большой перебор остальных пространств. При найденном настоящем ключе его дальнейшее использование требует отдельной зафиксированной стадии с новым входом.

## Вычисления и контроли

Точная арифметика GF(2), CPU. Нативное C++-ядро для больших матриц, без изменения математических моделей. До реальных данных: малые случайные и исчерпывающие системы, отрицательные и вырожденные примеры, fixed-bit/XOR/mixed-only, проверка пар и transfer-размерностей относительно Python; сравнение с завершёнными сертификатами E1d. В основном запуске проверять ранги противоположным pivot-порядком и сертификаты прямым суммированием исходных строк.

Символические карты до №256 сверяются с числовым MT; реальные свидетели и допустимые синтетические состояния — с историческими Python 2.7.9/3.4.2. При единственном состоянии не требовать нескольких разных свидетелей. Исторические runtime-вызовы сериализовать, чтобы избежать гонки восстановления WSL, обнаруженной в E1d.

Каждый этап получает checkpoint с SHA-256. Сохранить параметры, код и бинарник ядра/компилятор, данные, промежуточные матрицы, сертификаты, результаты, ошибки, README/RESULTS/NOTES. Поддержать create/resume/report/verify, пропуск готовых стадий, повреждение копии, пересборку отчёта. Неполное вычисление обозначать как неполное. GPU-перебор не входит в этот этап.

## Будущие эксперименты

Пересечение разных историй, использование групповых уравнений публичных точек, независимая проверка происхождения генератора, новая стадия при подтверждённом приватном ключе. Эти задачи не подменяются большим числом автоматически возникающих XOR-связей.

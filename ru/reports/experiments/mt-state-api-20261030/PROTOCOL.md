# E1b: состояние MT при исторических API, обрезке и скрытых отклонениях

Зафиксировано 2026-10-30 до применения новых моделей к приватным решениям. Исследование без перебора seed. Произвольное ненулевое достижимое состояние MT19937: 19937 координат до twist, как в проверенном E1. Основные проекты и прежние эксперименты не меняются.

## Конечные модели

1. getrandbits(i) с принудительным старшим битом; getrandbits(i-1), где №1 возвращает 1 без расхода.
2. 32 последовательных байта: getrandbits(8), Python 2.7.9 randrange(256), Python 3.4.2 randrange(256). Big/little-endian соединение байтов.
3. randrange(2**(i-1),2**i) в Python 2.7.9 и 3.4.2.
4. randrange(1,n_secp256k1) в обеих версиях, затем маскирование младших i-1 бит и установка старшего.

Каждая модель: stride 1/2. Перед задачей i>1 пропускается stride-1 вызовов генерации целого ключа, с шириной текущего i для переменных API. Нумерация puzzle и пропуски решений сохраняются. Начальных дополнительных пропусков нет. Итого 24 конфигурации API/порядка/шага. Общие API сопоставляются с обеими историческими версиями, но не считаются двумя разными семействами.

## Неизвестные отклонения

Полная модель — объединение всех допустимых историй rejection sampling. Для строгого доказательства НЕоднозначности достаточно найти внутри неё семейство состояний с любой целевой величиной: наличие допустимой подсемьи со всеми 2^70 остатками исключает гарантированное определение бита/XOR во всём объединении. Это не доказательство равномерности posterior или отсутствия статистического преимущества при заданном распределении состояний/seed.

Для каждой конфигурации сначала строится подсемья без отклонений. Для всех 12 конфигураций с rejection дополнительно проверяется ненулевая история: один отказ в каждом вызове randrange с порядковым номером c, где c mod 37 = 5 (нумерация с нуля). Итого 36 ветвей. Если подсемьи несовместны или не дают полной свободы цели, результат отмечается только для них; вся API-модель не считается опровергнутой. Произвольное дерево отказов не объявляется исчерпанным. Дополнительный поиск историй требует отдельной записи параметров и пределов до запуска.

Для степенной границы Python 3 / больших диапазонов Python 2 каждый отказ задаёт старший бит предложенного значения 1, принятие — 0. Это точное линейное описание фиксированной истории. Для Python 2 малых диапазонов используется random() из 53 бит, без rejection; 2^k масштабируется точно.

Для order-диапазона выбираются достаточные линейные условия: принятое 256-битное число имеет bit255=0; Python2 дополнительно bit256=0. Отказ Python2: bit256=1. Отказ Python3: все 256 бит равны 1. Это намеренно более узкая допустимая подсемья. Прибавление 1 к принятому значению учитывается точно: известные остатки преобразуются вычитанием 1 по модулю 2^(i-1). Свобода всех 70 бит исходного остатка переносится на ключ биекцией +1, но XOR-сертификаты исходных битов не выдаются за XOR-сертификаты ключа.

Уравнения истории отказов — гипотетические условия выбранной ветви, **не дополнительные опубликованные наблюдения**. Отдельно показываются их ранг, вклад 1225/3767 настоящих наблюдаемых битов и остаточная размерность.

## Контроли и отделение предсказаний

До реальных данных: точные числовые API на произвольных состояниях в исторических CPython, независимая арифметика, символические карты и реальные последовательности отказов. Синтетические данные имеют тот же набор известных номеров (1–70,75,80,…,135) и ту же обрезку. Проверяется принадлежность исходного состояния решению; при недоопределённости строится другое состояние с теми же наблюдениями и другим №71, а не заявляется ложное уникальное восстановление.

Дополнительный положительный контроль алгоритма восстановления использует больше синтетических частично наблюдаемых выходов (байты), до полного ранга и последующих независимых предсказаний. Он явно отделяется от объёма данных puzzle. Восстановление по одинаковому объёму puzzle нельзя требовать, если размерность показывает неоднозначность.

На реальных данных сначала подбирается состояние только по №1–50 и заранее заданным условиям ветви. Его предсказания сохраняются и воспроизводятся историческим интерпретатором; затем оцениваются на всех 33 известных решениях >50. Лишь после сохранения этого результата остальные ключи добавляются в линейную систему. Удовлетворение всем данным после их добавления — проверка совместности, не успех отложенного предсказания.

Для полной системы сохраняются A, RHS, 70 целевых строк, базовое состояние и независимые направления. Все свидетельства проверяются числовым MT и историческими API; ранги перепроверяются независимым исключением. Ненулевая история должна фактически воспроизводиться API у каждого проверенного свидетеля. Нулевое состояние не допускается.

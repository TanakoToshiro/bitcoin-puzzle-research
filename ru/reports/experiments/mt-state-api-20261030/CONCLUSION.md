# E1b: состояние и №71 не определяются в проверенных моделях

**Для всех 24 конфигураций исторических API найдены допустимые семейства состояний, совместимые со всеми 83 известными решениями и допускающие любой из 2^70 остатков ключа №71.** Однозначное состояние, гарантированный неизвестный бит или нетривиальный XOR битов №71 из этих наблюдений не восстанавливаются в указанных моделях произвольного достижимого состояния MT19937.

Seed не перебирались. Линейные вычисления выполнялись на CPU. [Основной протокол](<PROTOCOL.md>), [дополнительные истории order2](<EXTENSION_PROTOCOL.md>), приёмка — артефакт исходного исследования (`ACCEPTANCE.json`; вне снимка), [полная таблица 24 моделей](<MODEL_TABLE.md>), [промежуточные выводы](<NOTES.md>).

|---|---:|
| getrandbits(i), принудительный старший бит | 2 |
| getrandbits(i-1), №1 без расхода | 2 |
| 32 × getrandbits(8), big/little-endian | 4 |
| 32 × randrange(256), Python 2.7.9 | 4 |
| 32 × randrange(256), Python 3.4.2 | 4 |
| randrange(2^(i-1),2^i), Python 2.7.9 | 2 |
| То же, Python 3.4.2 | 2 |
| randrange(1,n_secp256k1) с маскированием, Python 2.7.9 | 2 |
| То же, Python 3.4.2 | 2 |

Шаг 1/2, точное потребление потока, номера puzzle не сжимаются. Для переменной ширины пропущенный вызов использует ширину текущего i. Начальное состояние охватывает 19937 независимых координат; не накладывается ограничение на конкретный seed или образ конкретной процедуры инициализации Python.

## Почему неизвестные отказы не обходятся молчаливым предположением

Рассмотрено 39 заранее описанных фиксированных историй в двух запусках. **Семь несовместны, 32 совместны и дают d=70.** Условия каждого принятия и отказа входят в систему; фактический randrange исторического Python воспроизводит именно эту историю на состояниях-свидетелях. Для степенных диапазонов условия точны; для order использована явно ограниченная достаточная подсемья принятых/отвергнутых предложений.

Полная модель с неизвестными отказами включает найденную подсемью. Если уже внутри подсемьи возможен каждый №71, во всей модели тоже не может быть гарантированного бита/XOR. Перебор всех историй для **этого отрицательного вывода об определённости** не нужен. Это не утверждение, что вся нелинейная модель была исчерпывающе решена SMT, и не расчёт вероятностей всех историй.

Случай Python 2.7 order, stride1 показал необходимость этого различия: нулевая и sparse истории противоречат ключам. Дополнительные one и geometric-a тоже не подошли; geometric-b допустима и оставляет все 70 бит свободными. Нельзя было останавливаться на первой несовместной истории и объявлять API исключённым. [Сертификаты семи противоречий](<CONTRADICTIONS.md>).

## Ранги и число состояний

83 решения дают **3767 опубликованных битов**; старшие принудительные биты не учитываются. Уравнения выбранной истории — дополнительные условные ограничения, не новые наблюдения. Среди допустимых подсемейств общая размерность свободного состояния составляет **7329–16170**, а добавление 70 целевых raw-строк всегда увеличивает ранг ровно на 70.

После фиксации любого №71 остаётся как минимум **2^7259** состояний внутри одной из проверенных допустимых подсемей для каждой конфигурации; это нижняя граница, а не подсчёт всего объединения историй. Для order прибавление 1 по модулю 2^70 является биекцией, поэтому свобода raw-остатка означает свободу настоящего остатка ключа.

## Контроли и отложенные решения

- По **2493 последовательным 8-битным выходам** на синтетике восстановлено точное состояние и правильно предсказаны **128 последующих байтов**. Ранг 19937 перепроверен независимым исключением. Этот положительный контроль использует больше данных, чем puzzle.
- Все 39 новых историй прошли свои контроли с теми же 83 номерами, пропусками и обрезкой, что у puzzle. Построено другое состояние с теми же наблюдениями. Доступ к истинному синтетическому состоянию используется только для проверки правильности, не добавляется в систему.
- До добавления решений >50 сохранены предсказания **38 состояний**, подобранных только по №1–50 и условиям ветви. Каждое дало **0 совпадений из 33** отложенных ключей; ещё одна ветвь несовместна уже на обучении. Эти 38×33 сравнений не являются независимыми наборами данных. Провал произвольно выбранного состояния не опровергает всё семейство.
- После добавления остальных ключей выполнено **2880 числовых воспроизведений состояний историческими API**. Это проверки свидетелей и комбинаций, иногда одних и тех же состояний в двух версиях, не 2880 независимых моделей. Все 83 решения и №71 сверяются; сама совместность после добавления ключей не выдаётся за отложенное предсказание.
- Ранги вычислены двумя реализациями исключения; состояния и XOR-сертификаты проверены. Повреждённый сертификат отклонён. Resume пропустил все 73 этапа основного запуска и 7 этапов дополнения, сохранив 856 файлов без изменения SHA-256/mtime. Один положительный контроль во втором запуске переиспользован, а не вычислен повторно.

Сумма сохранённых времён вычислительных этапов, включая локальное историческое исполнение и без повторного учёта переиспользованного контроля: **428.194 с**. Подготовка кода и заключительная приёмка учитываются отдельно. Полные журналы: [основной запуск](<runs/20261030-115651-2cf8bdc3/RESULTS.md>), [дополнение](<runs/20261030-120642-c431f68d/RESULTS.md>).

## Границы вывода и будущие эксперименты

Результат относится к произвольному достижимому состоянию MT, этим API и схемам размещения. Дополнительные ограничения реального seeding могут сузить семейства; прежний E2b с seed32 — отдельная проверка. Нельзя переносить вывод на неизвестный исходный скрипт создателя или утверждать, что puzzle действительно создан MT.

Наличие всех возможных №71 **не доказывает**, что они имеют одинаковую posterior-вероятность при конкретном prior на состояния/seed и неизвестные истории. Здесь доказано отсутствие однозначного восстановления и гарантированных битов/XOR, а не невозможность любого статистического преимущества. HASH160 в этот анализ не входит.

Следующие отдельные задачи при наличии основания:

1. Явно заданный prior и корректная оценка/выборка по объединению историй отказов, с синтетической калибровкой; равномерная выборка из одной удобной линейной подсемьи не заменяет posterior.
2. Исторически обоснованное ограничение инициализации, иной расход потока, reseeding или дополнительные преобразования.
3. Новые опубликованные решения: пересчитать ранги по новому снимку. Те же 83 решения и те же семейства повторять не требуется.

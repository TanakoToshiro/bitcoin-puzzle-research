# Дополнительные истории для order2, stride1

Зафиксировано 2026-10-30 после синтетического контроля, до выполнения следующих трёх историй на реальных данных. Основание: у нулевой/sparse ветвей Python 2.7.9 randrange(1,n_secp256k1), stride1 выявлены линейные зависимости, а у sparse цели — только 46 свободных raw-битов. Такой условный результат нельзя переносить на неизвестную историю.

Условие запуска: обе прежние ветви order2 stride1 несовместны с настоящими ключами или не позволяют доказать полную свободу цели. Остальные схемы не повторяются. Новый отдельный ID сохраняет основной код плюс этот протокол и extension.py; прежний запуск не изменяется. Положительный контроль 2493 байтов переиспользуется как неизменяемый артефакт с хешем; новые истории проходят свои синтетические и исторические контроли до реальных ключей.

Три заранее заданные истории:

- `one`: ровно один отказ перед каждым принятием.
- `geometric-a`, `geometric-b`: для вызова c SHA-256 строки `E1b-history-{policy}-{c}` даёт 256-битное little-endian число; число его младших единиц до первого нуля задаёт число отказов. Это детерминированная конструкция истории, а не перебор MT seed и не подгонка по ключам. Редкий случай всех 256 единиц задаётся как 256 отказов. Для обычной случайной битовой строки число имеет геометрическое распределение, но никакая статистическая типичность выбранных трёх историй не предполагается доказанной.

Условия реального Python: каждый отказ имеет bit256=1, принятие — bit256=0 и bit255=0. Остальные методика, математическое обоснование подсемьи, разделение №1–50/отложенных и независимые сертификаты остаются как в основном протоколе.

Если хотя бы одна история даёт d=70 и все числовые проверки проходят, для общей модели со скрытыми отказами любой №71 возможен. Если нет — сохраняется незавершённость вопроса для этой API-модели; отсутствие решения в трёх историях не объявляется общим опровержением.

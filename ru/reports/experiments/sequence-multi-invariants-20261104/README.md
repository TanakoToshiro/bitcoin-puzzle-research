# SEQ-17 — расширение совместных инвариантов

Протокол: [PROTOCOL.md](<PROTOCOL.md>). Все методы получают одинаковые восемь
наблюдений. Сравниваются отдельные кубики, перекрывающиеся пары и блок
четырёх кубик. Выбор сделан по зарегистрированному структурному правилу.

Статус принятия определяется только `ACCEPTANCE.json`, `COMPLETE.json`
и `ARTIFACTS.json`. До их появления эксперимент и аудит не завершены.
После принятия итог: `FINAL_REPORT.md` и `RESULTS.json`.

`MANIFEST.json` фиксирует входы и структурную стадию. Символьная оценка
cuso имеет отдельный манифест. `SCIENCE_PLAN_V2.json` — действующая
научная очередь после технического исправления Windows-запуска.
Исходный план и его прерванные результаты сохранены. Повтор general h24
использует побайтно тот же пакет с суффиксом `_retry`; это не новый контроль.

Старый Windows-запуск контролировал venv-загрузчик вместо вычислительного
Python. Попытка подключить существующее дерево к Job Object завершилась
ошибкой привязки дочернего процесса и прерыванием первого расчёта. Старые
работники остановлены. Новый координатор запускает тот же CPython 3.11.9
напрямую с теми же закреплёнными vendor-библиотеками. Математический код
и параметры LLL не менялись. `PHASE1_INTERRUPTION.json` хранит учёт;
прерванное время включено в общий бюджет. Технические ошибки не являются
отрицательными научными результатами.

`constructions/`, `reduced_raw/`, `lattices/`, `combined/`, `algebra/`
сохраняют результаты по стадиям. Матрица перед незавершённой LLL остаётся
доступна; внутренний checkpoint LLL не заявляется. `method_audits/`
содержит независимые проверки. Истина хранится отдельно от blind-входов.

После принятия разрешён только `verify.py`; генераторы, координаторы
и аудиторы записывают файлы и не запускаются в опечатанной папке.

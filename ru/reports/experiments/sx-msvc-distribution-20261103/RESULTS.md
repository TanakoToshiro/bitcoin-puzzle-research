# SXM-01 — точный MSVC distribution восстановлен

03.11.2026, Europe/Moscow.

**Генератор байтов воспроизведён старым компилятором для x86 и x64. Майский
`uniform16 >> 8` не получил подтверждения как штатная рабочая MSVC-команда.
В июне появился другой, low-byte вариант. Для него выполнены синтетические
контроли и измерения; полный проход Puzzle не запускался.**

Полная нативная сборка SX с историческими зависимостями остаётся неподтверждённой.
Это ограничивает рекомендацию о полном поиске, хотя сам RNG больше не является
предположением по имени компилятора.

## Восстановленная инструментальная цепочка

- CTP Nov2013: compiler `18.00.21114`, `_MSC_FULL_VER=180021114`.
- Оригинальные STL/CRT RTM `12.0.21005`, включая `random` и `xutility`.
- Headers и import libraries Windows SDK 8.1.
- Локальные CRT DLL для обеих архитектур; системной установки не было.

[Объявление Microsoft от 18.11.2013](https://devblogs.microsoft.com/cppblog/announcing-the-visual-c-compiler-november-2013-ctp/)
указывает, что CTP меняет компилятор и использует стандартную библиотеку VS2013.
Получены [официальный CTP](https://www.microsoft.com/en-us/download/details.aspx?id=41151)
и нужные фрагменты [официального ISO VS2013](https://download.microsoft.com/download/2/5/5/255DCCB6-F364-4ED8-9758-EF0734CA86B8/vs2013.3_dskexp_ENU.iso).
Из ISO читались только выбранные файлы через HTTP Range. Пакет STL внутри
образа имеет версию RTM 12.0.21005: номер Update 3 в имени ISO не выдаётся за
версию заголовка. Современные даты перепубликации Download Center не являются
основанием исторической датировки.

Проверены пять Authenticode-подписей Microsoft, 14 payload hashes из подписанных
манифестов, 2 156 восстановленных файлов и 212 Git blobs SX.

## Точный алгоритм

```text
default_random_engine = MT19937, инициализированный одним uint32
uniform_int_distribution<uint16_t>(0, 65535)(engine) = uint16_t(engine())
```

Полный диапазон uint16 выбирает `_Get_all_bits()`. В `_Rng_from_urng`
промежуточный тип имеет 32 бита; диапазон MT равен 0…2³²−1, поэтому `_Bits=32`,
отбрасываний нет и выполняется один вызов engine. Возвращение uint16 оставляет
младшие 16 бит. Ширины типов нативно проверены для обеих архитектур.

| SX-код | Точный байт |
|---|---|
| Майский `uniform_dist(engine) >> 8` | `(MT.next() >> 8) & 255` |
| Июньский `uint8_t(distribution(engine))` | `MT.next() & 255` |
| Поздний `engine() % uint8_max` | `MT.next() % 255`, генератор E15 |

Для seed=1 первое MT-слово — `0x6ac1f425`: distribution даёт `0xf425`,
майский байт `f4`, июньский `25`, BX `%255` — `46`. В июньском потоке появляется
`ff`, невозможный для `%255`. Это разные отображения seed→entropy. Такие
контрпримеры не доказывают непересечение множеств выходов или уникальность
всех entropy. Верхняя граница числа последовательностей — 2³²; seed 0 допустим.

## Контроли и пилот

Нативные x86/x64 сборки CTP дали побайтно одинаковые результаты: **12 553
сценария и 459 136 выходов на архитектуру**. Проверены 12 473 унаследованных
MT-вектора, длинные потоки через границы 624/625/2500, seed 0 и 2³²−1,
десять специально заданных выходов URNG. Для каждого distribution sample
подтверждён один MT draw. Эталон — отдельная скалярная MT-модель.
RNG_CONTROLS.json — артефакт исходного исследования (`RNG_CONTROLS.json`; вне снимка).

Для июньской математической модели выполнен **только синтетический** пилот
`entropy32 → BIP32` по прежним 20 схемам id20…39. Он измеряет вычислительную
цену, а не восполняет историческую проверку всей программы. Настоящие ключи
Puzzle и holdout не читались; искусственный 49-битный target — `0x123456789ab`.

CUDA прошла MT-векторы, SHA/HMAC/EC/scalar-add, 17 BIP32-векторов, scan20 против
affine CPU в пяти разнесённых интервалах (28 seed), 20 положительных/20
отрицательных фильтров, overflow, invalid master/child, границы uint32 и
положительный контроль на последнем seed последнего блока.

## Решение

1. **Майский штатный MSVC high-byte вариант не перебирать:** рабочая команда
   с таким RNG не подтверждена, а в проверенных проектах есть конкретные
   признаки незавершённого переноса. Пользовательская переделка — отдельная
   гипотеза, для которой нужно отдельное основание.
2. **Июньская low-byte модель новая и конечная.** Её алгоритм, контроли и цена
   установлены. При требовании подтвердить работоспособность самой исторической
   SX-программы полный проход пока отложить.
3. Для перехода к реальному поиску сначала подтвердить нативный запуск июньского
   `sx hd-seed` с зафиксированными историческими зависимостями либо проверяемым
   ранним бинарником. Сверить внедрённые синтетические seed, entropy32 и xprv.
   Затем принимать решение о проходе ориентировочно на 1 час 20 минут.

Новых ключей/битов Puzzle и отрицательного результата реального перебора нет.
Неопределённость самого MSVC distribution закрыта; граница доказанного для
всей исторической программы сохранена.

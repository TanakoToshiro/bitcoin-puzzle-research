# Следующая отдельная серия: MSVC/BX MT19937

Это подготовленная задача, **не команда немедленного запуска**. Текущий SX/GPU не останавливать и не нагружать параллельно. Связь модели с автором Puzzle не доказана.

## Зафиксированный механизм

Официальный Windows x64 BX 2.0.0, commit aae99b278fdbfa31005cfa083ccbbf909212cbe4, релиз декабря 2014:

`uint32 seed → std::mt19937(single integer) → 32 выхода → каждый %255 → entropy16/32 → BIP32 → masked puzzle key`.

Весь домен `[0, 2^32)`, включая seed0 и seed0xffffffff. Индексы блоков, вычисление последнего seed и end должны быть uint64; не допускать переполнения uint32 до сравнения границ. Предварительный результат random_device при конструировании не является дополнительным неизвестным параметром MT: используется второе, единственное переданное слово.

Ровно 40 схем из SCHEMES.json. Родители m, m/0, m/0'/0, m/0'/1 normal/hardened i−1/i; BIP44 external/change normal i−1/i. Длины 16 и32. Это не SX uniform и не GNU/libc++ minstd. Не добавлять другие пути/длины в тот же проход.

## Реализация

Один seed порождает общий 32-байтный entropy, первые16 служат второй длиной. Для 32 первых MT-выходов достаточно 429 значений init (индексы0..428); хранить первые33 и текущее. Для j=0..31:

```text
y = (state[j] & 0x80000000) | (state[j+1] & 0x7fffffff)
x = state[j+397] ^ (y>>1) ^ ((y&1) ? 0x9908b0df : 0)
temper x стандартными 11/7/15/18 и масками 0x9d2c5680/0xefc60000
byte[j] = x % 255
```

Проверенный CPU-код: model_mt.py. Не хранить полный 624-word массив по привычке; сравнить register pressure/spills и фактическую скорость. При этом 33-word хранение не гарантирует лучшую occupancy — решает пилот. Кэшировать master и общие parent-узлы между схемами; прежние SHA/HMAC/secp256k1 переносить с pins в новую папку.

Фильтр: младшие49 бит истинного №50, затем независимая CPU-проверка №1–50. Любой полный training-match сохраняет seed, entropy, путь, все intermediate; остановить расширение и проверить известные №51+ с независимой affine-EC. Лишь после полного совпадения выводить кандидатов нерешённых задач и проверять их адреса.

## Приёмка до полного поиска

- BINARY_CONTROLS подтверждает исторический RNG; RNG_CONTROLS и 136 seed использовать для GPU, добавить границы всех блоков/верхний бит/0xffffffff.
- Сверять оба entropy/master/parent/final ключа, не только число совпадений. 40 planted-positive и40 negative; настоящие данные отделить от синтетики.
- Проверить полный последний блок, overflow, stop/resume, повреждённый checkpoint и запрет повторного выполнения готовых блоков.
- Проверить стандартные BIP32-векторы и существующие invalid-child/HMAC-контроли перенесённого HD-кода.
- Затем измерить несколько блоков GPU: kernel time и wall pipeline, все40 схем, без текущей SX-нагрузки.

Возможная разбивка —4096 блоков по2^20 seed, но размер выбрать после пилота. Полное число state×scheme =171798691840. Скорость предыдущих minstd-проходов сюда не переносить. CPU Python-пилот около176 seed/s всех40 служит эталоном, не оценкой GPU.

После измерения вычислить полный срок, выбрать разумный локальный бюджет, лишь затем запускать полный проход. Аренда4090 требует отдельного измерения или явно обозначенной грубой оценки; пока экономическая выгода не установлена.

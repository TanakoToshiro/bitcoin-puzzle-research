# Журнал MSVC-01

02.11.2026, Москва. Точные UTC загрузок — SOURCES.json. Текущие SX/GPU-процессы не изменяются.

1. Создан отдельный протокол, сохранены архивная документация Visual Studio 2013, официальный релиз BX v2.0.0 и build-файлы. Релиз опубликован 14.12.2014; Windows assets загружены 13.12.2014. В проекте указан PlatformToolset CTP_Nov2013. Данные не подменены современным STL.
2. Исходник random_fill вызывает random_device и инициализирует default_random_engine одним результатом; байты равны engine()%255. Архивная документация VS2013 прямо задаёт default_random_engine=mt19937. Подтверждается полный домен uint32, включая 0, а не minstd [1,2^31−1).
3. Скачаны официальные x86/x64 PE; linker version 12.0, обнаружены константы MT и реальный машинный код. Целиком EXE не запускались. В новой папке установлены capstone 5.0.9, pefile 2024.8.26, unicorn 2.1.4; общее окружение не обновлялось.
4. В x64 выделен random_fill: после получения seed начинается MT init с 1812433253, далее twist/tempering и %255. Сам random_device делает два обращения в видимом пути: один результат при конструкции не используется в MT, второй передаётся как uint32. Поэтому два обращения не означают 64-битное состояние. В эмулятор подставляется именно используемое слово; ОС/криптографический провайдер не эмулируются.
5. 80 случаев эмуляции официального кода, длины 0/16/32/625/2500 и граничные/псевдослучайные seed, дали 50768 совпавших байт с NumPy MT19937. Проверен выход за первый блок 624 слов. Эмулятор разрешает только блоки random_fill и его MT-helper, ограничивает инструкции/время. Система Windows и сеть бинарнику не доступны.
6. Для первых 32 выходов реализована точная сокращённая инициализация: достаточно MT state[0..428], при вычислении сохраняются первые 33 слова. Это снижение вычислительной/памятной цены, не дополнительное сокращение домена seed. 136 seed и 4352 слова совпали с независимым Python MT и NumPy; контролируются укороченные префиксы.
7. Постановка HD сохраняет прежние 20 путей и длины 16/32: 40 схем. Новая MSVC RNG-часть отличается от обоих проверенных minstd; сохранены контрпримеры. На синтетике проверены 160 child/public сравнений с affine-EC; 83 реальных опубликованных решения проверены по диапазону, public/address. Настоящий полный поиск ещё не проводился.

8. После подтверждения домена выполнен только малый CPU-пилот4096 seed ×40 схем. Четыре блока, 23,271с, 176,015 seed/s, кандидатов0. Покрытие0,00009537%; итог не исключает модель. Полная экстраполяция этого Python-эталона282суток не переносится на GPU. Верхние состояния отдельно проверены контролями, не объявлены покрытыми настоящим поиском.
9. Реальный scan проверен на40 planted seed в семиэлементных интервалах и40 изменённых отрицательных примерах. Все сработали. При повторе настоящего пилота0 новых блоков,6 файлов run сохранили SHA-256/mtime. История MSVC содержит218 уникальных commits на трёх страницах; восемь исходных файлов совпали с Git blob tree. Материалы и будущая GPU-задача сохранены, общая сводка дополнена.
10. Уточнение даты документации: страница относится к VS2013, но ms.date равна29.07.2015. Она используется вместе с декабрьским официальным бинарником, а не как самостоятельное доказательство доступности алгоритма до Puzzle. Ранний SX/MSVC uniform distribution остаётся незавершённым вопросом; текущий SX GNU/libc++ не закрывает его, но и новый BX-пилот его не подменяет.

Ошибки подготовки: предположенный src/utility.cpp дал 404, правильный путь src/utility/utility.cpp найден в tree. Первые две страницы истории MSVC имели по 100 записей, поэтому загружена третья — первые страницы не объявлялись полной историей. Предварительный просмотр PE-helper через exception table не нашёл leaf-функцию и показал предыдущий адрес; правильный helper затем дизассемблирован непосредственно по цели call, сохранённый файл исправлен до приёмки. Web-open архивной страницы Microsoft не удался, но прямая загрузка той же страницы успешна и закреплена SHA-256.

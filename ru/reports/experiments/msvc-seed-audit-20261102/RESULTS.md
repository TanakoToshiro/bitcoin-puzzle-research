# MSVC-01 — подтверждён новый 32-битный генератор BX

02.11.2026. **Исторический аудит завершён: для официального BX 2.0.0 Windows x64 подтверждена новая конечная модель `uint32 → MT19937 → %255 → entropy`.** Полный домен — не более 4 294 967 296 разных исходных seed. Ограничение относится к этой программе, а не к ключам Puzzle вообще. Связь автора с BX/MSVC не установлена; полного поиска не было.

## 1. Историческое основание

Официальный [релиз BX 2.0.0](https://github.com/libbitcoin/libbitcoin-explorer/releases/tag/v2.0.0) опубликован 14.12.2014, Windows x86/x64 assets загружены 13.12.2014 — до первого финансирования Puzzle. Сохранены сами mainnet PE, размеры и метаданные API. Их SHA-256 — SOURCES/PE_INVENTORY. Подпись издателя не проверялась; происхождение — официальный GitHub release. Загруженные EXE целиком не исполнялись.

Закреплённый commit `aae99b278fdbfa31005cfa083ccbbf909212cbe4` содержит проекты Visual Studio с `PlatformToolset=CTP_Nov2013`. Архивная [документация VS2013](https://learn.microsoft.com/en-us/previous-versions/visualstudio/visual-studio-2013/bb982398(v=vs.120)) задаёт `default_random_engine=mt19937`. Метаданные страницы обновлены 29.07.2015, поэтому одна документация не доказывала бы поведение декабря 2014. Для этого дополнительно проверен **машинный код самого релизного бинарника**.

В [random_fill](https://github.com/libbitcoin/libbitcoin-explorer/blob/aae99b278fdbfa31005cfa083ccbbf909212cbe4/src/utility/utility.cpp) выполняется:

Это `%255`, не `%256`; байт FF не возникает. Передаётся единственное 32-битное слово. В видимом машинном пути random_device есть предварительное обращение при конструкции и ещё одно для получения seed; первый результат не участвует в MT. Поэтому число обращений к системному RNG не превращает начальное состояние engine в 64-битное. Даже качественный системный RNG не расширяет 32-битный домен после этого сужения.

Ноль — допустимый seed MT19937, его нельзя удалять или сводить modulo 2^31−1. Домен для будущего поиска — `[0, 4294967296)`. Формулировка «не более 2^32 последовательностей» не утверждает, что все краткие entropy-выходы попарно различны; возможные коллизии могут лишь уменьшить их число.

## 2. Проверка официального бинарника

PE-инвентаризация обеих архитектур показывает linker 12.0 и MT-константы. **Полная побайтная проверка выполнена для x64**, x86 ограничен статическим осмотром и общей исходной моделью; результаты x64 не выдаются за динамическую проверку x86.

В x64 выделен участок `0x14007ebee..0x14007ed1b`: инициализация MT от EAX, генерация и запись байтов. Перед ним заканчивается получение использованного системного слова; после него начинается завершение функции/security-cookie check. При длинном потоке вызывается только MT-helper `0x14007ce90`. В Unicorn подставляются синтетический seed, память вектора и стек. Доступ к ОС, сети и настоящему RNG отсутствует; разрешённые basic blocks, время и число инструкций ограничены. PE entry point не запускается.

80 сценариев: 16 seed, включая 0/1/5489/2^31/2^32−1, × длины 0/16/32/625/2500. Все **50 768 байт** совпали с независимым NumPy MT19937 и `%255`. Длинные случаи проходят более одного refill и не ограничиваются первым словом. BINARY_CONTROLS.json — артефакт исходного исследования (`BINARY_CONTROLS.json`; вне снимка), код эмуляции — артефакт исходного исследования (`emulate_bx.py`; вне снимка), DISASM/disasm-файлы. Этот контроль существенно сильнее предположения по имени компилятора.

## 3. Что отличается от прежних проверок

GNU BX использовал minstd с множителем 16807, libc++ — 48271. Здесь MT19937 со стандартной инициализацией одним uint32. Сохранены контрпримеры несовпадения entropy в NON_EQUIVALENCE.json — артефакт исходного исследования (`NON_EQUIVALENCE.json`; вне снимка). Это не повтор предыдущих полных BX-проходов и не текущий SX uniform16>>8. Поиски Python random seed32 также не подменяют эту цепочку: инициализация и преобразование в HD-entropy другие.

Контроль MinGW default random_device использовал MT seed5489, чтобы получить **одно слово для последующего minstd**. Здесь результаты MT непосредственно превращаются в entropy-байты. Таким образом, встречавшееся раньше слово MT19937 не означает уже проверенную модель.

Ранний MSVC/SX остаётся отдельным вопросом. История build-пути — 218 уникальных commits до 15.01.2015, первые проекты марта 2014 прямо помечены незавершёнными. В срезе 23.05.2014 есть MSVC-проект CTP_Nov2013 и `uniform_int_distribution<uint16_t>(0,65535) >> 8`. **Точный исторический distribution MSVC этим аудитом не восстановлен**, готовый ранний SX-бинарник не найден в выбранном наборе. Подставлять GNU/libc++ distribution или современный MSVC нельзя. Подтверждённый BX `%255` пригоден для отдельной проверки уже сейчас и не требует угадывать ранний distribution.

## 4. Код и контроли

`model_mt.py` вычисляет первые 32 выхода без полного хранения 624 слов. Для них достаточно последовательности инициализации state[0..428], с сохранением первых 33 слов и текущего значения. Остальные слова первой twist-итерации не влияют на эти 32 выхода. Это точная оптимизация вычисления, не дополнительное ограничение seed. 136 seed, 4352 слова и укороченные префиксы совпали с отдельным Python MT и NumPy; сравнение с настоящим бинарником независимо покрывает используемую модель.

Зафиксированы 40 HD-схем: entropy 16/32 байта × прежние 20 путей (шесть родителей, разрешённые normal/hardened final, индексы i−1/i). Список — SCHEMES.json — артефакт исходного исследования (`SCHEMES.json`; вне снимка). Эти пути — конечная исследовательская постановка, не восстановленная конфигурация автора. Стандартная BIP32-модель и независимая affine-EC скопированы с проверенными pins из принятого эксперимента, без изменения оригиналов.

Прошли 160 affine child/public сравнений, 40 положительных восстановлений синтетического seed в семиэлементных интервалах и 40 отрицательных контролей после изменения наблюдаемого бита. Все 83 известных решения независимо проверены по диапазону/public/address. Синтетические №71/155 — контроли, не новые настоящие ключи. CONTROLS.json — артефакт исходного исследования (`CONTROLS.json`; вне снимка), HD_CONTROLS.json — артефакт исходного исследования (`HD_CONTROLS.json`; вне снимка), SCANNER_CONTROLS.json — артефакт исходного исследования (`SCANNER_CONTROLS.json`; вне снимка).

## 5. Ограниченный CPU-пилот

Run `a523ab5d459693bf`: `[0,4096)`, 4 блока по 1024, все 40 схем. Фильтр — 49 известных младших битов №50; при прохождении предусмотрена проверка всех известных №1–50. Настоящие holdout №51+ не использовались. Кандидатов фильтра нет.

Проверены 163 840 state×scheme, **0,00009537% домена**. Это проверка процедуры и скорости, не исключение гипотезы и не основание считать низкие seed вероятнее высоких. Время 23,271 с, 176,015 состояний/с всех 40 схем. Линейная экстраполяция этого последовательного Python-эталона — около 282 суток. Это не нижняя граница затрат и не скорость оптимизированного CPU/GPU: эталон повторяет часть HD-подготовки. Таблица собирается автоматически в [NUMERIC_REPORT.md](<NUMERIC_REPORT.md>).

При повторном запуске вычислено ноль блоков, шесть файлов run сохранили SHA-256 и mtime. Изменение входов создаёт другой run ID. Незавершённый блок пересчитывается; завершённые не повторяются. Источники сверены с SHA-256, восемь файлов с Git blob tree; ошибки загрузки сохранены. ACCEPTANCE.json — артефакт исходного исследования (`ACCEPTANCE.json`; вне снимка), PILOT.json — артефакт исходного исследования (`PILOT.json`; вне снимка).

## 6. Решение и пределы

**Есть основание для нового конечного поиска MSVC/BX, когда освободится GPU.** Следующий шаг — CUDA-перенос MT→%255 с существующими проверенными HD-примитивами, контроли и короткий пилот на 3070 Ti. До него срок полного прохода и экономику аренды 4090 утверждать нельзя. Полный домен в 2^32 вдвое больше одной прежней minstd-области, но вычислительная цена одного seed отличается; простое удвоение прежнего времени неверно.

Техническая постановка сохранена в [GPU_HANDOFF.md](<GPU_HANDOFF.md>). В данном аудите GPU и полный поиск не запускались. Новых ключей или битов Puzzle нет. Возможность использования Windows BX автором подтверждена по времени доступности программы, а фактическое использование не доказано. Возможные другие entropy-длины, пути, ранний MSVC/SX distribution, изменённые бинарники и схемы автора остаются за пределами вывода.

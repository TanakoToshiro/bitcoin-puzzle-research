# MSVC-01

Подтверждён новый 32-битный механизм Windows BX 2.0.0. [Результаты](<RESULTS.md>), [журнал](<JOURNAL.md>), [числа](<NUMERIC_REPORT.md>), [задача будущего GPU-пилота](<GPU_HANDOFF.md>). Полного поиска и GPU-запуска нет.

Из корня btc test (PowerShell):

> Исполняемый код/команды опущены в документационной копии.


Для независимого воспроизведения вычислительных контролей используйте копию папки эксперимента, чтобы сохранить принятые результаты и время исходного запуска:

> Исполняемый код/команды опущены в документационной копии.


Для копии подставить её путь в `$ms`. `controls.py` записывает новые длительности, поэтому новая подпись входов пилота создаст новый каталог runs и не изменит старые блоки. `pilot.py` — фиксированный пилот4096, не полный перебор; смена диапазона требует нового протокола и кода. Исходные данные и копии эталонов имеют pins. Завершённые блоки при продолжении не вычисляются повторно; прерванный незавершённый блок повторяется. RESULT сравнивается со всеми сохранёнными блоками, при несоответствии запуск завершается ошибкой.

Среда: общая Python3.11.9 .venv не обновлялась. В локальном vendor установлены только capstone5.0.9, pefile2024.8.26, unicorn2.1.4; точные версии остального — ENVIRONMENT.json. Зависимости можно восстановить через pip --target vendor с этими версиями. Ни один downloaded EXE не запускать как приложение: emulate_bx.py исполняет только изолированный вычислительный участок в Unicorn с синтетической памятью и ограничением control flow.

SOURCES.json содержит URL, UTC, SHA-256, размеры и ошибки; 404 по старому предполагаемому пути сохранены. SOURCE_FACTS связывает утверждения со строками. PE_INVENTORY/BINARY_CONTROLS закрепляют официальный бинарник. CONTROLS/RNG_CONTROLS/HD_CONTROLS/SCANNER_CONTROLS содержат синтетические результаты. PILOT и runs — реальные проверки4096 seed. RESULTS/JOURNAL сохраняются вручную и не переписываются генератором числового отчёта.

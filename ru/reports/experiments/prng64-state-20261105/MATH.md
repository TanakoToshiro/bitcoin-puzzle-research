# RNG64-01 — точные необходимые условия

Пусть y0…y3 — четыре последовательных64-битных выхода, а P — одна из четырёх зарегистрированных упаковок. Наблюдение для №i:

`P(y0,y1,y2,y3) & (2^(i−1)−1) = key[i]−2^(i−1)`.

В №130 наблюдаются129 младших битов, в №135 —134. При любой из выбранных упаковок это два полных выходных слова и часть третьего. Endian-перестановка меняет позиции наблюдаемых битов внутри частичного слова; она учитывается побитно. Никакие биты принудительно установленного старшего разряда не используются.

## xorshift64*

Переход T — R12,L25,R27 с64-битной арифметикой; выход y=c·x mod2^64 после перехода, c=2685821657736338717. Поскольку c нечётно, `x=c⁻¹y mod2^64` единственно. Шаг `x xor (x>>k)` и шаг `x xor (x<<k)` обратимы: последовательно xor со сдвигами k,2k,4k,…, меньшими64. Обратный T применяет обратные операции в обратном порядке.

Полное слово поэтому фиксирует64 независимых битов состояния. Остальные выходы того же4-word блока определены. В реальном №130 для каждой упаковки они противоречат наблюдению; значения и маски расхождений сохранены в LOCAL.json. Результат исключает весь ненулевой64-битный домен, не выборку seed.

## xorshift128+

Состояние перед шагом —(x,y). Для параметров(a,b,c):

`t=x xor (x<<a)`; `v=t xor y xor (t>>b) xor (y>>c)`;
новое состояние `(y,v)`, выход `(y+v) mod2^64`.

Правые сдвиги логические, левые усечены до64бит. Взяты(23,17,26) и(23,18,5). Переход обратим независимо от нелинейного выхода: из нового(u,v) восстановить `t=undo_right(v xor u xor (u>>c),b)`, затем `x=undo_left(t,a)`; прежнее состояние(x,u).

После полного известного выхода z состояние можно записать `(u,z−u mod2^64)`. Это точная параметризация всех совместимых состояний одним64-битным u; никакой информации о seed не предполагается. Генерируем соседние слова вперёд/назад и накладываем их настоящие маски. SMT использует сложение modulo2^64, включая переносы. Каждое SAT-состояние затем исполняется обычной целочисленной моделью. Следующий запрос исключает найденный u; unsat после единственного SAT доказывает единственность, unknown ничего не опровергает.

В синтетике все8 конфигураций128+ дали единственное состояние. Реальный №135 дал unsat для всех8; повторное решение сохранённых SMT2 подтвердило результаты. Отдельная дополнительная проверка кодирует128 исходных неизвестных битов и полную256-битную упаковку без сокращения к u; первый случай не завершился за60с. Это ограничение дополнительного метода, а не отсутствие решения и не незавершённость основного сокращённого метода.

Нельзя считать134 наблюдаемых бита134 независимыми линейными ограничениями. Нелинейная задача решена точно; исходов может быть0,1 или несколько. Для произвольного134-битного наблюдения существует не более2^128 различных образов состояний, но это лишь оценка размера образа, а не доказательство равномерности или распределения настоящих ключей.

## Что даёт только линейная часть

Для128+ исключительно LSB выхода равен xor двух LSB состояния. Ранги посчитаны по коэффициентам перехода, без использования значений holdout-ключей. Для fitting130/135 ранги6(big-endian) или4(little-endian); для всех83 номеров102 или29 соответственно, меньше128. Поэтому одних этих линейных условий для общего восстановления128-битного состояния не хватает. Полные слова и переносы дают существенно больше информации. Эти ранги не являются верхней границей информации всей задачи.

Для64* LSB также линейный, поскольку множитель нечётный; для всех83 номеров ранг64(big) или29(little). Основной алгоритм всё равно использует более прямое обращение полного слова.

## Почему расстояние между ключами не спасает эти модели

Все реальные противоречия находятся внутри одного ключа и относятся к четырём последовательным выходам. Изменение числа вызовов между ключами не меняет множество возможных4-word блоков при произвольном начальном состоянии. Поэтому вывод сильнее зарегистрированной проверки d=4…16: любые межключевые пропуски, прогревы и даже произвольное новое состояние перед каждым ключом не устранят это локальное противоречие для данной модели/упаковки. Пропуски **внутри** ключа, произвольная перестановка слов, иной PRNG или преобразование raw меняют задачу и здесь не исключены.

Новые истинные биты №71 из отвергнутой модели извлекать нельзя. В настоящем запуске ни одного состояния для проверки holdout не осталось.

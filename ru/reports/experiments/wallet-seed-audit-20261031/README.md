# E9 — seed исторических кошельков и первый пилот BX

Первый проход завершён 31.10.2026. [Журнал](<RESULTS.md>), [карта кошельков и первичные источники](<WALLET_MAP.md>), [числа пилота](<PILOT_RESULTS.md>).

Конкретный результат: для bx 2.0.0 + GNU libstdc++ подтверждён путь с не более 2^31−2 состояниями до HMAC/BIP32. Это не установленный генератор автора puzzle. На 65536 нормализованных состояниях и 16 схемах совпадений нет; это только ограниченный префикс, не исключение семейства. Обычное создание Electrum/Armory и bitcoinj рассмотрено отдельно от миграции/импорта. Найденный bitcoinj-путь миграции требует самостоятельной гипотезы о старом ключе.

## Воспроизведение

Из `research/puzzle71-hypotheses`:

> Исполняемый код/команды опущены в документационной копии.


Python 3.11 и существующий coincurve. Версии — ENVIRONMENT.json. Публичные контрольные примеры BIP32/BIP39, синтетические секреты и машинные результаты сохраняются локально. Старые рабочие проекты не импортируются; читаются проверенные 83 решения E7 и независимая арифметика E8, их хеши закреплены в блоках.

`fetch.py TARGETS*.json` скачивает выбранные публичные источники, без исполнения их кода. sources/ хранит успешные ответы и ошибки; существующие ответы повторно не загружаются. После запуска пилота SOURCES.json является закреплённым входом: новые загрузки/исправления следует делать в новой ревизии, иначе resume отклонит несовпадение хешей.

Короткий собственный C++ контроль собран установленным g++13 в WSL и выдал RNG_CPP.json. Исторический GCC4.9 сравнивался по исходникам, целый старый кошелёк не запускался. Сборка выполнялась только в этой папке; бинарник rng_control — синтетический тест, не поисковый кошелёк.

## Файлы

- PROTOCOL.md и PILOT_PROTOCOL.md — область исследования и фиксированные 16 схем.
- SOURCES.json, sources/ — URL, UTC, SHA-256, raw-ответы.
- CONTROLS.json, RNG_CPP.json — независимые/официальные контрольные сравнения.
- pilot/block-*.json — 64 завершённых блока с входными хешами, временем и первыми противоречиями.
- PILOT_RESULT.json, PILOT_RESULTS.md — агрегаты без повторного поиска.
- ACCEPTANCE.json — проверка покрытия блоков, пропуска готовых стадий, хешей и контрольных данных.
- FINAL_MANIFEST.json — хеши артефактов на момент завершения.

## Будущие шаги

1. Независимо воспроизвести полный профиль исторической GNU-сборки и минимальный фильтр всех 16 схем; оценить оптимизированную CPU/GPU-стоимость полного 31-битного пространства. Текущий Python-пилот полного перебора не делает.
2. Проверить различия libstdc++/libc++/MSVC как отдельные зафиксированные семейства. Нельзя менять `%255` на привычное `%256`.
3. Расширять BIP32-пути/индексацию только отдельными гипотезами. Пилот не охватывает BIP39, Electrum import, произвольные passphrase, child-of-child цепочки или пропуски.
4. Для bitcoinj-миграции искать проверяемое основание об исходном старом ключе. Без него 128-битное пространство остаётся практически недоступным.

Известный класс проблемы bx не является нашей новой криптографической находкой. Польза результата — исторически подходящая и конечная модель слабости seed, отличная от прямого MT-потока puzzle-ключей.

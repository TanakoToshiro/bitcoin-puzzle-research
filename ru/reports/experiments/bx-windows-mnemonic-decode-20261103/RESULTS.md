# BMD-01 — потеря нулей подтверждена официальным Windows BX

03.11.2026. **Официальный BX2.0.0 Windows x64 действительно удаляет ведущие
нули каждого32-битного блока при mnemonic-decode.** Проверена настоящая
CLI-цепочка encode→decode→hd-new с передачей реального stdout в stdin следующей
команды. Это закрывает основной пробел прежнего source-only вывода EMS-01.

SHA-256 EXE:
`d60329e6dacc7edda87c7c6ad12a79a5f556199a51658b6b66ddc26827118832`.
[Официальный asset](https://github.com/libbitcoin/libbitcoin-explorer/releases/download/v2.0.0/bx-windows-x64-mainnet.exe).
Файл скопирован без изменений из закреплённого исторического аудита.
Оригинальная зависимость EXE теперь не угадывается для проверки этого поведения:
измерялся сам executable на Windows. Это не новый аудит всех функций бинарника.

## Что реально произошло

| Исходная entropy | Фактический результат decoder | hd-new |
|---|---|---|
| `baadf00d` ×8 | те же32 байта | xprv, exit0 |
| `00112233` + `baadf00d` ×7 | `112233` + `baadf00d` ×7,31 байт | другой xprv, exit0 |
| `01122334` + `baadf00d` ×7 |63 hex-цифры | invalid argument, exit−1 |
|32 нулевых байта | `00000000`,4 байта | seed менее128 бит, exit−1 |

Exit−1 наблюдается Windows subprocess как4294967295. Точные bytes, включая
начальный CRLF decoder, return codes и stderr сохранены в SMOKE.json — артефакт исходного исследования (`SMOKE.json`; вне снимка)
и852 уникальных native call logs — артефакт исходного исследования (`calls`; вне снимка). Запуск скрытый, cwd отдельный,
пустой explicit config, BX_* environment удалён,10s timeout на дочерний процесс.
Сетевых команд и настоящих wallet/private inputs не было.

## Контроли

- **216 codec cases**, все совпали с независимой моделью. Включены136 прежних
  RNG seed (0,1,2³²−1), разные позиции/ширины hex-блоков, внутренние нечётные
  потери цифр, нулевые блоки, крайние допустимые/отклоняемые длины и entropy16.
- **129 принятых master-xprv** проверены Base58Check и побайтно по HMAC-SHA512:
  scalar и chaincode совпали с фактическим преобразованным seed.
- **180 final HD children**:3 изменённых seed ×20 прежних HD-схем ×synthetic
  номера1/50/71. Нормальные/hardened children, родители и xprv совпали с
  независимой Python affine-EC моделью.32→16-byte accepted case включён.
- Подготовленный ограниченный CPU worker прошёл **20 positive +20 negative**
  фильтров с targets из native binary traces, множество из20 кандидатов,
  отказ при capacity19, границы uint32 и отбрасывание уже покрытых inputs.
- В проверенных207 случаях исходной длины32:83 unchanged,40 changed_valid,
  82 odd-hex reject,2 too-short reject. Это специально составленная контрольная
  выборка, **не оценка частот полного домена**.

Бинарная приёмка — артефакт исходного исследования (`BINARY_CONTROLS.json`; вне снимка), байтовые traces — артефакт исходного исследования (`BINARY_TRACES.json`; вне снимка),
HD traces — артефакт исходного исследования (`HD_TRACES.json`; вне снимка), CPU worker controls — артефакт исходного исследования (`BLOCK_CONTROLS.json`; вне снимка).
Реальные решения Puzzle/holdout не загружались. Все новые ключи синтетические.

## Подготовленная отдельная область поиска

`uint32 → MT19937 →32×%255 →8 uint32 BE chunks → hex без leading zeros → bytes → BIP32`.
Новый input принимается только при **чётной длине hex от32 до62 символов**,
то есть effective master seed16…31 байт. Длина64 уже покрыта E15, нечётный
hex и<16-byte seed отвергаются реальным BX. Пропускать их можно до HD.

Нечётные потери в разных chunks могут суммарно дать чётную длину: удаление
только целых нулевых байтов неверно. Для исходных16 байт новой допустимой
области нет.32→16-case не обязательно совпадает с E15 entropy16 того же RNG seed.

Сохранены **ровно20 схем E15 для исходной length32, id20…39**, без новых родителей,
индексов, RNG или масок. Training1–50, holdout51+ после кандидата.
[Точная спецификация](<SEARCH_SPEC.md>), SCHEMES.json — артефакт исходного исследования (`SCHEMES.json`; вне снимка),
эталон — артефакт исходного исследования (`search_reference.py`; вне снимка), bounded CPU worker — артефакт исходного исследования (`block_reference.py`; вне снимка).

**Основание для отдельной поисковой серии теперь есть.** Следующий этап — новая
копия CUDA HD-кода с этим transform/predicate и переменной длиной seed,
приёмка и измеренный пилот. Полный поиск, CUDA-пилот и оценка его стоимости
здесь не выполнялись; готовность unattended full-run не заявляется.
46,49с — время набора native controls, не скорость поиска.

Старые EMS-01/E15 artifacts/checkpoints сохранены. Результат не устанавливает
программу автора и не исключает весь BX. Новых настоящих ключей или битов нет.

# BMD-01 — официальный Windows BX и потеря нулей

03.11.2026, Europe/Moscow. Новое поручение: проверить именно декодер официального
Windows-бинарника. При подтверждении подготовить отдельную гипотезу только для
допустимых изменённых32-byte inputs с20 прежними HD-вариантами этой длины.
Полный поиск этим поручением не объявляется начатым. Старая BIP39/PBKDF2 задача закрыта.

## До результатов

- Исходный официальный x64 mainnet asset BX2.0.0 закреплён прежним SOURCES и
  SHA256 d60329e6dacc7edda87c7c6ad12a79a5f556199a51658b6b66ddc26827118832.
- Все новые файлы только в этой папке. EMS-01/E15 manifests, code, checkpoints
  и исходный asset не менять. Копировать EXE с проверкой SHA-256.
- Здесь проверяется реальный CLI, а не современная пересборка library source.
  Запускать только mnemonic-encode/decode, hd-new и ограниченные hd-private
  синтетические вызовы. Отдельный cwd, явно пустой config, без BX environment,
  stdin/stdout/stderr pipes, CREATE_NO_WINDOW, timeout на каждый дочерний процесс.
  Никаких кошельков/пользовательских backup/сетевых команд/настоящих ключей.
- Первые smoke cases фиксируют фактическое поведение и exit status без
  предварительного объявления источниковой модели правильной. Ошибки исполнения
  не являются отрицательным результатом гипотезы.
- Далее designed cases: leading zeros на каждой позиции4-byte chunk, нулевой
  chunk, разные длины hex-числа, чётная/нечётная суммарная потеря цифр, unchanged,
  <16-byte результат; исходные entropy16 как отрицательный контроль нового покрытия.
  Сохранённые136 RNG seeds включают0,1,2^32−1; RNG заново не сканируется.
- Сохранять точные input/stdout/stderr bytes, return code, время, PID, argv,
  binary hash. End-to-end stdout encode→stdin decode→stdin hd-new без подмены
  промежуточной строки Python-моделью. Модель вычисляется отдельно для сравнения.
- Каждый принятый xprv декодировать Base58Check и сравнить master scalar/chaincode
  с HMAC-SHA512("Bitcoin seed",фактические decoded bytes). Никакого PBKDF2.

## Если эффект подтверждён

Для исходных32-byte entropy разбить на8 BE uint32. Для каждого взять lowercase
hex без leading zeros (ноль → "0"), конкатенировать. Новым поиском считать
только 32≤число hex-цифр≤62 с чётной длиной. Длина64 — дубликат E15; нечётная
или<32 — rejected. Это условие должно совпасть с реальным CLI перед приёмкой.
Нечётная потеря в отдельных chunks допустима, когда общая длина чётна:
нельзя удалять только целые нулевые байты каждого блока.

Зафиксировать20 схем length32 из E15 без изменения parent/hard/offset, обычную
маску2^(i−1)+(raw mod2^(i−1)), training1–50, holdout51+ только после кандидата.
На synthetic дополнительно проверить реальные parent/final HD nodes для20 схем,
в том числе normal/hardened и индексы49/50. Неизменённые cases и rejects
должны отсеиваться до HMAC/HD. Полный домен uint32 не исключается частичным тестом.

Подготовка поиска не означает полный поиск. При отсутствии бинарного эффекта
новые схемы не принимать. При подтверждении сохранить точную спецификацию,
эталон, controls и следующий исполнимый шаг с численной оценкой только после пилота.

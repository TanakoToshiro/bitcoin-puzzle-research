# Следующий этап E12: CUDA для принятой цепочки SX

Постановка и контрольные значения уже готовы. Не повторять исторический поиск, старые BX-проходы или E11. Проверить сначала COMPLETE.json командой verify.py. Новую CUDA-версию и её результаты создать в отдельной папке рядом с этой.

## Точный конечный набор

Два RNG,32 байта, непосредственные дети master m, четыре схемы на RNG:

| scheme | Последний индекс для puzzle i |
|---:|---|
|0|i−1|
|1|i|
|2|0x80000000+i−1|
|3|0x80000000+i|

Всего8 схем, каждая по2147483646 нормализованных начальных состояний1..2147483646. Здесь seed генерируется один раз для master, а не заново для каждого puzzle. Mask: установить бит i−1, сохранить младшие i−1. Final filter №50: младшие49 бит child49/50 либо hardened49/50. Все опубликованные №1–50 — проверка кандидата; №51+ — holdout, после фиксации модели. Только после полного совпадения проверять адреса нерешённых задач независимо.

## RNG — не перепутать с BX

GNU: a16807, m2147483647. После каждого перехода x=state−1. Если x≥2147483392, продолжить engine; иначе байт=floor(x/8388607). LLVM: a48271, тот же m и порог, байт=x&255. Продолжать до32 **принятых** байтов. Не использовать `%255`, `state&255`, верхний байт без точного деления или фиксированные32 вызова engine. В RNG_CASES.tsv есть все254 начальных состояния, дающих первое отбрасываемое значение, плюс допустимая граница.

HD — обычный проверенный BIP32 из майского libwallet. Exact extended nodes: PROBE.tsv, Python model.py, исходное C++ native/hd_keys.cpp. Историческая serialisation использует little-endian число fingerprint, прочитанное из тех же четырёх байтов little-endian; эти две операции сохраняют стандартные четыре байта. Не менять порядок на основании имени переменной.

## Приёмка до полного поиска

1. Перенести EC/HMAC примитивы из принятой BX-версии в новый каталог, проверить исходные pins. Не изменять прежние ядра/манифесты.
2. Изменить число схем/размеры буферов согласованно:4 на RNG; одна длина32, один parent m. Проверить даже при использовании старого общего кода, что результаты называются state/s всех4, а не8/16.
3. Сравнить entropy и число RNG draws по1173 случаям; GNU4.8/4.9 — один числовой вариант, не два новых прохода.
4. CPU/GPU/Python сравнение master/chain/public и детей; positive/negative planted-сценарии всех8 схем, targeted rejection, начало/конец пространства, границы блоков, forced filter bits0 и переполнение списка кандидатов. Ошибки invalid master/child прекращают блок.
5. Stop/resume, неизменность завершённых блоков, pinning inputs, два последовательных прохода, отсутствие пропусков. Кандидат останавливает расширение поиска до CPU/affine проверки.
6. Пилоты нескольких блоков с внешним wall. Оценить цену полного домена на3070Ti; не выдавать старую скорость `%255` за измеренную SX.

CPU-пилот уже прошёл по262144 состояния на RNG. При полном новом GPU-проходе можно начать с1: небольшой повтор явно учитывать, пилотные состояния не прибавлять к полному покрытию второй раз. На CPU полный последовательный цикл этого кода оценивается около45,17ч; GPU-стоимость пока неизвестна. Аренды и оценки4090 по одному лишь имени карты не требуется.

Новые BIP44 paths, другие parents/entropy lengths, ранние сломанные API, MSVC uint16 distribution и BIP39 — отдельные будущие протоколы. Связь SX с создателем не доказана.

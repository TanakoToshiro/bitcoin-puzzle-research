# E12 — историческая цепочка SX

01.11.2026. **Историческое воспроизведение и ограниченный CPU-пилот завершены. Полный поиск не запущен, гипотезы SX пока не исключены.**

Первый этап: зафиксировать историю hd-seed до 15.01.2015, libwallet/libbitcoin и алгоритм uniform_int_distribution. Восстановить достижимую цепочку с контролями до пилота. Старые BX-проходы не перезаписываются и не повторяются.

Источники, время получения, SHA256 и ошибки: SOURCES.json и sources/. Установщики и загруженные программы автоматически не исполняются.

## Исторический результат

Восстановлена конкретная совместимая цепочка мая 2014 года: `sx hd-seed` без аргумента → 32 байта через `default_random_engine(random_device())` и `uniform_int_distribution<uint8_t>(0,255)` → `libwallet::hd_private_key` → `sx hd-priv [--hard] i` → маска puzzle. Установщик не фиксировал commit зависимостей, поэтому версия машины автора неизвестна. Рабочий срез фиксируется по исходникам SX 16.05.2014, libwallet 10–13.05.2014 и EC/HMAC API libbitcoin 15.05.2014. Полный старый набор библиотек не собирался: исполнены исторические HD-функции с явными современными адаптерами. [Источники и метод](<README.md>).

Две архивные копии libwallet имеют одинаковые HD-файлы и тесты; проверены SHA256 и 53 Git blob SHA1 доступных файлов. Старые первичные URL libwallet сейчас дают404, это ограничение происхождения архива, а не отсутствие исторической библиотеки. Всего сохранено168 HTTP-ответов:159 успешных,9 HTTP404 (в том числе удалённые/перемещённые пути и неверно предположенные имена заголовков). Первичные сетевые ошибки среды сохранены отдельно.

**Новое существенное уточнение:** отличие uniform относится к раннему SX. В сохранённой истории переход `random_fill` на `%255` присутствует в commit `252b5d…` от22.07.2014. Поздняя RNG-часть частично совпадает с уже проверенным BX; это не повод повторить прежние полные проходы. Полная эквивалентность всегда требует совпадения HD-цепочки, длины entropy и индексов. [87 снимков и изменения](<HISTORY.md>).

GNU 4.8.2/4.9.2 для этого вызова: `state←16807×state mod2147483647`, `x=state−1`, повтор при `x≥2147483392`, байт `x//8388607`. libc++3.5: множитель48271, тот же порог отбраковки, байт `x&255`. Это не `%255` и не обычный `%256`. В обеих схемах полный домен нормализованных состояний —2147483646. Наличие random_device не расширяет этот домен после сведения к состоянию minstd.

Изучено исправление HD-генератора апреля2014. Замена HMAC-ключа `Bitcoin seed` длиной13 с завершающим нулём на строку длиной12 **сама по себе не создаёт другого HMAC**: дополнение HMAC нулями делает их эквивалентными, что проверено. Другие изменения старой библиотеки не смешиваются с принятой майской цепочкой. В самом раннем SX HD-child команды ещё были незавершены; рабочая команда hd-priv и проверка valid появляются24апреля.

В июньском коде также найден `min_uniform_dist_size`: uint8 для обычной ветки, uint16 для MSVC. Это оставленный отдельный вопрос исторической Windows-сборки; результаты GNU/libc++ на него не распространяются.

- 4 неизменённых исторических C++-теста libwallet,36 утверждений: BIP32-векторы, публичная деривация, serialize/deserialize, неправильные типы ключа.
- 1173 RNG-примера, по391 на GCC4.8.2/GCC4.9.2/libc++3.5. В каждой группе254 специально сконструированных случая с отбраковкой. Число вызовов engine и все32 байта совпали.
- 11 730 точных extended private nodes совпали с независимым Python;192 child/public проверки выполнены чистой аффинной арифметикой.
- 8 искусственных HMAC-случаев подтвердили ошибки invalid-master/invalid-child, допустимость IL=0 и отсутствие скрытого retry/skip.
- Сканер восстановил8 синтетических состояний — по одному на схему; изменённые фильтры отвергнуты. Нулевой фильтр дал все128 ожидаемых кандидатов;24 проверки границ/отбраковки совпали с Python.
- Все83 опубликованных входных решения проверены по диапазону и адресу; для8 дополнительно использована аффинная арифметика. Исходный файл скопирован с сохранением SHA256.
- Продолжение выполнено с принудительным запретом новых subprocess: завершённые51 JSON вызовов/входов не изменились, повторного сканирования не было.

## Пилот настоящих данных

Фиксированы8 схем: два RNG × normal/hardened child × i−1/i;32 байта entropy, непосредственные дети master. Для каждого RNG проверен `[1,262145)`,4 блока по65536. Кандидатов49-битного фильтра №50 —0, ошибок —0. Отложенные решения №51+ не использовались для выбора модели. На один RNG покрыто **0,012207%** домена. Это отрицательный результат только для перечисленных состояний; полный поиск и исключение семейства не заявляются.

Числа автоматически сохранены в [PILOT_RESULTS.md](<PILOT_RESULTS.md>) и PILOT.json — артефакт исходного исследования (`PILOT.json`; вне снимка). GNU:27 375,65 state/s всех4 схем, внутренняя CPU-экстраполяция21,79ч. libc++:25 514,54 state/s всех4,23,38ч. Вместе настоящий сканер работал19,85с, внешнее wall23,35с. Это однопоточный CPU-пилот; ускорение CUDA и стоимость4090 пока не измерялись.

**Допустимый вывод:** исторически конкретная новая цепочка воспроизведена и пригодна для конечной проверки. Реальный ключ/бит не найден. Пилот не даёт основания считать SX маловероятным: его префикс составляет слишком малую долю пространства и не выбирался по вероятностному основанию. Приоритет определяется проверяемостью и конечной стоимостью, а не установленной связью с автором.

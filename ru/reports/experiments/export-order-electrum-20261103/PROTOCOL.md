# EXP-01 — точный порядок Electrum CSV / CPython2 dict

03.11.2026. Только синтетические кошельки и исходники. Никакого нового поиска
реальных seed/master/Puzzle ключей. Старые EL-02/E7/BX/SX/MT результаты не пересчитывать.

## Конечное покрытие

Основной экспорт: Electrum1.7.4 commit e8ffe29554dbb616005218f9686a3d9d8c85ca49,
неизменённые методы addresses/get_account_addresses/get_address_index/get_private_keys
и GUI do_export_privkeys. Выделенные функции исполняются настоящим CPython2.7.9,
с подставными storage/network/UI, без запуска PyQt GUI, сети и кошелька пользователя.
OldSequence приватные children вычисляются по сохранённым историческим методам;
криптографический результат сверяется с независимым Python3/coincurve расчётом.
Контрольный CSV: Electrum1.9.8 commit f92b483942d3f8ee51506e0436d9b524db33a336,
неизменённые методы addresses/get_account_addresses и GUI do_export_privkeys;
поставщик WIF для него подставной, с заранее независимо проверенными значениями.
Это воспроизведение порядка и CSV, не полного UI/wallet lifecycle.

Платформы: официальный Windows CPython2.7.9 x86 и amd64 (2014 MSI), Linux x86_64
CPython2.7.9 из прежней проверенной сборки исходников. MSI только читаются и
распаковываются, не устанавливаются в систему. Хеш-режимы каждого: unset,
PYTHONHASHSEED=0,1,42,4294967295 и два независимых random-процесса. Для random
снимается _Py_HashSecret с синтетического процесса, чтобы сравнить точную модель;
секрет неизвестного исторического автора этим не восстанавливается.

Модель явно разделяет C long (хеш) и size_t (perturb). Hash LCG и prefix/suffix,
1000003, −1→−2, начальные8 слотов, probing5*i+perturb+1 со сдвигом5, загрузка2/3,
рост4*used и повторная вставка по старым слотам. Dummy/deletion/update проверяются
отдельно. ASCII str/unicode сравниваются; произвольный Unicode за пределами scope.
Dict construction через {} и последовательные присваивания. Presizing/update(dict),
нестандартные __eq__/__hash__ вне профиля экспорта; искусственные hash-collisions
используются только для проверки probing и различия long/size_t.

Синтетические наборы: две детерминированные 128-bit seed-строки; чистый
old-wallet account0, R256/C3, R253/C3, R257/C3; вариант с3 импортированными
ключами и тем же account0. Нет неподтверждённых независимых old accounts.
Default change3 подтверждён прежними source-fixtures. Пулы передаются готовыми:
synchronize/history/GUI timing здесь не воспроизводятся.

Дополнительно: тот же набор адресов с другой историей вставок/удалений; границы
роста5/6,21/22,85/86,341/342, up to1025, длинные коллизии, пустая строка,
значения заменяются без смены ключа. У тестов hash signed-negative отдельный контроль.

## Содержательные проверки

1. Сравнить каждый нативный hash и реальные слоты CPython dict с независимой моделью.
2. Проверить побайтно исторический CSV с учётом Windows CRLF; порядок/WIF/число строк
   сверить с моделью. Padding адреса до34 символов — часть исходного кода.
3. Сравнить receiving/change последовательность, фиксированные hash-профили,
   другой master, увеличение R на1, импортированные ключи и hash-randomization.
4. Различать «экспортировать259 и взять256 строк» и «создать256 исходных записей».
   Выбор первых256 после dict-order не равен отбрасыванию change до создания dict.
5. На synthetic masked sequence проверить, что правильный map возвращает исходные
   branch/index и keys, а последовательный map даёт ошибки; не заявлять перебор
   всех перестановок или восстановление неизвестного hash secret.
6. Если известен MPK, raw-адреса и их order можно вычислить публично; показать это
   на synthetic без подачи приватного master алгоритму построения map. Проверяющий
   код знает master. Если MPK неизвестен, объяснить зависимость order от кандидата.

Полные числа из JSON/CSV. Фиксировать inputs/code/runtime hashes и ошибки,
переиспользовать завершённые задания при совпадающих входах. Изменение inputs
после принятия требует нового run id. Документы README/RESULTS/JOURNAL в новой
папке, общий журнал — отдельной записью по окончании. Никаких автоматических
новых GPU серий по результату этого аудита.

# SEQ-05 — функция вывода скрытой цепочки

02.11.2026. Новая конечная серия по указанию пользователя «дальше».
Протокол фиксируется до расчёта настоящих данных этой серии.
Бюджет вычислительных стадий15 минут CPU/wall; один процесс, без GPU,
установок пакетов, перебора seed и повторения старых научных стадий.

## Три гипотезы

Скрытая цепочка прежняя: s[i+1]=(a*s[i]+c) mod n,
0<=a,c,s[1]<n, n — порядок secp256k1. Теперь наблюдаемая часть
puzzle[i]−2^(i−1) образована одним из трёх способов, b=i−1:

1. `msb`: старшие b бит 256-битного состояния, s>>(256−b).
2. `bit_reverse`: младшие b бит после разворота всех256 бит.
3. `byte_reverse`: младшие b бит после разворота32 байтов.

Ведущие нули сохраняются: операции всегда над256 битами/32 байтами.
Никаких комбинаций этих преобразований и подбора параметров после
просмотра результатов. Историческое применение автором не установлено.

Вход — прежние83 решения. Fit: №75,80,...,135. Проверка: №1–70,
которые не подаются в решётки параметров. Все данные уже изучались;
это не новый закрытый тест. Обязательный старший бит puzzle исключён.

## Решётка отношений

Наблюдение преобразуем в известный старший префикс y[i] полного s[i].
Для msb/bit_reverse известны b бит; для byte_reverse на первом этапе
используем только8*floor(b/8) полных бит старшего префикса.
Последний неполный байт обязателен в окончательной проверке.

s[i]=y[i]+u[i], 0<=u[i]<2^(256−known_bits).
Для шага5 разности t[j]=s[i_(j+1)]−s[i_j] mod n имеют множитель
rho=a^5 mod n. Доступно Y[j]=y[i_(j+1)]−y[i_j] mod n,
ошибка e[j]=u[i_(j+1)]−u[i_j]. Полиномиальные отношения и парный
gcd применяются как в SEQ-04, но **без деления состояний на2^b**
и без множителя32 в извлечении a.

Длины полиномов k=4,5,6,7; размер решётки13. Вес полиномиальной
координаты P_j=2^(256−74+loss−5j), loss=0 для msb/bit_reverse,
loss=7 для byte_reverse (консервативная потеря неполного байта).
Веса окон W_l=2^(5l). LLL delta=3/4. Все пары полиномов базиса;
линейный gcd даёт rho, a=rho^(inverse(5,n−1)) mod n.
Общие делители большей степени сохраняются без произвольного выбора
корня. Лимит128 кандидатов; превышение — незавершённость.

## Восстановление и точная проверка вывода

По найденному a решётка двух неизвестных s[1],c использует центры
старших префиксов и их веса. Babai предлагает d=(a−1)*s[1]+c mod n.
Затем при фиксированных a,d **все** допустимые s[1] вычисляются точно:
s[i]=s[1]+T[i]*d mod n; каждое наблюдение задаёт объединение интервалов
для s[i], сдвигаем его и пересекаем интервалы s[1].

msb/bit_reverse дают один интервал. byte_reverse даёт до128 интервалов
из-за неизвестных старших битов последнего частичного байта. Нельзя
принять кандидат по округлённому префиксу, не проверив эти биты.
Условные множества и проекции на №71 сохраняются; уникальность
полного исходного состояния не предполагается.

## Проверки и конечные стадии

До реального анализа: roundtrip/точные интервалы всех трёх maps на
уменьшенных16-битных моделях против полного перебора, сдвиги и
пересечения интервалов, проекции. Полноразмерные проверки используют
независимую прямую сериализацию и генерацию скрытой цепочки.

Для каждой map12 новых случайных полноразмерных положительных цепочек,
SHAKE-домен `SEQ-05/controls/v1/{kind}/`, номера0..11.
Реальный пилот допускается только при >=10/12 правильных a,d и
отсутствии неверных принятых параметров. Непрошедшая map остаётся
непроверенной на реальных данных, а не отвергнутой.

Для каждой прошедшей map:12 новых положительных реплик с отдельным
доменом и64 нулевых последовательности с теми же масками/индексами.
Вырожденные a=0,1,−1/постоянная цепочка — отдельные границы метода,
без требования восстановления единственного истинного a.

Независимый аудит матриц, gcd, интервалов/сериализации и условных
проекций. Замена нижних наблюдений не должна менять fit по верхним.
Хэши и mtime всех принятых файлов SEQ-01..04 сохраняются. Все результаты
возобновляемы без повторных научных вычислений; финальные артефакты sealed.

Метод эвристический. Отсутствие кандидата не доказывает невозможность
модели/вывода; успех на синтетике не является получением реального ключа.
Не подбирать новые maps после отрицательного реального результата.

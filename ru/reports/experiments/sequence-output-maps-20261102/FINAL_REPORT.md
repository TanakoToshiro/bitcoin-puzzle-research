# SEQ-05 — другой способ вывода скрытого состояния

02.11.2026, Москва. Следующая конечная серия после SEQ-04.

**Проверены три функции вывода скрытой аффинной цепочки: старшие биты,
разворот256 бит и разворот32 байтов. На опубликованных Puzzle-решениях
ни одна не дала кандидата.** Контрольный восстановитель правильно
восстановил параметры72 из72 новых полноразмерных искусственных цепочек;
на192 случайных последовательностях совместимых кандидатов нет.

Это эвристический отрицательный результат для трёх зафиксированных
гипотез. Реального нового ключа, подтверждённого бита или обоснованного
сокращения диапазона поиска не получено.

## 1. Что именно проверено

Скрытое состояние:

```text
s[i+1] = (a*s[i]+c) mod n,  0 <= a,c,s[1] < n
```

n — порядок группы secp256k1. Порядок экспорта прямой, один переход
на номер puzzle, постоянные a,c. Обязательный старший бит puzzle
исключён; наблюдается b=i−1 остальных битов.

| Идентификатор | Функция наблюдения |
|---|---|
| msb | Старшие b бит: s[i] >> (256−b) |
| bit_reverse | Младшие b бит после разворота всех256 бит s[i] |
| byte_reverse | Младшие b бит после разворота32 байтов s[i] |

Ведущие нули обязательны: ширина состояния всегда256 бит/32 байта.
Перестановки слов, произвольные вращения, XOR-маски, сочетания
преобразований и неизвестные функции вывода не исследовались.
Историческая связь этих трёх вариантов с автором Puzzle не установлена.

Fit использует13 решений №75,80,...,135. Последующая проверка использует
№1–70. Эти данные уже изучались; новый закрытый тест не заявляется.
Вход, протокол и код зафиксированы до реального пилота в
MANIFEST.json — артефакт исходного исследования (`MANIFEST.json`; вне снимка).

## 2. Новый математический шаг

Каждое наблюдение превращается в известный старший префикс y[i]:

```text
s[i] = y[i]+u[i],  0 <= u[i] < 2^(256−known_bits)
```

Для первых двух maps known_bits=b. Для byte_reverse на этапе поиска
отношений известный префикс округляется вниз до целых байтов,
known_bits=8*floor(b/8). Это только предварительное ослабление;
частичный байт возвращается при точной проверке состояния.

Разности состояний через5 шагов удовлетворяют:

```text
t[j] = s[i_(j+1)]−s[i_j] mod n
t[j+1] = a^5 * t[j] mod n
```

Доступны Y[j]=y[i_(j+1)]−y[i_j] mod n. Разница между t и Y
ограничена неизвестными хвостами u. Четыре взвешенные решётки
размерности13 ищут полиномиальные отношения степеней3–6;
общие линейные делители предлагают rho=a^5. Поскольку gcd(5,n−1)=1,
пятый корень даёт единственное a modulo n.

В отличие от SEQ-04, здесь нет деления состояния на2^b и нет
множителя32 при извлечении a. Для байтового варианта веса допускают
потерю до7 предварительно неиспользованных битов. Исходные номера
сохранены: соседние элементы верхней панели разделены5 переходами.

## 3. Точная проверка вывода и состояний

После предложения a решётка по центрам старших префиксов предлагает
d=(a−1)*s[1]+c mod n. Затем рассматривается
s[i]=(s[1]+T[i]*d) mod n при фиксированных a,d.

Каждое точное наблюдение задаёт разрешённые интервалы для s[i].
Их модульные сдвиги и пересечение дают **все** допустимые s[1]
для данного a,d, без выбора удобного представителя Babai.

Для msb и bit_reverse наблюдение задаёт один интервал. В byte_reverse
последний частичный байт фиксирует некоторые его биты, оставляя другие
неизвестными: получается до128 интервалов. Именно это полное множество
используется в приёмке. Совпадения только по округлённым полным байтам
не принимаются.

Неудача LLL/Babai не доказывает отсутствие a или d. Точность интервального
этапа условна на уже предложенные a,d; весь поиск параметров остаётся
неполным. Единственность исходного полного состояния не предполагается.

| Функция вывода | Первые положительные контроли | Новая положительная репликация | Совместимых результатов на нулевых данных | Реальных кандидатов |
|---|---:|---:|---:|---:|
| msb | 12/12 | 12/12 | 0/64 | 0 |
| bit_reverse | 12/12 | 12/12 | 0/64 | 0 |
| byte_reverse | 12/12 | 12/12 | 0/64 | 0 |

Во всех72 положительных случаях восстановлены истинные a,d, истинное
s[1] входит в точное множество, а все83 наблюдения согласованы.
Множители имеют244–256 значащих битов. В каждом положительном случае
проекция множества на искусственный №71 была единственной и правильной.
**Это не прогноз настоящего №71.**

Условные множества полных s[1] остаются большими:

| Map | log2 числа допустимых состояний после всех83 наблюдений | Медианное время положительного восстановления |
|---|---:|---:|
| msb | 122.000 | 0.242s |
| bit_reverse | 121.008–122.000 | 0.254s |
| byte_reverse | 116.764–120.902 | 0.258s |

Эти числа — мощность сохранённых множеств при найденных a,d,
не энтропия настоящего генератора и не число всех возможных моделей.

На каждой реальной map получено52 полинома из четырёх базисов.
У всех312 пар gcd=1. Итого156 полиномов и936 пар для трёх maps;
они не объявляются независимыми статистическими тестами. Ни одного
a не предложено, поэтому реальный подбор d/состояния не выполнялся.
Реальные пилоты заняли0.145s,0.137s,0.140s соответственно.
Все реальные матрицы и полиномы — артефакт исходного исследования (`REAL.json`; вне снимка).

Отсутствие кандидатов вместе с успешными новыми контролями уменьшает
практический приоритет именно этих сочетаний аффинной модели и вывода.
Это исследовательская оценка, не вычисленная вероятность исторического
происхождения ключей и не точное опровержение модели.

## 5. Проверки реализации

До реальных данных:

- 335 наборов интервалов вывода сверены по всем65521 состояниям
  16-битной модели; охвачены ширины0–16 и границы байтов.
- 600 точных множеств начальных состояний сверены с полным перебором
  той же области;500 проверок модульных сдвигов/пересечений прошли.
- Из2400 попыток проекции2393 завершены и сверены точно,7 достигли
  лимита перечисления. Это не отрицательные результаты и не заявления
  о числе вариантов. Уточнение счётчиков — артефакт исходного исследования (`PROJECTION_COVERAGE.json`; вне снимка).
- 128 полиномиальных gcd сверены с независимым нативным FLINT.
- Полноразмерная сериализация проверена отдельным перечислением
  исходных битовых позиций, а не повторным вызовом основной функции.

После расчёта выполнен независимый аудит:

- 1116 решёток отношений заново построены из наблюдений; проверены
  U*B=B_reduced и det(U)=±1, также проверены решётки состояния.
- 87 048 пар полиномов независимо пересчитаны нативным FLINT,
  включая все936 реальных пар.
- Разрешённые состояния выведены независимо через битовые маски;
  точные пересечения вычислены другим алгоритмом по событиям границ.
- По границам и внутренним представителям интервалов выполнена прямая
  генерация, проверены наблюдения и условные проекции.
- Замена69 нижних наблюдений для каждой map не меняет fit по верхней
  панели; испорченные цепочки отвергнуты последующей проверкой.
- Все334 принятых файла и seals SEQ-01..04 сохранили SHA-256 и mtime.
  Старые научные стадии не запускались.

Итог аудита: AUDIT.json — артефакт исходного исследования (`AUDIT.json`; вне снимка). Сумма сохранённых времён основных
72 положительных и192 нулевых случаев —49.103s; малые контроли —7.112s,
аудит —11.423s. Разработка, оформление, старт процессов и отдельные
вырожденные случаи не входят в эти суммы. GPU не использовался,
пакеты общей среды не устанавливались и не изменялись.

## 6. Границы метода

Вырожденные a=0,1,−1 и постоянная цепочка сохранены отдельно.
Для a=1 в msb и byte_reverse множитель был предложен, но условное
восстановление состояния не завершилось принятым результатом.
Для bit_reverse соответствующий пример прошёл. Это демонстрирует
неполноту метода и зависимость восстановления от конкретных данных.

Для постоянной цепочки разные a с соответствующими c могут давать
одни наблюдения; найденный совместимый a не выдаётся за единственный
истинный. Вырожденные случаи не включены в показатель72/72.

Другие модули, нелинейные переходы, другой порядок экспорта, хеширование
или произвольные функции вывода этой серией не исключены. LLL не
перечисляет все отношения: даже для зарегистрированных maps отрицание
носит алгоритмический, а не полный доказательный характер.

## 7. Приёмка и дальнейшее направление

[Протокол](<PROTOCOL.md>), [команды](<README.md>), приёмка — артефакт исходного исследования (`ACCEPTANCE.json`; вне снимка),

ноль новых вычислений и неизменность уже завершённых результатов.

Дальнейшее простое расширение списка представлений той же аффинной
цепочки без отдельного основания сейчас имеет низкий приоритет.
Следующий самостоятельный эксперимент должен менять сам переход
скрытого состояния либо иметь конкретное основание для другого
модуля/порядка экспорта. Новые классы в этой серии не запускались.

Метод коротких полиномиальных отношений использует решёточную линию
Stern / Contini–Shparlinski; преобразование конкретных maps и точные
интервальные проверки приведены здесь. Новизна в литературе не заявляется.
[Первичный контекст и эвристические ограничения](https://researchers.mq.edu.au/en/publications/on-sterns-attack-against-secret-truncated-linear-congruential-gen/).

# MINGW-RD-01 — итог проверки фиксированного random_device

**02.11.2026, завершено.** Дефект старого MinGW подтверждён первичными исходниками и вычислениями. Для проверенных SX/BX-цепочек он **не объясняет puzzle**:80 комбинаций,60 различных последовательностей, все противоречат известным решениям уже на №2–5. Нового приватного ключа, бита или XOR-связи не получено. GPU не использовался, текущий поиск SX не изменён.

Числа ниже берутся из AUDIT.json — артефакт исходного исследования (`AUDIT.json`; вне снимка), [числового отчёта](<NUMERIC_REPORT.md>), точных предсказаний — артефакт исходного исследования (`PREDICTIONS.json`; вне снимка). Протокол: [PROTOCOL.md](<PROTOCOL.md>). Предварительные выводы и ошибки сохранены отдельно: [JOURNAL.md](<JOURNAL.md>).

## Что установлено исторически

Публичное [сообщение MinGW #338](https://sourceforge.net/p/mingw-w64/bugs/338/) создано06.05.2013: новый процесс с `std::random_device` выдавал то же первое число. Upstream GCC4.7.4/4.8.2/4.9.2 содержит fallback MT19937 с default seed5489. Это подтверждается **кодом**, а не спорными комментариями о `rand()` в обсуждении. [GCC4.7.4 random.h](https://github.com/gcc-mirror/gcc/blob/releases/gcc-4.7.4/libstdc%2B%2B-v3/include/bits/random.h), [GCC4.8.2 random.cc](https://github.com/gcc-mirror/gcc/blob/releases/gcc-4.8.2/libstdc%2B%2B-v3/src/c%2B%2B11/random.cc).

Условие — не определён `_GLIBCXX_USE_RANDOM_TR1`. Crossconfig MinGW в трёх версиях не включает его;4.8.2/4.9.2 дополнительно явно отключают его для native MinGW/MSys. У4.7.4 native configure проверяет доступность `/dev/random` и `/dev/urandom`, без позднего явного исключения MinGW. Это различие записано в RNG_CONTROLS.json. Точная сборка/патчи установленного автором бинарника неизвестны. В2019 upstream [исправление GCC9](https://gcc.gnu.org/pipermail/libstdc++-cvs/2019q2/026853.html) заменяет этот fallback на `rand_s` для MinGW-w64; поздняя дата исправления не означает, что проблема возникла после2015.

Цепочка при стандартном конструкторе:

```text
MT19937 seed = 5489
первый random_device() = 3499211612
minstd_rand0 initial state = 3499211612 mod 2147483647 = 1351727965
SX/BX byte generation → BIP32 master → выбранный путь → маска puzzle
```

Нельзя передавать5489 непосредственно в minstd и считать это воспроизведением SX. В штатных сохранённых SX/BX-функциях создаётся **новый локальный random_device**, а затем вызывается один раз. Поэтому каждый такой вызов заново получает одно и то же первое число. Второй и последующие выходы MT не являются альтернативными seed этой штатной функции. При иных правилах жизни объекта это уже другая модель приложения.

## Что проверено и что дублируется

Четыре цепочки: SX uniform8→32байта; SX23.05.2014 uniform16>>8→32байта; BX%255→16байт; BX%255→32байта. Для каждой20 путей: `m`, `m/0`, `m/0'/0`, `m/0'/1` с normal/hardened последним индексом i−1/i; BIP44 account0 external/change с normal i−1/i. Это условные HD-композиции; наличие путей в эксперименте не доказывает их использование автором.

Все80 комбинаций отвергнуты по решениям1–50. На фиксированном состоянии две SX-версии дали одинаковую entropy, поэтому **уникальных последовательностей60, а не80**. Реальный holdout51+ не потребовался; опубликованные ключи51+ использовались только для проверки корректности исходных адресных данных, не для выбора моделей.

| Подмножество | Отношение к прежней работе |
|---|---|
| BX,16/32байта,40 GNU-путей | Фиксированное состояние входит в уже полностью проверенный домен E9; нового пространства нет. |
| SX uniform8,4 direct-master пути GNU | Входит в завершённый полный E12-GPU. |
| SX uniform8,16 остальных GNU-путей | Входит в постановку отдельной серии E13; здесь проверена только одна точка, её текущий статус не изменяется и не переоценивается. |
| SX23мая uniform16>>8,20 путей | На данном состоянии совпадает с предыдущей SX entropy; дополнительной независимой последовательности нет. Это не доказательство равенства алгоритмов на всём домене. |

**Практический вывод:** повторять полный поиск BX/SX специально ради фиксированного MinGW seed не нужно. Закрыта конкретная модель дефолтного fallback и перечисленных путей. Сам MinGW, все Windows-кошельки или любые другие цепочки генерации не исключены.

## Проверяемость

- По10000 последовательных выходов каждой из трёх исторических fallback-реализаций совпали с собственной Python MT19937 и NumPy RandomState. Проверены новый объект, явный token5489 и ошибочный token.
-1590 сравнений исторического C++ distribution с независимой формулой, включая границы отбраковки и фактическое состояние MinGW.
-83 опубликованных ключа подтверждены по диапазону, сжатому публичному ключу и адресу;8 сверены независимой аффинной EC-арифметикой.
-80 синтетических предсказаний на всех20 путях совпали с независимой EC-арифметикой,20 положительных и20 отрицательных контролей; проверен master из BIP32 test vector1.
-Повторный запуск использует сохранённые результаты. Принятые457 файлов E12 проверены по прежнему COMPLETE.json и не изменились.
-Отдельная приёмка пересчитала первое реальное противоречие всех60 различных последовательностей через независимую аффинную EC-арифметику. Повторный запуск с принудительным запретом subprocess не изменил хэши и время модификации результатов. ACCEPTANCE.json — артефакт исходного исследования (`ACCEPTANCE.json`; вне снимка).

Расчётная часть около2,1с CPU/wall с запуском WSL; подготовка, загрузка и сборка не включены. Это не замер скорости массового перебора и не основание для оценки аренды GPU. Запуск исторических функций произведён с явно указанными современными адаптерами engines, а не полным старым MinGW/Windows-бинарником; детали в README.md.

## Что остаётся открытым

1. **Исторический SX23.05.2014 uniform16>>8 при произвольном состоянии** отличается от раннего uniform8. Сохранён контрпример state5489 — артефакт исходного исследования (`NON_EQUIVALENCE_WITNESS.json`; вне снимка); он служит только доказательством различия формул, не новым предположением о seed автора. Если возвращаться к этой версии, сначала отдельный аудит её срока существования/рабочей HD-цепочки и оценка отличий от уже покрытых кандидатов. Полный проход здесь не выполнялся.
2. Прямое получение entropy из нескольких `random_device()` в другом историческом приложении. Нужно сначала предъявить конкретный код до15.01.2015. Произвольные упаковки выходов не проверялись и автоматически не добавляются.
3. Явный нестандартный token, другие правила создания/сохранения объекта, vendor-патчи, MSVC и другие STL. Эта серия их не исключает. MSVC-ветка uint16 с приведением кбайту из июньского SX — отдельная постановка, её нельзя смешивать с uniform16>>8 мая.

Связи автора puzzle с MinGW по-прежнему нет. Следующий содержательный отдельный аудит из прежнего списка — конкретный исторический браузерный кошелёк/BitcoinJS, после фиксации достижимой цепочки энтропии.

# MinGW random_device — фиксированный seed

Изолированная серия `MINGW-RD-01`, 02.11.2026. [Итог и ограничения](<RESULTS.md>), [числовые таблицы](<NUMERIC_REPORT.md>), [протокол до вычислений](<PROTOCOL.md>), [промежуточные выводы и ошибки](<JOURNAL.md>).

Проверяется опубликованный дефект старого MinGW/libstdc++: fallback `std::random_device` использует MT19937 с default seed5489. Проверены первичные исходники GCC4.7.4/4.8.2/4.9.2, условия выбора fallback и последствия для двух исторических SX-версий и BX. Не устанавливается программа автора puzzle. MSVC — другая библиотека, не синоним MinGW.

## Воспроизведение

Команды PowerShell из корня `btc test`; Python3.11 из существующего исследовательского venv. Новый venv не нужен: зависимости не менялись, версии фиксирует AUDIT.json. Сборка C++ и небольшой probe — CPU в WSL Ubuntu-24.04. GPU не используется.

> Исполняемый код/команды опущены в документационной копии.


`audit.py` при существующем результате проверяет совпадение входов/артефактов и пропускает вычисления. Изменение входов вызывает ошибку; новый вариант проводить в новой папке. `report.py` только пересобирает числовую таблицу из сохранённых результатов; интерпретации RESULTS.md и журнал не переписывает.

Для воспроизведения с нуля скопировать постановку/скрипты в новую папку и вызвать `fetch.py`, `prepare.py`, `build.sh` через WSL, затем `audit.py`, `report.py`. `prepare.py` копирует необходимые принятые файлы E12 только после сверки с его COMPLETE.json. Никакой автоматической записи в E12 нет.

## Метод и границы

- `sources/`, `URLS.json`, `SOURCES.json`: первичные исходники/сообщения, URL, время, SHA256, неудачные попытки. Ветка GCC release зафиксирована содержимым и хэшами; готовый исторический MinGW-бинарник не устанавливался.
- `prepare.py` извлекает полные классы random_device и нужные fallback-функции, а также исторические тела uniform_int_distribution. Они сохранены в `native/` и исполняются с современными **явными** адаптерами стандартных MT19937/minstd_rand0. Это не запуск старого Windows-кошелька и не проверка ABI. Собственный MT Python и NumPy RandomState дают независимый контроль стандартной последовательности.
- `model.py`, `affine.py`, `known_solutions.json`: копии принятых E12 функций/данных, происхождение в INPUT_PINS.json. Все83 известных решения перепроверены по адресу/публичному ключу. Тест моделей использует только решения1–50; №1 не несёт наблюдаемых битов исходного генератора.
- Четыре entropy-модели ×20 путей. Две entropy-модели совпали на данном состоянии: всего60 различных последовательностей. Схемы/первые противоречия/полные предсказания1–50 сохранены в PREDICTIONS.json. Старшие принудительные биты не служат наблюдением генератора.
- Публикация владельцем полного *после маскирования* приватного ключа не означает публикацию исходного 256-битного HD-child. Здесь сравниваются именно остатки исходных детей после принятой маски.

Сырые выводы native: NATIVE_OUTPUT.txt; условия/время запуска: NATIVE_INVOCATION.json; контрольные входы: RNG_CASES.txt. Подтверждённый результат: AUDIT.json; полный манифест файлов: COMPLETE.json. Для продолжения достаточно этих файлов и RESULTS.md, история чата не требуется.

# SEQ-23 — совместное нелинейное решение QCG

Сводный результат: [FINAL_REPORT.md](<FINAL_REPORT.md>). Формулы и точность: [MATH.md](<MATH.md>). Исходный план: [PROTOCOL.md](<PROTOCOL.md>); уточнение допуска и исправление мониторинга до основной серии: [AMENDMENT_01.md](<AMENDMENT_01.md>).

Серия содержит только синтетику. Четыре новые QCG-цепочки и два случайных полноразмерных входа используют в точности исходные 83 маски и 135 позиций. Рабочий процесс получает только INPUT.json; полный эталон доступен аудитору отдельно. Это запуск точного совместного решателя, а не тест одиночного HG-идеала.

## Файлы и стадии

- `cases/*/INPUT.json` — входы решателя, без параметров генератора и закрытых состояний; `CHECKER_TRUTH.json` — отдельный эталон.
- `encoding.py` — неизменённые точные NIA/FF системы; `worker.py` — построение .smt2 и один check-sat, без чтения эталона.
- `TOY_RUN.json`, `reference/*.json`, `VALIDATION_FF.json` — исходные малые попытки, полный независимый перебор и раздельный допуск кодировок. NIA не прошёл допуск на основной этап.
- `MONITOR_TEST.json`, `run_main.py` — проверенный запуск непосредственно базового Python и контроль реального рабочего PID/памяти. Исходный монитор из experiment.py сохранён для истории; его малые измерения памяти исключены из результатов.
- `FULL_FF_RUN.json`, `cases/full*/ff/OUTER.json` — шесть основных запусков и внешние ограничения. При принудительной остановке RESULT.json не создаётся; OUTER.json является итоговой записью ограничения.
- `cases/*/*/query.smt2`, `MODEL.json`, `START.json`, `stdout.log`, `stderr.log` — точная задача, контрольные хеши, размеры и вывод. В основной серии дополнительно сохранён PROCESS.json.
- `GAUGE_WITNESSES.json` — эталонные представители общего сдвига для проверки системы после поиска; не входы рабочего процесса.
- `OPEN_CASES.json` — отдельный учёт малых ограничений NIA, основных ограничений FF и незапущенных NIA-попыток. Это новые записи SEQ-23, не изменение старых SEQ-16/17.
- `RESULTS.json`, `AUDIT.json` — научные статусы и независимый аудит. `MANIFEST.json` и `AMENDMENT_MANIFEST.json` фиксируют код/данные/план до соответствующих запусков; `ARTIFACTS.json` — окончательный архив всех файлов.

Не запускать стадии `setup`, `toy`, `full`, `run`, `validate`, `finish` или `seal` поверх завершённой серии. При продолжении конкретного ограниченного запроса использовать новый каталог и сохранить ссылку/хеш исходного query.smt2; новые лимиты, PID, память и ответ записывать отдельно. Сохранён вход, а не checkpoint памяти решателя: повтор с большим лимитом начнёт поиск заново. Старая метка ограничения при этом остаётся исторической, а не превращается задним числом в отрицательный ответ.

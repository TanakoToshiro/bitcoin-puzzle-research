# MAP-01 — аудит преобразования исходного числа в puzzle-ключ

Зафиксирован 02.11.2026 до вычисления новых таблиц. Только CPU, без перебора
seed и без новых GPU-проходов. Набор: T01–T32 в models.py. Новые варианты после
просмотра результата требуют отдельной серии. Цель — необходимые следствия,
а не приписывание автору Python/JavaScript.

Обозначения: i — номер задачи, b=i−1, B=2^b, r=k−B, M_b(x)=B+(x mod B).
Неизвестный исходный x для каждого i свободен в [0,2^256), кроме явно отмеченных
условий. Полный скаляр secp256k1 дополнительно требует 1<=x<n. Все свидетельства
для реальных данных проверяются также на это условие, когда оно выполнимо.
Свободные x_i НЕ являются свидетельством существования одного кошелька/seed.
Обязательный старший бит не трактуется как наблюдение исходного генератора.

## Семейства

T01–T10: младшие/старшие биты, разворот32 байтов/256 бит до маски,
hex prefix/suffix длины ceil(b/4) с точной остаточной маской,
JS-парсинг по32-битным словам с точной склейкой, ошибочное hex(x)[2:-1]
Python3 (потеря последней цифры), переменная длина hex-префикса,
разворот выделенных ceil(b/8) байтов до маски. Проверка: построить точные
прообразы всех опубликованных ключей. Это доказывает неразличимость на
уровне отдельных значений, но не равенство функций на одном и том же x.

T11–T15: округление длины вниз до hex/байтов; буквальная приставка '1'
к floor(b/4) цифрам; префикс b бит unpadded bin(x), если длина x не меньше b;
разворот32 байтов ПОСЛЕ формирования окончательного puzzle-ключа.
Фиксируются точные условия достижимости или необходимое условие.

T16–T20: uint32/uint64 на окончательном числе или отдельно на остатке;
JS `(x & ((1 << b)-1)) >>> 0`, затем ТОЧНОЕ добавление B вне Number.
Для JS сдвиг b берётся modulo32. Это не BigInt JS: в 2015 его стандартного
встроенного типа не было; точная склейка могла быть строковой/библиотечной.

T21–T24: округление исходного x в binary64, затем точное целое и маска;
округление уже окончательного k; тот же полный x с bit_length=256;
независимый Number/float на каждом64-битном слове с точной фиксированной
склейкой (переполнение слова — ошибка, не перенос в соседнее слово).
Для целого z точная binary64-представимость эквивалентна
z mod 2^max(0,bit_length(z)−53)=0. Для полного256-битного x шаг >=2^203.
Обратное направление, integer division и хранение в длинном целом, не
приравниваются к float. Python2 integer `/` соответствует точному старшему
префиксу; Python3 `/` через binary64 подпадает под соответствующее условие
остатка, если затем результат только переводится в int и добавляется B.

T25–T27: shortest decimal Number.toString или repr(float) на окончательном
числе/остатке, затем ТОЧНЫЙ разбор десятичного числа; Python2 str(float)
с12 значащими цифрами на окончательном числе, затем точный decimal-разбор.
Здесь проверяется лишь НЕОБХОДИМОЕ число значащих десятичных цифр <=17/12.
Не использовать binary64-сетку для десятичного вывода: shortest string может
обозначать целое, не равное точному binary64! Например, JS выводит
1000000000000000100 для некоторого Number, чьё точное целое равно
1000000000000000128. Экспонента раскрывается точно; Python int('1e20')
сам этого не делает. Другой промежуточный float, хеш, сдвиг или XOR после
этой стадии не входит в модель.

T28–T30 — регрессия прежних PRECISION_EXCLUSIONS, НЕ новые исключения:
random=j/2^53 с масштабированием2^256; масштабирование2^b и точное B;
окончательный uniform в binary64. T30 совпадает с условием T22.

T31: окончательный hex(k) без0x и безL, без выравнивания чётной длины,
затем Python2 `.decode('hex')` / строгий байтовый decoder. Нечётная длина
даёт ошибку. T32: `long(hex(long(x))[2:][-ceil(b/4):],16)` с оставленным L,
затем B, без исправления длины. L считается символом среза; для m=1
остаётся одна L, что не число. b=0 обрабатывается отдельно как k=1.

## Историческая опора и границы

Сохранить официальные CPython2.7.9/3.4.2 docs/source и ECMA-2625.1 с URL,
временем и SHA256. Исторический Python2 здесь не запускать и не заявлять
такого запуска: семантика моделируется по исходникам. Современный Node —
дифференциальный контроль операций ES5, не эмуляция браузера2015.
Утверждения, зависящие от особенностей конкретного старого dtoa/браузера,
не выводить из одного современного Node.

Предшественники: python-expanded/PRECISION_EXCLUSIONS — три float-конструкции;
SEQ-05 sequence-output-maps — high/byte-reverse/bit-reverse внутри скрытой
аффинной цепочки. Эти генераторные поиски НЕ повторять. Зафиксировать хэши
прочитанных отчётов; старые checkpoints/сертификаты не изменять.

## Приёмка и порядок

1. Перед реальными предикатами проверить криптографию всех83 строк через
   coincurve и независимый affine, диапазоны, номера, адреса и public.
2. Проверить формулы на исчерпывающем12-битном мире и b=0..11; для word/byte
   операций использовать согласованную ширину, для float — уменьшенную
   точность5 бит. Сравнивать буквальную операцию и независимый образ/условие.
   Не называть необходимый decimal-критерий достаточным.
3. Полноразмерные граничные/случайные синтетические x (SHA256-счётчик),
   положительные и отрицательные контроли, JS-файл с ES5-операциями;
   Node не получает приватных реальных данных до окончания контролей.
4. Проверить T01–T32 на обучении1–50, затем отдельно на51+.
   Для необходимого условия одно противоречие достаточно; известные ранее
   holdout не называть новым закрытым тестом. Здесь нет fit/p-values.
5. Для неотвергнутых свободных maps сохранить прообразы всех83 строк и
   вторые различные прообразы, если они существуют. Для variable hex prefix
   при b кратном4 и числе hex-цифр(r)<b/4 источник вынужденно x=r:
   любой более длинный unpadded префикс имеет ненулевую первую цифру.
   При полной длине префикса второе свидетельство может требовать добавления
   цифры (x<<4), а не переворота одного бита. Не путать условный x с
   восстановлением настоящего raw или установлением истинности модели.
6. Сохранить CSV/JSON, доказательства, точные контрпримеры, время/версии,
   input/code hashes, журнал. Повторный запуск с теми же входами читает
   сохранённое и проверяет хэши; изменение входов требует нового каталога.

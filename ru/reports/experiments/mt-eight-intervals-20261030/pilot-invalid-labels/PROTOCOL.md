# E1i — общий поиск по восьми интервалам №155

2026-10-30, предварительный протокол. Источник геометрии — E1g BLOCKS155.json. В модели getrandbits(i), stride=2 условные скаляры равны 2^154+h*2^146+x, h∈{1,25,108,116,137,145,228,252}, 0≤x<2^146. Модель не подтверждена. Реальные скаляры не ищем.

Предлагаемый малопамятный вариант: K tame-прогулок, каждая стартует с правого края одного интервала длины N, и одна общая wild-прогулка от Q. Все используют одну детерминированную функцию скачков. Хранятся K конечных ловушек. Суммарное смещение wild ограничено N−1+максимальное смещение tame; этого достаточно, чтобы достичь ловушки правильного интервала, ЕСЛИ wild слилась с соответствующим tame-путём. Совпадение всегда проверяется точным умножением найденного скаляра и принадлежностью объединению.

Параметры до тестов: μ=max(2,floor(sqrt(N/(2K)))), 16 детерминированных скачков в [1,2μ], один скачок=1; T=4μ шагов каждой tame. До четырёх независимых публичных солей. Эвристическая оценка расходов O(Kμ+N/μ)=O(sqrt(KN)), память O(K+16). Это не следствие одной размерности пространства и не доказанная вероятность успеха. Оценку обосновать явно через пути и проверить эмпирически; отрицательный ограниченный запуск не опровергает наличие ключа.

Сравнения: (1) общий sparse K=8, (2) восемь отдельных capped-kangaroo с одним раундом на интервал и до четырёх раундов, (3) исходный полный интервал одним tame, (4) тот же полный интервал, разделённый на восемь соседних частей — одинаковые восемь ловушек, (5) общая BSGS-таблица на 32 записи для восьми интервалов. Все расходы подготовки и проверки включаются. Ни один вариант не получает номер правильного блока. Максимум около 32 одновременно хранимых публичных точек; дополнительную память Python измерять, не приравнивать количество точек байтам.

Основной набор: N=2^8,2^12,2^16, по одному секрету в каждом из восьми блоков. В первых двух блоках x=0 и N−1, в остальных — псевдослучайный x, воспроизводимый только в проверяющем коде. Пять алгоритмов на каждом примере, 120 запусков. Дополнительные K=1,2,4,8 при N=2^12: по четыре случая, общий алгоритм. Отдельное подтверждение: 16 новых примеров N=2^18, общий sparse и полный интервал с восемью tame. Параметры после просмотра результатов не менять; при изменении нужен новый набор.

Перед измерениями — тесты арифметики и отрицательных/граничных случаев. Solver читает только публичный JSON из stdin, не открывает файлы с секретами. Fixture/проверяющий код — отдельно. Независимая Python-криптография сверяет точки. Считать сложения, шаги, попытки, обращения к таблицам, пиковую память и успешность. Результаты сохранять после каждого запуска; готовые запросы с тем же кодом и хэшами пропускать. GPU не используется: сначала проверить алгоритм и масштабирование.

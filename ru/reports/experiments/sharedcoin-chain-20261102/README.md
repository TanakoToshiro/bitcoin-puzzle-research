# SC-01 — SharedCoin

Итог: [RESULTS.md](<RESULTS.md>). Промежуточные выводы и ошибки: [JOURNAL.md](<JOURNAL.md>). Область: точная историческая цепочка seed→ключ, RNG-контекст, хранение seed, offer/recovery. Реальные seed не перебираются; GPU и соседние проекты не используются.

Из корня `btc test`, PowerShell:

> Исполняемый код/команды опущены в документационной копии.


`prepare.py` проверяет хэши, копии принятых входов и строит историю. Для первоначальной загрузки источников — `fetch.py`; повторная загрузка сохранённых успешных URL не нужна. `run.py` с теми же кодом, данными и версиями пропускает готовый запуск. Изменение входов архивирует предыдущие RUN/TRACES/CHECKS в previous-runs и создаёт новый ID. При прерывании незавершённого короткого JS-этапа он выполняется заново; внутри отдельного 30-секундного стенда checkpoints нет. Частичный результат не выдаётся за завершённый.

`report.py` пересобирает только NUMERIC_REPORT.md, не меняя интерпретации RESULTS/JOURNAL. `verify.py` отдельно проверяет TRACES независимой Python-арифметикой, coincurve и RC4. `seal.py verify` проверяет целостность принятого набора; новые данные следует оформлять новой серией или обновлением с явной записью в журнал, а не скрытой заменой выводов.

Среда закреплена в RUN.json: Python 3.11.9, Node v24.18.0, версия coincurve и ОС. Общая .venv исследовательской папки уже существовала; пакеты не обновлялись. Node исполняет старые файлы с явными адаптерами, не эмулирует весь исторический браузер. Выходы Math.random, WebCrypto, время и пароль синтетические и зафиксированы в sharedcoin.cjs.

Основные артефакты: SOURCES/INPUT_PINS (происхождение), HISTORY/SOURCE_AUDIT (история и строки), TRACES (ключи, адреса, pool, requests), CHECKS (проверки), RUN (ID, код/данные, версии, длительности и ошибки subprocess), COMPLETE (целостность). Все приватные ключи в TRACES — специально созданные синтетические контроли.

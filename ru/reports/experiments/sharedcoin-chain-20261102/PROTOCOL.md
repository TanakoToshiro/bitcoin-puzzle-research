# SC-01 — исторический SharedCoin

02.11.2026. Проверить конкретный генератор SharedCoin до15.01.2015. Отдельная папка, CPU, без изменений SX/RND-01/RND-02, без реального поиска seed и словаря паролей.

1. Сохранить историю sharedcoin.js (GitHub API, конечный список до даты) и снимки. Установить изменения seed-префикса, хеширования, выбора compression, порядка RNG и границы индексов. Даты commit не приравнивать к доказанным датам deployment.
2. Исполнить полные исторические SharedCoin/BitcoinJS файлы выбранных срезов29.12.2013 и07.01.2015 с явными заглушками UI/сети/хранения. Проверить newPlan→seed→последовательные адреса и восстановление из сохранённого seed.
3. Независимо воспроизвести точные байты SHA256, приватный ключ, public/address; включить нулевые/ведущие нули/ff seed, индексы0/1/9/10/99/100/255. Проверить расходы RNG, один seed на план, несколько планов, ограничения и off-by-one. Синтетический известный seed не является найденным seed puzzle.
4. Проследить дополнительный seed в wallet backup, фактический offer payload и запросы восстановления: отправляется seed или только адреса? Не объявлять отсутствие всех утечек на основании одного пути.
5. Оценить пределы восстановления и совместимость со структурой puzzle. Различать штатный интерфейс и гипотетическое внешнее маскирование. Только при выявлении исторически обоснованного малого пространства ставить отдельный поисковый эксперимент; не запускать произвольный перебор144бит.

Основные конечные контроли: точные JS/Python совпадения для двух версий; положительное восстановление и изменённый seed/index/prefix; граница100; payload без seed; сохранение/resume с hashes. Результаты и ошибки вести в RESULTS/JOURNAL, числовые таблицы формировать из артефактов.

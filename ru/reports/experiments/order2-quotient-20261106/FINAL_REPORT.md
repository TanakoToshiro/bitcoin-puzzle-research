# O2-Q01 — точный поиск классов и объединение прогнозов №71

6 ноября 2026, Europe/Moscow. Продолжение O2-ID01. **Этап завершён: алгоритм корректен на проверенных уменьшенных задачах и действительно ускоряет их. Практического способа найти неизвестный класс modulo n пока нет. Реальная рекурсия Puzzle не восстановлена и не исключена; ни один реальный бит №71 не получен.**

## Конкретный алгоритм

Убираем общий сдвиг и ищем четыре координаты `(a,b,d,c0)`, где `d=s2−s1`, `c0=c−(1−a−b)*s1 mod p`. Это эквивалентно `(a,b,d1,d2)` для однородной рекурсии разностей. Каноническая цепочка начинается с `x1=0,x2=d`; исходные состояния равны `(x_i+t) mod p`. Прежние маски на x напрямую не накладываются.

Для заданного класса построен точный **интервальный решатель всех сдвигов t**. Границы `p−x_i` разделяют случаи переноса через p. В каждом интервале наблюдения сводятся к совместимости сравнений `t = r_i−x_i+epsilon_i*p mod 2^k_i`. Результат — конечный список арифметических прогрессий с числом элементов и остатком №71. Огромные множества сдвигов не перечисляются. Стоимость O(m²) сравнений и O(m) интервалов, арифметика произвольной разрядности. Объединение по всем найденным классам даёт полное множество прогнозов только после полного покрытия классов.

Отдельный NumPy-решатель полностью перечисляет классы для малых p, проверяет сдвиги через самое широкое наблюдение и остальные маски. Он служит проверяемым конечным поиском и тестом ускорения; масштабировать его напрямую до n нельзя. [Доказательство и детали](<MATH.md>), [протокол до запуска](<PROTOCOL.md>).

## Точное препятствие и следующий выбор

Факторизация уменьшает домен с `p^4*(p−1)` пятёрок до `p^3*(p−1)` классов. Для порядка secp256k1 это всё ещё **примерно2^1024** неизвестных классов. Даже идеальный интервальный проектор не делает их перечисление реализуемым. Пакетная версия дополнительно перебирает до ceil(p/2^K) сдвигов; на настоящих размерах использовать следует интервальную версию, но число классов остаётся тем же.

Следующая нерешённая математическая задача сформулирована уже точнее: получать ограничения непосредственно на `(a,b,d1,d2)` из обрезанных наблюдений без полного перечисления классов, с сохранением всех случаев модульных переносов. Такой алгоритм ещё не построен. Увеличение brute-force до настоящего модуля, GPU-перенос этого перечисления или повтор нечувствительных решёток SEQ-18 сейчас не обоснованы. Новые семейства/прочие эксперименты не запускались.

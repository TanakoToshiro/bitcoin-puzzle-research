# SEQ-28 — шесть QCG-задач: fused reduction, 600 с и 8 GiB

Дата: 06.11.2026 (Москва). Повтор всех шести сохранённых полноразмерных синтетических задач с настройками SEQ-27 и ресурсами SEQ-26.

## Итог

Статусы: **{'unknown': 6}**. Проверенных положительных восстановлений: **0/4**; совпадений истинного класса сдвига: 0/4. Без окончательного ответа осталось **6/6**. Пики ОС: **464.6–558.2 MiB**.

Все исходные маски, точные границы скрытых частей и нелинейные связи мономов сохранены. Тела математических запросов побайтно совпали с SEQ-24 на 6/6 входах. Ресурсная остановка не является отрицательным ответом о модели. Реальные ключи не проверялись; новых реальных состояний/ключей/битов эта серия не устанавливает.

## Протокол

full00..full05 последовательно, один процесс за раз. Неизменная установленная Windows DLL Z3 5.3.3.0, коммит 430d19e697e2ec9bad79ff210d41b4a7a5fcfa3e. random_seed=0; параметры Python API: timeout=600000 мс, max_memory=8192 МиБ, **ff.preprocess=false, ff.fused_reduction=true**.

Внешние ограничения: 660 с на процесс, 8 GiB по максимуму working/private. Опрос 0.25 с, трасса раз в 5 с. Стартовый резерв свободной физической и commit-памяти 10 GiB; аварийный резерв 2 GiB. Монитор запуска побайтно совпадает с SEQ-26. PLAN.json — артефакт исходного исследования (`PLAN.json`; вне снимка), [PROTOCOL.md](<PROTOCOL.md>), PREFLIGHT.json — артефакт исходного исследования (`PREFLIGHT.json`; вне снимка).

Четыре положительных QCG-входа и два случайных контроля прежние. 83 позиции: №1–70, №75–135 с шагом 5; 82 информативные маски, 3767 наблюдаемых младших битов. Все 135 состояний, 134 квадратных связи z=s², 134 перехода с общими a,b,c, a≠0, точные границы представителей и прежний gauge. Каждый запрос: 17497 переменных, 17659 утверждений. Пропуски не сжимаются; квадраты не становятся независимыми неизвестными.

Каждый поиск запущен с начала. Старого внутреннего checkpoint нет; повторные входы не являются новой независимой выборкой. Истинные коэффициенты/состояния доступны только аудитору и не передаются worker.

Расход памяти за текущий интервал не гарантирует поведение при ещё более длинном запуске.

## Проверка корректности

Encoder SEQ-23 и 35 файлов установленного Z3 не изменены. Переиспользованы 40/40 малых эталонов и 8/8 отдельных проверок скалярной редукции из SEQ-27; новых математических преобразований нет. Перед основной очередью проверена загрузка обеих настроек через тот же replay-код. Любой найденный SAT проверяется прямой целочисленной арифметикой; для положительных входов дополнительно сравнивается класс сдвига.

Z3 может возвращать несколько записей одного статистического ключа. Как в исправленном SEQ-27, сохранены все индексные записи RAW_STATISTICS.json и их суммы. Старый ошибочный способ получения только первой записи не используется. WORKER_CHANGES.patch — артефакт исходного исследования (`WORKER_CHANGES.patch`; вне снимка) показывает изменения оболочки SEQ-26: параметры из плана, сырая/суммарная статистика и CPU-время.

Аудит подтвердил **20526 прежних файлов** с SHA-256/mtime, **1792 прежних зависимостей**, **35 файлов Z3**, 734 отсчётов памяти и 6 точных тел запросов. Старые эксперименты не изменены. AUDIT.json — артефакт исходного исследования (`AUDIT.json`; вне снимка), RESULTS.json — артефакт исходного исследования (`RESULTS.json`; вне снимка), COMPARISON.json — артефакт исходного исследования (`COMPARISON.json`; вне снимка).

## Открытые задачи и повтор

CLOSURE.json — артефакт исходного исследования (`CLOSURE.json`; вне снимка) связывает каждый новый исход с SEQ-26 и SEQ-27. В runs/fullXX сохранены query.smt2, SOLVER_OPTIONS.json, MODEL.json, START/CHECK_STARTED, RAW_STATISTICS.json, ответ либо причина внешней остановки, трасса памяти, фазы, stdout/stderr. Внутреннего checkpoint нет.

Для повторения сохранённого запроса: исследовательский `.venv/Scripts/python.exe -B replay.py <каталог-runs/fullXX>`. Обязательные solver-local настройки читаются из SOLVER_OPTIONS.json; одна query.smt2 без них не воспроизводит исследованный режим. Сам replay.py задаёт внутренние пределы. Внешние 8 GiB/660 с и последовательность обеспечивает run.py; он защищает прежние выходные каталоги от перезаписи. Для новой очереди нужен новый каталог эксперимента.

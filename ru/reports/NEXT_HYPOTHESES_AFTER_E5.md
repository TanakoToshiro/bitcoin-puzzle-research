# Следующие гипотезы после E1–E5

Дата: 2026-10-30. Статус: план, новые вычислительные эксперименты не запускались.

## Основание и ограничения

Приоритет означает полезность конечной проверки, а не оценку вероятности успеха. Данных для честного процента вероятности найти ключ нет. Эти методы общеизвестны; непроверенность в нашей серии не означает, что никто их не проверял.

- [E1](<experiments/mt19937-linear-20261030/runs/20261030-093024-0567d283/CONCLUSION.md>): восемь фиксированных способов упаковки MT с произвольным состоянием не определяют ни один из 70 неизвестных битов №71 или их нетривиальный XOR.
- [E2b](<experiments/python-expanded-20261030/runs/20261030-105921-2f40f0fd/CONCLUSION.md>): все 2^32 integer seed исключены для 120 конкретных Python-схем. Повторять те же состояния через строковые seed Windows Python 2.7 бессмысленно в соответствующей области покрытия.
- [E5](<experiments/public-key-forensics-20261030/runs/20261030-114903-5757a87d/CONCLUSION.md>): проверяемого публичного ключа №71 не найдено; выбранные подписи не содержат повторов r. Для 15 доступных проверок транзакции раскрытия 2019 года nonce совпали с RFC6979. Это не идентификация генератора 2015 года.

Опубликованные решения — полные приватные ключи. Неизвестная величина raw_i в гипотезе маскирования является отдельным исходным числом, а не неопубликованной частью решения.

## Ближайший эксперимент: E6, генерация по байтам и hex-символам

**Гипотеза:** исходное 256-битное число собиралось из 32 отдельных байтов либо 64 hex-символов. E2b проверял другие способы расходования потока; одинаковый seed не делает эти последовательности одинаковыми.

Зафиксировать CPython 2.7.9/3.4.2 и три рецепта:

1. 32 вызова getrandbits(8).
2. 32 вызова randrange(256).
3. 64 вызова choice('0123456789abcdef').

Для каждого — прямой/обратный порядок полученных байтов или символов, каждый/каждый второй полный исходный ключ. Начальный пропуск в первом цикле строго 0; сначала генерируется полный raw_1, затем raw_2 и т. д., включая №1. Маскирование: d_i = 2^(i−1) + raw_i mod 2^(i−1). Произвольные алфавиты, пропуски и reseeding не добавлять по ходу поиска.

Это 24 логические конфигурации, ожидаемо 20 физических после объединения одинакового getrandbits(8); окончательные эквивалентности подтвердить историческими векторами. Список заморозить до прогона.

**Сначала дешёвая структурная проверка.** Для фиксированного расхода — getrandbits(8), Python 2.7 randrange(256) и choice(hex) — построить линейные наблюдения MT и измерить ранг и проекцию на №71. У Python 2.7 выбор из диапазона степени двойки через random() использует старшие биты первого слова, но расходует два слова; точную эквивалентность обязательно проверить на историческом runtime. У Python 3.4 randrange/choice есть отбрасывание, поэтому переносить этот линейный расчёт на них нельзя.

Затем проверять ограниченный seed32, начиная с пилота и измерения скорости. Полный диапазон [0,2^32) — отдельная явно записанная цель вычислительного запуска; частичное покрытие нельзя называть опровержением. В этой записке GPU-запуск не назначается.

Контроли: независимые исторические последовательности, восстановление искусственных seed включая границы, сохранение расхода при пропусках и отказах, противоречивые данные, stop/resume, независимая проверка кандидатов. Подбор только по №1–50; оставшиеся известные решения — подтверждение фиксированной модели. Для итогового линейного анализа допустимо отдельно использовать все известные решения с явным указанием области наблюдений. Предсказание №71 проверять по адресу.

**Зачем:** закрывает конкретный пробел расходования MT и сохраняет исходную цель проверки бита/XOR. **Слабое место:** свидетельств, что создатель использовал такой скрипт, нет. Нулевой результат ранговой проверки не заменяет seed32-поиск, и наоборот.

## Следующие будущие эксперименты — по убыванию приоритета

### E7: MT19937 с init_genrand(seed32)

Стандартная scalar-инициализация MT отличается от Python integer seeding через init_by_array. Полный E2b не перебирал этот другой образ 2^32 состояний. Исторический конкретный пример — прямой _random.Random(None) в CPython 2.7.9, вызывающий init_genrand от времени; это не стандартная обёртка random.Random(None).

Начальная конечная постановка: восемь uint32 на raw, прямой/обратный порядок слов, big/little внутри слова, шаг 1/2, смещение 0: восемь моделей. Сверить с оригинальным MT и историческим низкоуровневым Python; проверить, не имеется ли уже опубликованного воспроизводимого полного покрытия этих точных моделей. После этого пилот и, если оправдано, seed32-поиск. Не утверждать, что этим проверены все C++/PHP-программы, их упаковка или API.

### E8: исторический временной fallback Python

Конкретный механизм — int(time.time()*256) при NotImplementedError от os.urandom в Python 2.7.9/3.4.2. Для 2015 года это число больше 32 бит и не входит в E2b. Обычная инициализация предпочитает системную энтропию; признаков срабатывания fallback у создателя нет.

Перед вычислением указать UTC-окно, точную формулу и набор API. Дата финансирования 2015-01-15 даёт ориентир, но не доказывает недавнее создание ключей. Например, 30 дней дают 663 552 000 временных отсчётов по 1/256 с на одну схему; это иллюстрация стоимости, не выбранное окно. Не добавлять автоматически миллисекунды, микросекунды, PID и произвольные комбинации. Отрицательный вывод только для зафиксированного окна и рецепта.

### E9: конкретный исторический генератор кошелька

Сначала искать исходный код, архив скрипта или воспроизводимую историческую ошибку, существовавшую до финансирования puzzle. Для Electrum/BIP32 и других кандидатов отделять обычный путь с достаточной энтропией от конкретного слабого seed. Восстановление штатной реализации без ограничения seed само по себе не уменьшает поиск №71. Название кошелька не выводится из RFC6979 или общего вида распределения решений.

Практический результат архивного этапа — точная версия, путь генерации энтропии, правила индексации/маскирования и конечное множество кандидатов, либо зафиксированное отсутствие основания для вычислительного поиска.

### Более низкий приоритет

- getrandbits(i) с повтором до установленного старшего бита: отдельная схема, отличающаяся от принудительного бита и от прежнего randrange; заранее задать поведение №1.
- Повторное seeding для каждого ключа: проверять лишь обоснованный рецепт. Произвольные seed+i и seed XOR i создают бесконечный список без повышения правдоподобия.
- Новые подписи/архивы публикаций №71: продолжать при появлении конкретного источника. Отсутствие повторов r не исключает все nonce-уязвимости, но пока нет основания для большой lattice-атаки; подписи разных решателей нельзя смешивать как один генератор.
- Новые HASH160-модели, произвольные XOR/суммы решений и большие seed-словари: только при содержательной новой гипотезе и независимой проверке. Обнаруженный постфактум узор не является предсказанием.

## Последующее выполнение: E6H, 2026-10-30

Описанный ограниченный этап выполнен: [выводы и артефакты](<experiments/high-points-xor-20261030/runs/20261030-122003-bb9bb8/CONCLUSION.md>). Наборы реальных точек построены, общий C на уменьшенных моделях восстанавливается; проверенный совместный MITM не уменьшил сложность относительно обычного DLP+отбора. Без нового алгоритма расширять тот же MITM не предлагается. Прежний E6 по байтам/hex остаётся отдельным невыполненным экспериментом.

Цель по уточнению пользователя теперь — любая нерешённая puzzle, включая задачи с известными публичными ключами. Требование пути именно к №71 снимается; для практического результата по-прежнему требуется показать извлечение числового ключа/его полезного ограничения или подтверждённое уменьшение работы для некоторой нерешённой задачи.
